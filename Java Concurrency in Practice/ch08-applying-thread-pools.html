Applying Thread Pools

A thread pool is a set of knobs: core and maximum size, the work queue, what to do when full, how threads are made. Most settings are fine alone; some combinations quietly break.

Tasks aren't always independent of their policy

Chapter 6 promised that executors separate submission from execution. That's a slight overstatement. Some tasks only work under particular execution policies:

The sharpest case is thread starvation deadlock. If a task submits another task to the same bounded pool and waits for its result, and every thread is doing the same, nobody can run the inner tasks. Step through it with a single-thread executor.

Future<String> header = exec.submit(() -> load("header.html"));
Future<String> footer = exec.submit(() -> load("footer.html"));
String body = renderBody();

Whenever you submit tasks that depend on other tasks to a bounded pool, you risk thread starvation deadlock. Document the pool size or configuration constraints.

Long-running tasks cause a milder version: if enough of them clog the pool, short tasks wait for ages. Prefer timed blocking calls (get(timeout), poll(timeout)) so stuck tasks can give up.

2

Sizing a thread pool

Pool sizes shouldn't be hard-coded; compute them from Runtime.availableProcessors() or configure them. You just need to avoid the extremes: too big and threads fight over CPU and memory; too small and processors sit idle with work waiting. For compute-bound tasks, about Ncpu + 1 threads (the extra one covers page faults and other stalls). For tasks that wait on I/O, more, in proportion to how long they wait:

Nthreads = Ncpu × Ucpu × (1 + W/C)

Other resources set upper bounds too: if each task needs a database connection and the pool has 10, more than 10 threads just wait on the connection pool.

Configuring ThreadPoolExecutor

The Executors factories are presets of ThreadPoolExecutor. Configure it yourself with a core size (threads it tries to keep), maximum size, keep-alive time, a work queue, and a saturation policy. The rule that surprises people: the pool only creates threads beyond the core size when the queue is full. With an unbounded queue, the maximum size is never used.

Thread factories and extension hooks

Whenever a pool needs a thread, it asks its ThreadFactory. A custom factory can give threads meaningful names (thread dumps become readable), set an UncaughtExceptionHandler, count live threads or set a priority. ThreadPoolExecutor is also designed for extension, with three hooks.

class TimingPool extends ThreadPoolExecutor {
  private final ThreadLocal<Long> start = new ThreadLocal<>();
  protected void beforeExecute(Thread t, Runnable r) {
    start.set(System.nanoTime());
  }
  protected void afterExecute(Runnable r, Throwable t) {
    record(System.nanoTime() - start.get());
  }
  protected void terminated() { logAverage(); }
}
beforeExecuteRuns in the worker thread before each task. If it throws, the task doesn't run.
afterExecuteRuns after each task, whether it returned or threw (not after an Error).
terminatedRuns once when the pool has fully shut down. Release resources, send notifications, finish statistics.

Want to stop someone later reconfiguring your carefully tuned executor through a cast? Wrap it with Executors.unconfigurableExecutorService.

5

Parallelizing recursive algorithms

A sequential loop whose iterations are independent can become parallel by submitting each iteration as a task. Recursive tree walks work the same way: do the per-node work in a task, recurse sequentially to submit them. The book applies this to a sliding-block puzzle solver: a breadth-first search where each position spawns tasks for its moves, a ConcurrentHashMap records positions already seen (via putIfAbsent), and a result-bearing latch holds the first solution found.

Knowing when to stopThe first solver to find a solution sets the latch; the main thread waits on it, then shuts the pool down. If there is no solution the latch would wait forever, so the concurrent solver counts active tasks and sets the latch to null when the count drops to zero. Adding a time limit or a position limit is another option.
