Memory

LLMs are stateless. Every bit of memory an agent seems to have is something we chose to put back into its context, so memory is really the craft of deciding what goes in.

1

Memory is what turns an LLM into something that learns from its steps

A locally loaded LLM cannot remember your name from one call to the next. Hosted chat apps seem to remember only because memory is built around the model. For agents, memory covers more than the chat: the original query, each intermediate step, every tool call and its output. Without that record the agent could not use tools across steps or follow a plan, since it would forget what it already did.

2

Four kinds of memory

The Cognitive Architectures for Language Agents (CoALA) framework borrows from human memory. Working memory is short-term: the chat history fed back every call. Long-term memory has three forms: episodic (what the agent did and how it went), semantic (facts about the world, such as a knowledge base or your codebase) and procedural (how to do things, held in the system prompt or in the weights). Knowledge stored in the weights is also called parametric memory. Sort these examples.

3

Short-term memory and the context window

The easiest memory is to resend the whole conversation as a list of role-tagged messages. But the context window, the maximum tokens a model can handle, must hold both the input and the output. As history grows, the reply gets clipped or cannot be produced at all. The book implements three fixes: trimming to the last few turns, a rolling summary rewritten each turn, and a hybrid that summarises old turns and keeps recent ones verbatim.

Long-term memory: retrieval-augmented generation

  
For knowledge that will never fit in a window, store it outside the model. RAG splits documents into chunks, turns each into an embedding (a vector that places similar meanings close together) and stores them in a vector database. At question time, the query is embedded, the nearest chunks are retrieved, pasted into the prompt (augmented), and the LLM generates an answer grounded in them. Pick a question and see which notes come back.

5
MemoryBank: remember what gets used

  
MemoryBank keeps past conversations, LLM-written summaries of events and a running user portrait, all embedded for retrieval. Its twist is forgetting, modelled on the Ebbinghaus forgetting curve: memories fade over time unless recalled, and every recall makes them last longer, like spaced repetition before an exam. Add recall events and watch the memory survive.

  

    

    
    

    

  






  
6
Agentic RAG: let the agent decide what to look up

  
Vanilla RAG retrieves once, before the model speaks, and the model has no say in it. In agentic RAG each knowledge source becomes a tool. The agent chooses where to search, how many times, and can chain searches (find a name in one source, then look it up in another). Several retrieval agents can also be coordinated by a stronger one. The authors suggest starting with a single agent.

7
Context engineering: the right tokens, not the most

  
Context windows grew to millions of tokens, and needle-in-a-haystack tests looked near perfect. But finding one planted fact is not reasoning over a long context: harder benchmarks such as RULER exposed drops, and adding marginal material can make answers worse, sometimes called context rot. Long context also costs latency and memory. Context engineering means the right information, in the right place, in the right format. Build a context for the request "Fix the failing login test".

  

    

    

    

  

  
In multi-agent systemsEvery agent has its own context to manage, and their messages to each other become context too. Handing narrow jobs to small subagents keeps each context small, easier to test and debug, and leaves the orchestrator room to think.






  
8
Selecting and compressing: reranking and MMR

  
Retrieval returns related chunks, not necessarily the best set. A reranker re-reads query and candidates together and reorders them. Then compression: summarise, deduplicate, or use Maximal Marginal Relevance. MMR picks the most relevant document first, then repeatedly picks the one with the best balance of λ × relevance minus (1 − λ) × its highest similarity to anything already picked. Lower λ favours diversity. Choose 3 of 5.

  

    
    

    

  






  
9
Ordering: lost in the middle

  
Where information sits matters. Models attend best to the start and end of a long prompt and miss what is buried in the middle, much like the human serial-position effect (primacy and recency). Keep contexts short and put what matters at the edges. Move the key fact.

  

    
    

  






  
10
Context is the specification

  
The authors end on a mindset shift. The query, a PLAN.md, a REQUIREMENTS.md and the files you point to are not throwaway inputs: they are the specification of what the agent was asked to do. We usually keep an LLM's output and discard its input, which is odd. Store the context, especially for autonomous work like an agent-written pull request, so reviewers can see the why, results can be reproduced and failures can be debugged. What belongs in context differs sharply by domain: patient records in healthcare, papers in research.
