Introduction: What Is an AI Agent?

An agent perceives its environment and acts on it. Swap in an LLM as the brain, add memory, tools, planning and reflection, and you get the system this whole book is built around.

1

An agent perceives and acts

Definitions of "AI agent" keep shifting, so the book anchors itself to a classic one from Russell and Norvig's AI textbook: an agent is anything that perceives its environment through sensors and acts on it through actuators. That gives four parts: the environment (the world it works in), sensors (how it observes), actuators (how it changes things) and the agent program, the "brain" that turns observations into actions.

tap a box

This book is about agents whose brain is a large language model. Other kinds of agents exist (a thermostat, a chess engine), but from here on "agent" means an LLM-backed one.

3

The brain: one token at a time

At heart an LLM does one thing: given text, predict the next token. Tokens are pieces of words, which lets the model handle words it never saw whole. To write a full answer it appends its own prediction to the input and predicts again. This loop is called autoregression. Step through it.

4

Reasoning: spend compute on thinking

For years progress came from train-time scaling: more data, more parameters, more compute during pre-training. Gains became expensive. Models such as OpenAI o1 and DeepSeek-R1 opened a second axis: let the model think out loud first, writing reasoning tokens before the answer. Apps often hide or summarize these thoughts and show only the conclusion.

Why agents need itPlanning, choosing a tool, noticing a mistake and revising a plan are all multi-step judgements. Reasoning models are better at them. If you only need a fast, cheap reply, a regular model is still the better fit.
5

Memory: LLMs forget by default

An LLM is stateless: nothing persists between calls. A follow-up question arrives with no trace of the first one. The simplest fix is to send the earlier conversation along with every new prompt. Real memory systems get more elaborate, and too much context causes information overload, so deciding what to include, called context engineering, becomes a skill of its own.

Tools: the LLM writes the intent, software acts

  
Text in, text out: an LLM cannot press buttons. What it can do is write a call in an agreed format, such as multiply(5.1, 7.3). Your code (the harness) spots that text, runs the real function and hands the result back. Chapters 2 to 5 together produce what Anthropic calls the augmented LLM: a model with memory and tools.

  

    

  






  
7
Planning and reflection close the loop

  
The last ingredient is the ability to plan (break a big task into small steps, called task decomposition) and to reflect (look back at results and fix the plan). Watch a research agent work through its plan and change it halfway when its sources turn out to be thin.

  

    
    
  
    
  
    Reasoning LLM + memory + tools + planning and reflection: that combination is what the book calls an AI agent. Chapter 6 puts it together.
    

    


    
  
    8
    Autonomy is a spectrum
    
  
    An agent can pick tools, rewrite its plan, add steps or decide it is done. How much of that freedom you grant is a design choice. Some say a system is only "agentic" when the LLM controls everything; the authors take a wider view: goal-directed decisions are enough, so orchestrated workflows with partial autonomy count too.

    Harnesses and the TinyAgent
    
  
    The code wrapped around the model, which runs the loop, calls tools and tracks state, is the agent harness. They come in several flavours, and the list changes monthly. Underneath, all share the same scaffolding: LLM, memory, tools, planning. Personal-assistant harnesses (always on, reachable over chat apps, with access to email and files) took off fast in 2026, and give agents the most autonomy of all.
