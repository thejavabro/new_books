When one agent is not enough

So far the agent has worked alone, talking only to humans. A multi-agent system (MAS) puts several agents in a shared environment, where they can collaborate or compete. Agents may be homogeneous (identical, for parallel work), heterogeneous (different roles, models, memory and tools, like a search agent and a summariser) or start identical and drift apart into emergent specialisation. Weigh the trade-off.

Gains
Costs

In production: Anthropic built a research system from multiple Claude agents; Uber uses a supervisor with data-retrieval agents (one writes SQL) for financial questions; Delivery Hero uses agents to extract entities and write product titles for its catalogue.

The simplest MAS: subagents as tools

A neat trick builds a centralised (and potentially hierarchical) system with nothing new: wrap a specialised agent so it looks like a tool. The supervisor sees a function such as ask_math_agent(task); calling it runs a whole ReAct loop inside the subagent, which returns only its answer. The subagent's messy context never reaches the supervisor.

Role-play frameworks: CAMEL and MetaGPT

  
CAMEL builds collaboration from role-play. From a user's idea and two roles, a task specifier rewrites the idea as a concrete task; then an AI user (who instructs) and an AI assistant (who executes) converse turn by turn until done. MetaGPT goes further and copies a software company: role profiles (product manager, architect, engineer, QA), communication through artefacts such as documents and diagrams rather than chat, and engineers that run and debug their own code.

  

    

    

  

  
Frameworks and harnesses all handle memory, planning and tools in their own way. The ingredients are the same as in Part I; only the recipe changes.






  
5
Agent2Agent: a protocol between agents

  
MCP connects an agent to its tools (vertical). Agent2Agent (A2A) connects agents to other agents (horizontal), again turning N × M custom links into N + M. Three actors: the user, the client agent that acts for them, and remote agents (single agents or whole systems) that do the work. Remote agents publish an agent card at /.well-known/agent-card.json.

  

  
Alternatives exist, such as Internet of Agents, with an instant-messaging style design, and research uses RL to train agents for multi-agent settings. Standards here are young.






  
6
Agent societies: Smallville

  
Give agents identities and a shared world without a fixed task, and social behaviour starts to emerge. LLMs pick up traits of human psychology from their training data; researchers probe their emotional intelligence and even theory of mind. The landmark Generative Agents paper populated a town, Smallville, with 25 agents, each seeded with a one-paragraph profile. Their memory stream logs observations; to act, an agent retrieves memories scored by recency, importance and relevance. Change the weights for the question "What should Isabella do this evening?"

  

    

    

    
Top 3 (green) enter the prompt. Agents also periodically write reflections, higher-level insights drawn from many memories, which are stored back in the stream, and they plan their days. From such pieces emerged lifelike behaviour: news spreading through town, new relationships, and agents coordinating to turn up at a Valentine's Day party one of them organised.

  






  
7
Deep research by committee

  
Research is a natural fit for MAS. Google's AI co-scientist (built on Gemini 2.0) turns a research goal into hypotheses and a proposal. A supervisor schedules specialists: Generation drafts hypotheses from literature, Reflection reviews them, Ranking runs Elo tournaments of simulated debates, Proximity groups near-duplicates, Evolution refines the leaders, Meta-review feeds lessons back. The researcher can steer at any point. Run a tournament.

  

    

    

  

  
Agent Laboratory is more structured: three fixed phases, driven by the human researcher, ending in a report plus the experiment code.
