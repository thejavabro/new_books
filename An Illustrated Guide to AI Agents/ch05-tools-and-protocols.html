Tool Usage, Learning, and Protocols

An LLM can only write text. Tools turn that text into actions: a call the harness parses, runs and feeds back. Protocols make the same tools work across every model.

1

Tools let a text function reach the world

By itself an LLM is a function from text to text. Tools, meaning functions and APIs, let it step into its environment. They come in two flavours: tools that retrieve information (web search, a database query, the weather) and tools that take an action (send an email, book a slot, write a file). How much say the model has over them is a design choice.

2

Five stages of a tool call

The book walks every tool through the same lifecycle: creation (write the function), definition (describe it to the model), selection (the model decides whether and which), calling (the model writes the call, the harness parses and runs it) and output processing (the result goes back into the conversation, often as a tool role message, for the model to use).

3

Describing a tool well

Newer models are trained to use tools in general, recognising definitions in the prompt, rather than memorising specific tools. You can describe a tool in plain language in the system prompt, or as a structured JSON Schema (name, description, typed parameters, required fields), which APIs accept as a separate tools parameter. Either way, it is ultimately rendered into the prompt. Tick the practices this definition follows.


    

  






  
4
Selection: harder with every tool you add

  
Picking the right tool, and using it correctly, is where reasoning models earn their cost: they can think through which tool fits before acting. Still, every tool definition takes context and adds a chance to choose wrong. A common fix for big catalogues is RAG over tool definitions: embed the descriptions and retrieve only the few that match the query.

  

    
    

    

    
Shape of the trade-off, not measured numbers. The authors' rule of thumb: start with fewer than 10 tools.

  






  
5
Calling: parse, execute, observe, repeat

  
The model's tool call is only a string. The harness must parse it (usually JSON), execute the named function, add the observation back to memory, and decide whether to stop. The TinyAgent's step follows the pattern THOUGHT → ACTION → OBSERVATION, ending with an ANSWER. Try the parser on a few model outputs, including broken ones.

  

    

    

    

  

  






  
6
How models learn to call tools

  
Three routes. In-context learning: show a few example calls in the prompt (or as separate example messages) and the model copies the format. Supervised fine-tuning: train on tool-use traces, though good data is hard, since many different calls can be equally correct. Reinforcement learning: reward correct behaviour and let the model find its own strategy, which tends to generalise better than imitation. A landmark self-supervised approach was Toolformer: it learned to insert API calls inline between special bracket tokens. Step through.

  

  






  
7
Native tool calling hides a chat template

  
Models trained for tools, like Gemma 4, have their own template. Inference engines such as Ollama or llama.cpp convert the standard OpenAI-style schema into it, which can feel like magic. The TinyAgent writes a small tool_to_schema helper that reads a Python function's signature and docstring and produces that schema, so you never write JSON by hand.

  

    

    

  






  
8
MCP: one protocol instead of N × M integrations

  
Every new model or tool used to mean new glue code: N models times M tools. The Model Context Protocol (MCP) puts a standard in the middle, so each side implements it once: N + M. A host (an IDE, a chat app) runs one client per server; servers expose tools (actions), resources (data to load as context) and prompts (reusable templates). Agent2Agent (A2A) does the same job for agents talking to each other.

  

    

    

    

    

  

  






  
9
Skills: know-how loaded only when needed

  
Tools and MCP give an agent actions, but not your team's way of working: use uv not pip, structure meeting notes like this. Skills, introduced by Anthropic, package that know-how as a folder with a required SKILL.md. They use progressive disclosure, a context-engineering trick in three layers. Click through as an agent would.
