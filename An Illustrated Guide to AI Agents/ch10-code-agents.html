Code Agents and Code LLMs

Code is the domain where agents shine: clear goals, tools that run, tests that verify. This chapter looks at how coding agents work and how the models behind them are trained.

1

Why code is the agent's home turf

Code is a prime investment area for two reasons. A huge range of knowledge work (engineering, research, data analysis, visualisation) can be expressed as code. And code can be verified automatically: run it, test it, get a clear signal. That verifiability helps both while training models and while agents work. Different people want very different things from a coding agent. Tap each.

2

A code agent for people who never see code

Ask for a chart of sales by region. The agent must retrieve the data (from a file you hand it in a Python sandbox, from a filesystem it searches with command-line tools, or from a database via a SQL tool), write plotting code, and troubleshoot. Errors are just observations in the ReAct loop, so the model often recovers on its own, but planning for known failure cases makes a far better product.

3

The toolbox: from sandbox to whole computer

Code tools tie the model's decisions to a real environment. More power means more risk, so match the tool to the job. Slide along the ladder.

4

Design the context for the cache

Even the first call of a software-engineering agent can run to tens of thousands of tokens (system prompt, tools, repository map, task) and the agent may take dozens of steps. Prompt caching (Chapter 2's KV cache, offered by providers) lets repeated prefixes be reused cheaply, with two rules: the cached part must stay byte-for-byte identical, and new content must be appended at the end. Then every step's whole history is a cache hit. Step through, then try breaking the rule.

Practical layout: a static section (system prompt, tool definitions) that never changes, a stable section (repo map, plan) that changes now and then, and a dynamic tail of recent steps. When context fills, compaction summarises the dynamic part and leaves the cached sections intact.

5

From functions to repositories

Early code models solved isolated, LeetCode-style functions. Repository work needs software engineering skills: managing environments, testing, reproducing bugs, reading the right parts of a codebase to understand intent. SWE-bench made this measurable: a real GitHub issue plus a repo snapshot, judged by hidden tests. Early agents leaned on heavy scaffolding (SWE-agent built a special agent-computer interface); stronger models need less. Planning became central, and coding UIs show plans and to-do lists the user can review. Good plans include exploration steps, because you often do not know the fix until you have looked.

Not everything needs an agentA fixed workflow is often simpler and enough. Agentless resolves issues in three fixed phases and competes with agentic systems.

How code LLMs are built

  
An agent is capped by its model. A coding model follows the familiar stages (pre-training, SFT, RL) but differs in its data and its reliance on RL. Qwen3-Coder, for example, was pre-trained on 7.5 trillion tokens, about 70% of it code. Post-training needs data that looks like real agent work.

  

  
One frontier pipeline: GLM-5
Large-scale RLVR with tests as the verifier is now central, where RLHF used to be the main polish. Coding alone is not enough: reasoning, multi-step tool calling, long context, planning and good engineering habits all matter.

  
The synthetic data loopAround 2024, LLMs became a major source of training data for the next generation. Much of Llama 3.1's post-training data came from Llama 3; Qwen2.5-Math and Qwen2.5-Coder helped make data for Qwen3 and Qwen3-Coder; DeepSeek-R1-Zero generated reasoning traces for R1.






  
8
Afterword: a gift, not a transaction

  
The book closes on a single page. Borrowing a distinction from the botanist Robin Wall Kimmerer, the authors say buying the book was a transaction, even and finished. The ideas inside were a gift, passed on by people who worked something out and wrote it down instead of keeping it. A gift asks only that it keep moving. Their hope is that readers build well, and that what they make reaches people they will never meet and is good to them.
