The Intersection of Security and Reliability

A password manager falls over, and getting it back needs a power drill. Reliability and security pull on the same system from different sides; this chapter maps where they agree and where they fight.

1

An outage that needed a power drill

The chapter opens with a real Google incident from 2012. A popular announcement overloaded an internal password manager. Every security control on the recovery path then got in the way. Step through the chain.

The lessonA reliability problem (no load shedding, both replicas failing the same way) started the outage. Security measures (smart cards in safes, a combination stored in the very system that was down) made recovery slow. You have to design for both at once, or each can undermine the other.
2

Accidents vs. adversaries

Reliability engineering assumes things go wrong some of the time, by accident. Security engineering assumes someone is trying to make things go wrong at any time. That one difference changes how a system should fail. Cut the power to this door and see.

3

Confidentiality, integrity, availability

Both disciplines care about the same three properties. The difference is whether a malicious adversary is involved. Pick a corner and switch between an accidental failure and a deliberate attack.

4

A security tool saves a reliability incident

In 2015, cryptographic integrity checks on a few stored blocks started failing. Machines that handled the data had memory errors, so SREs guessed each block had a single flipped bit. They recomputed the check for every possible one-bit change until one matched. Try it on a 16-bit block with a toy checksum.

stored block

The checksum was recorded when the data was written. Corrupt the block, then search.

Recap on one page

The key differenceReliability defends against accidents; security against people actively trying to cause harm.
Same propertiesBoth protect confidentiality, integrity and availability.
Real tensionFail open vs. fail secure, redundancy vs. attack surface, many responders vs. need-to-know.
EmergentBoth come from the whole design and must be built in early, then maintained.
Shared toolsSimplicity, defense in depth, failure domains, least privilege, multi-party authorization.
Plan for failurePrevention will fail; logging, crisis response and recovery need designing too.
