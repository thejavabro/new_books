Let the framework carry the invariants

Almost every RPC backend needs logging, authentication, authorization and throttling, and every one written by hand is a new chance to get one wrong. A framework runs these as interceptors around the business logic, so app developers write only the logic and can't forget a step. Send a request through.

Make injection impossible to write: TrustedSqlString

Gluing user input into SQL lets attackers rewrite the query. Google's answer is a type: the query builder accepts only a TrustedSqlString, which can be built only from compile-time constants; user values go in as parameters. The vulnerable code simply won't compile. Type into the password-reset form.

Same trick for HTML: SafeHtml

  
Cross-site scripting is the same bug in a browser. With safe types, markup reaching the page must be a SafeHtml value produced by a contextually escaping template or a vetted builder. Raw strings are escaped automatically. Try some input.

Catch it at compile time

  
Linters you opt into and comments in code review arrive late, when the code already "works" and rearchitecting hurts. Compiler checks (Error Prone for Java, Tsetse for TypeScript) and IDE underlines arrive while the developer is still on that line. Slide to see when a banned pattern is caught.

Simple code has fewer hiding places

  
Deeply nested error handling hides bugs in the paths tests rarely visit. Compare two versions of the same function and spot the bug.

  

    

    

    

  

  






  
6
Types that know their units

  
Untyped primitives invite mistakes ranging from harmless (a 30-second timer that should be 30 minutes) to catastrophic (mixing up two IDs). Strong types make the wrong call fail to compile and allow only sensible operations: subtracting timestamps gives a duration; adding two timestamps isn't allowed.

  

    

    

  

  

    
Choose memory-safe languages
Microsoft, 2019

    

    
Around 70% of the vulnerabilities Microsoft fixed over about 12 years were memory-safety bugs. Where you must use C++, run sanitizers (AddressSanitizer, MemorySanitizer, ThreadSanitizer, UBSan) or Valgrind in continuous builds; in Go, use the race detector.

Recap on one page

  

    
FrameworksAuth, logging, throttling as interceptors: written once, reviewed once.

    
Safe typesTrustedSqlString, SafeHtml: whole bug classes become compile errors.

    
Fast feedbackCompiler and IDE checks beat linters and review comments.

    
Roll out graduallyNew code first, then incremental conversion; one obvious, reviewed exemption function.

    
Keep it simpleFlat control flow, no YAGNI code, repay TODO debt, refactor in separate commits.

    
Right toolsMemory-safe languages, strong typing, sanitizers.
