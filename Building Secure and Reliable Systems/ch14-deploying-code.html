1

From commit to production: the software supply chain

The supply chain is everything between a developer's change and a running binary: version control, review, build, test, deploy. The adversaries are benign insiders who make mistakes, malicious insiders, and outsiders who've taken over an insider's account. Pick a threat to see where in the chain it enters and which control stops it.

2

Five habits that close most gaps

Don't check in secretsPasswords, keys and tokens in a repository are readable by everyone with source access and live forever in history. Keep them in a secret manager or KMS and reference them from config. Encrypted-in-repo is acceptable only if the decryption key is tightly controlled.
3

Verify the artifact, not just the person

Checking who clicked deploy isn't enough: a trusted person's account can be stolen, and a trusted person can deploy the wrong thing. Instead, every build emits signed binary provenance (which sources, which build command, which builder) and a policy engine at the deployment choke point checks it. Edit the provenance of this artifact and try to deploy it to production.

Artifact hashsha256:3b7e…a91c Source repo Branch Every change reviewed? Built by Version 
# deployment policy for the payments service (illustrative)
policy payments-prod {
  source_repo   = "git.corp/payments"
  branch        = "main"
  require       = ["code_reviewed", "built_by:trusted-builder"]
  min_version   = "2025.06"         # no known-vulnerable rollbacks
}
4

Can you trust the provenance itself?

Provenance is worthless if the build that wrote it can be subverted. A build is verifiable if its provenance is trustworthy. Tap the terms, then see what happens when user-defined build steps share a machine with the signing key.

6

Lessons from rolling it out

Google's first version stored provenance asynchronously in a database keyed by artifact hash. Then it turned out that millions of different builds produce the empty file, all with the same hash. Verifying one empty file meant checking hundreds of thousands of records, blowing the 100 ms latency budget by orders of magnitude, and the only possible error message was "none of 497,129 records met the policy". Fix: ship provenance with the artifact so it is unambiguous.
