RAG: Retrieval-Augmented Generation

A model answers better when it is handed the right facts. RAG builds a fresh context for every query by retrieving from your own data, and its quality rests on the retriever.

1

Why retrieval-augmented generation

To do a task, a model needs instructions and information. RAG retrieves the information relevant to each query from external memory (documents, databases, past chats, the web) and puts it in the prompt. Ask "Can the X-300 printer do 100 pages per minute?" and the model answers far better with the spec sheet in front of it. The book compares context construction to feature engineering in classic ML: both give the model what it needs to decide.

Won't long context make RAG obsolete?Probably not soon. Data grows faster than context windows, and a model that can read a long context doesn't necessarily use it well. Every extra token adds cost and latency. RAG sends only what matters.
Sometimes you don't need itAnthropic's guidance for Claude: if your knowledge base is under about 200,000 tokens (roughly 500 pages), you can put it all in the prompt, ideally with prompt caching.
2

Retriever plus generator

A RAG system has a retriever and a generator. The retriever does two jobs: indexing (processing data so it can be found later) and querying (fetching the most relevant pieces). Documents are usually split into chunks; the book calls both "documents". In today's systems the two parts are often built separately, though training them together can help.

3

Term-based retrieval: keywords, TF-IDF and BM25

The simplest retriever matches keywords. Many documents contain a keyword, so rank them: a term matters more if it appears often in the document (term frequency) and rarely across the collection (inverse document frequency). TF-IDF combines the two; BM25 refines it by normalising for document length and is still a formidable baseline. Elasticsearch stores an inverted index: for each term, the documents containing it. Search the little collection below.

Details matter: tokenising "hot dog" into two words loses its meaning; lower-casing, removing punctuation and stop words ("the", "is") are common steps. Term-based retrieval is fast and works well out of the box, but it matches words, not meaning: "transformer" pulls in electrical transformers too.

4

Embedding-based (semantic) retrieval

Semantic retrieval compares meaning. Indexing converts each chunk into an embedding and stores it in a vector database. At query time, embed the query with the same model and fetch the k nearest chunks. Exact nearest-neighbour search compares the query with every vector, which is precise but slow; large systems use approximate nearest neighbour (ANN) algorithms. Query speedMuch fasterEmbedding the query plus vector search can be slow

Judge a retriever by what it returns. Context precision: of what was retrieved, how much is relevant? Context recall: of everything relevant, how much was retrieved? Production systems combine retrievers. In sequence: a cheap term-based pass fetches candidates, a precise model (embeddings or a reranker) orders them.         6

        Chunking strategy

        How you split documents decides what can be found. Split by characters, words, sentences or paragraphs, recursively (sections, then paragraphs, then sentences), with format-aware splitters for code or Q&A, or by tokens of the generator's tokenizer. Overlap keeps context that would otherwise be cut mid-thought.

        Smaller chunksMore, more diverse chunks fit in the context. But a fact spread over a section may be split and lost, and halving the size doubles the embeddings to compute and store.
        Bigger chunksMore context per chunk, fewer to manage. But fewer fit in the prompt, and chunks must stay under the generator's context and the embedding model's limit. No universal best: experiment.
        7

        Reranking, query rewriting and contextual retrieval

        Reranking

        Reorder candidates with a stronger model, or by recency for news and email. Unlike web search, exact position matters less; what matters is which documents make it into the context, though first and last positions may get more attention.

        Query rewriting

        Turn the user's last message into a self-contained query. Often done by a model; may need identity resolution or other knowledge.

        Contextual retrieval

        Augment each chunk before indexing: titles, tags, extracted entities like error codes, questions it answers, or a short model-written blurb placing the chunk in its document (Anthropic's approach).

How long does indexing take, and can you add or delete data in bulk? What are query latency and pricing (per document, vector or query)?
        

        


        
  
        8
        RAG beyond text
        
  
        Multimodal RAG retrieves images, audio or video too: by metadata (captions, tags) or by content, using a joint embedding model like CLIP so a text query can find a picture. Tabular data needs a different route: the system writes and runs a SQL query, then answers from the result. With many tables, first predict which schemas to put in the context.
