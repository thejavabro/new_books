1

The whole book as one system

Every chapter uses one running example, MREP (the Macro Research and Education Platform). ACME Research builds it to replace static reports with multi-agent market intelligence. This appendix puts the pieces back together, adding complexity in order. The agents come first. Then the pipeline that coordinates them, the context that feeds them, the runtime that executes them, the security that contains them, the state that makes them auditable, the delivery discipline that ships them, and finally the organization that runs them. The author built the reference version on Google Cloud against a real research workload. The book's figures are its own. The diagrams here are simplified redraws to explore.

The appendix's one-line argumentA production agentic system is a governance, integration and operating-model problem. The agents are the easy part.

4

No exfiltration, yet continuous ingestion

The research agents live inside a service perimeter and never call the internet. That looks like a contradiction, because the platform needs fresh filings and market data all day. The answer is in the project layout. A dedicated egress project outside the perimeter is the only thing allowed to reach external APIs. It pushes data in over a one-way message bridge. A separate audit perimeter receives data and never releases it. The project boundaries also become cost-attribution boundaries. Try sending traffic.

Pick a flow.

5

Write-back gate and the hardest gate

Once an agent can change something outside the system, the question stops being "is the answer good?" and becomes "is this action allowed?" Every outbound action passes the tool gateway: authorization, schema validation, rate limit, and human approval for anything material. The Compliance Agent is the hardest gate. It returns pass, fail or escalate, and if the check itself errors it fails closed. A wrong thesis published costs more than a delayed thesis held. Because this one gate stays hard, the other agents can afford to be aggressive. Run some theses through it.

6

What to build, what to buy

Plot MREP's parts from custom-built to commodity and the roadmap stops being a matter of taste. The runtime, the models and the tool gateway are drifting toward commodity, so buy them. Context curation, the systems of record, the golden evaluation set, the compliance rules and the personalization logic stay custom on purpose. No vendor will ever ship them, and they are the moat. Sort them yourself.

Build or buy?

The book suggests redrawing this map every few quarters, because components drift toward commodity faster than procurement cycles expect.
