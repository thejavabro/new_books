AgentOps and EvalOps

Traditional ops asks whether a system is up. Agent ops must also ask whether it is right. Evaluation becomes the authority that decides what ships.

1

Up is not the same as right

DevOps disciplines still apply, but agents break their assumptions. The same input gives different outputs. Behaviour changes with a model update or a prompt edit, not just a code deploy. Cost tracks tokens, not CPU. Rolling back code may not roll back behaviour. And an agent can be perfectly up but wrong. Tap through the assumptions.

The chapter organizes Day 2 into the Agent Governance Stack. Each layer assumes the ones below hold: you cannot meaningfully evaluate an agent whose safety rails leak.

2

Safety: deterministic rails around a non-deterministic agent

You cannot trust the model to govern itself. Three rails sit outside the reasoning loop: the input rail (PII, known jailbreaks: cheapest, run before spending a token), the action rail (entitlements; is the client in this tool call the authenticated user? That stops confused-deputy attacks) and the output rail (valid format, content policy, and grounding: does the cited source exist?). Inside them, defense is layered from cheap to clever.

Architectural tip from the book: do not ask your expensive reasoning model to be the first line of safety. A small guard model also breaks the jailbreak's context, since it never saw the persuasive conversation.

# guardrails sketch (illustrative)
input:  [deny_patterns, pii_mask, jailbreak_classifier]
action: [entitlement_check, client_scope_match]
output: [json_schema, content_policy,
         guard_model("Contains a specific buy/sell recommendation? SAFE|UNSAFE"),
         citations_exist]
on_fail: {pii: mask, advice: block_and_refer_to_human}
3

EvalOps and the evaluation pyramid

Traditional tests assert 2 + 2 = 4. Agent evals assert that "Hello" is close enough to "Hi", and that "close enough" is the whole discipline. AgentOps is platform-owned (is it running?); EvalOps is business-owned (is it good?). The book cites survey data that about one in five agent deployments never reach payback, and links that to shipping without evaluation. Invest most at the base of the pyramid, where checks are cheap.

The 100 / 5 / 1 split

Monitor 100% of actions with automated telemetry, evaluate 5% through structured pipelines (LLM-as-judge), send 1% to expert humans for calibration. Judging every request would multiply the inference bill.

Humans stop being line-item reviewers once throughput passes what people can read. They become designers of evaluation criteria and calibrators of the automated judges.

4

Judge the path, not just the answer

A lucky final answer with a broken path is a time bomb. Three trajectory metrics compare the steps the agent took with the expected ones: exact match (same steps, same order, nothing extra), in-order match (required steps in order, extras allowed) and any-order match (required tools called, any sequence). 5

Agents as services: the 2 a.m. dashboard

When the agent fails at 2 a.m., a first-line support engineer is paged. They need a dashboard, not a Python traceback. A thin service wrapper emits standard health signals, and the front page answers three questions in five seconds: is it alive, is it expensive, is it confused? Every panel must offer an action, or it belongs on the deep-dive view. Pick a scenario.

Cognitive drift is how agents rot: a pipeline works for fifty interactions, then with no code change the router develops a bias and an agent starts keeping state in chat history instead of the database. Nothing crashes; decision quality erodes one bad turn at a time. The cognitive metrics map onto the memory tiers: token velocity and loop counts for working memory, topic drift and clarification rate for sessions, retrieval quality for long-term memory, trace completeness for the audit trail.

6

Control: retries, escalation and kill switches

You can watch token spend but not forecast it confidently, so control must run live: per-workflow quotas, real-time burn monitoring, routing and execution limits before the bill lands. And "failure" is ambiguous: a model answered but wrongly, a tool succeeded with bad parameters, a workflow completed by looping. Each needs a different reaction.

7

The flash crash playbook

Agents are high-frequency decision makers: they can break things faster than humans can fix them. The book's canonical case is a real-estate company's home-buying algorithm (2021) that overvalued homes, bought aggressively, and in doing so distorted the very market data it learned from. Overvaluation bred overvaluation; write-downs ran to hundreds of millions of dollars. No drift detection, no feedback-loop analysis, no circuit breaker. Run the loop.

8

Lifecycle: from birth to retirement

The chapter opens with an organization that found 47 agents in production and could account for only 35. Monitoring the agents you know about is not enough; you need to know which exist, which should, and which should have been retired. Without that, a platform team has a collection, not a platform. Every agent gets an entry in an agent registry (a configuration database for agents) with an owner, identity, version, evaluation status and retirement date. Agents are onboarded and offboarded with the same seriousness as people.

9

Evaluation as deployment authority

One passing run proves little when outputs vary. In the agentic deployment pipeline, passing code tests does not grant deployment authority: the change must also clear behavioural evaluation and policy checks before even shadow traffic, then earn wider exposure step by step with rollback ready. 10

Human in the loop, or automated rails?

The aim is neither maximum automation nor maximum approval, but putting each kind of authority where it can carry the risk. Default: automated governance for low-risk, read-only actions; human approval for high-stakes ones (publishing premium research, accessing personal data, irreversible operations), with thresholds to move between modes. All human: queues, frustrated users, agents waiting. All automated: flash crashes and "how did it publish unverified research?" audits.
