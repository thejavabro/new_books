The agent production journey

Design is done; now the agent has to earn its way to production. The book's MREP path has six stages, each with a gate, a deliverable and a named reviewer. It looks linear on a slide. It does not feel linear when the security review discovers the identity model assumes shared credentials and sends you back to high-level design. Step through, including the bounce.

2

Two Lanes: build fast, release deliberately

AI makes the build lane noisy before it makes the enterprise faster. Teams produce far more "nearly done" work, and it all lands at the same review, test and approval gates. Those gates were always slow; AI just made the queue visible. Lane 1 is agent-assisted creation. Lane 2 is deterministic, governed promotion. Accelerate one without the other and you have built a faster way to create a backlog. Run a sprint.

Industry examples line up: one large software company found about a quarter of cycle time was waiting for review and shrank it with AI-assisted review; another lab's orchestration system keeps agents in the build lane and a ticketing system as the governed lane. The cognitive load on Lane 1 people is real too: they need curated work, not a firehose.

The adversarial gateA third discipline the lanes diagram does not draw: someone runs the operator's question live against the built system, "how would I break this?". Lane 1 produces happy-path artifacts unless that posture is present, and Lane 2 cannot detect what nobody tried. Your pipeline should accept adversarial evidence, not just functional and performance results.

Agency scope: match autonomy to lifecycle stage

How much autonomy an agent gets depends on where it sits in the delivery lifecycle. Counterintuitively, the agents that create the most value need the most room, because a human is present the whole time.

4

Choosing a framework is a governance decision

The skeptical CTO asks "why not LangChain?". The architecture director asks which framework yields the fewest security findings and the smallest operational surface. Inside Google's platform, ADK (code-first) and a low-code studio share one agent-definition format, so a business analyst's prototype can be exported to code for hardening.

Model choice follows the role (fast tiers for routing and retrieval, deeper reasoning for synthesis), and tools follow the contract rules from Chapter 2. Composed workflows are rarely one pattern: a router hands off to a sequence that contains a parallel fan-out and a bounded review loop.

5

Three environments, enforced by infrastructure

Most tutorials show one environment; regulated finance cannot work that way. Isolation lives in infrastructure as code, not convention: location, encryption at rest (customer-managed keys in production), retention and access scope are set before an agent ever runs and cannot be overridden by application code. The rule: production data never leaves production. Even an owner of dev has zero-trust access to prod; only the agent's service identity crosses the boundary.

6

Errors: the resilience pattern stack

Five failure modes recur: slow external services (timeout and retry), rate limits (backoff and quota management), invalid model responses (validate and retry), tools that are down (circuit breaker and fallback) and runaway reasoning (hard limits). The defenses compose in layers: retry with exponential backoff, a wall-clock timeout on each attempt, a circuit breaker that opens after repeated failure, and graceful degradation to a fallback source. Simulate a flaky data API.

Set the breaker from the tool's SLA, not hope: an API promising 99.5% availability fails roughly once per 200 calls.

7

Cost-aware execution

The cost-control pipeline has three checkpoints: pre-flight estimation (about four characters per token as a rough English heuristic), per-step enforcement that returns partial results when a budget is hit, and post-execution logging to an analytics store. Fan-out breaks linear estimates: three parallel agents that each spawn two sub-agents can blow a pre-flight estimate by 40 times.

The efficiency win that was notA team celebrated a sharp drop in monthly spend. On inspection, a guardrail was silently blocking real users: less spend because less traffic got through. Tag every logged session with its traffic class (end user, developer, test) so the bill can be read per real session.
8

Where should the agent run?

The book makes the default deliberately boring: start on the managed agent runtime (sub-second cold starts, long-running support, built-in governance and observability). Move to Cloud Run when you need custom networking, sidecars or polyglot containers. Use GKE or VMs only for genuine edge cases like special GPUs. Then instrument for developers: structured logs and OpenTelemetry traces from day one.
