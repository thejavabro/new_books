Context, Memory, and Knowledge

Models are rented and prompts are disposable. What an agent is given to think with, and how carefully that is curated, is the part competitors cannot copy.

1

The model was fine. The context was poisoned.

MREP's macro agent produced a flawless analysis of a central bank's rate decision, except the bank had reversed its guidance eighteen hours earlier. No alarm, no stack trace: a confident, well-written answer built on stale context. That is what context failure looks like, and it is why this chapter is the book's centre of gravity.

Data is the old oil; context is the new refinery

Everyone buys the same market feeds and rents the same models. What competitors cannot copy is the ability to refine raw data into governed, current, coherent context. The author's thesis: the agent is the commodity, the model is the engine, the harness is the moat, and context curation is the harness's inner ring. An agent does not need bits of data; it needs a coherent story. If billing and customer service disagree, the agent has no shared reality to reason over.

2

No context strategy without a data strategy

Context is refined from data, so data problems become context problems, routed faster. Raw data is cleansed, curated (chunked, embedded, tagged) and served to agents, with governance across every stage. Four disciplines underpin it: quality, freshness, secure access and lineage. Many data strategies were written for analytics read access; agents need live, governed access to systems of record. Try the readiness check: which answers are red flags?

Context readiness: acceptable or facepalm?

The trap of automating legacy"Start small, add a bit of AI" turns into "stay small" without a context-layer mandate. Automate a broken workflow and the agent simply runs the brokenness faster.
3

The context hierarchy and the intent inversion

Moving from vibe coding to engineering means separating three layers. System context is the constitution: immutable rules for every agent ("cite all sources, never make forward-looking claims"). Role context is the job description for one agent type. Task context is the runtime reality: this request, this data. A prototype leans almost entirely on task context typed into a chat; production inverts that, putting most of the weight on stable system and role layers.

The three Cs, made testableFor every context source ask: can the agent reconstruct the intent (coherent)? Is the format standardized across agents (consistent)? Is it enough to act without guessing (complete)? Failing any one produces "reasoning well on bad data".
4

Prompt engineering is not context engineering

The prompt is the static instruction layer: role, tone, format, changed per deployment and owned by a prompt library. Context is the dynamic layer: the facts available to the model, changed per request and owned by data engineering and the context pipeline. Prompts fail with wrong format or tone; context fails with wrong facts, stale data or missing information. Good prompts cannot compensate for bad context.

5

Five context sources, and which to use

Each agent gets a deliberate context profile. RAG for large, fairly stable knowledge. Tools/APIs for real-time and system-of-record data (always fresh, but latency and availability risk). Session state for the current conversation. Long-term memory for preferences and facts across sessions. Domain and policy context for rules that govern behaviour. Getting freshness wrong is the most common mistake: a day-old RAG index of macro releases is simply wrong on release day.

First decide whether each workflow is stateful or stateless. Stateless needs only working memory and grounding; stateful needs session state, long-term memory and artifacts, plus the governance that comes with them. Long-term memory is also an attack surface: poisoned memories persist, so validate what goes in.

7

RAG pipelines that agents can trust

A chatbot that retrieves the wrong paragraph gives a poor answer; a compliance agent that retrieves the wrong policy clause approves something it should not. Retrieval quality is set at ingestion: chunking, embedding choice and metadata. Then come tuning parameters, each a precision-versus-recall trade.

Pick a chunking strategy

Agentic RAG lets the agent decompose a question, search several times, judge whether it has enough and search again. Better answers, but each iteration adds embedding, search and reasoning cost; a three-pass loop costs roughly three times a single pass, which adds up at hundreds of queries a day.

8

Budgeting the context window

Even a million-token window needs a budget. The book's illustrative MREP split: about 20% system and governance scaffold (cached), 40% retrieved filings and sector data, 25% upstream agent summaries and 15% reserved for the answer, never consumed by input. When a request overflows, compression runs in a fixed order, sacrificing summaries before evidence. Push the request size.

1. Windowing: summarize older conversation turns
2. Relevance filtering: drop low-similarity chunks
3. Selective extraction: keep only query-relevant passages
4. Hierarchical loading: summaries by default, expand on demand

Monitor context_fill_rate. Cache the identical system scaffold across calls (and invalidate the cache from your deploy pipeline). Give each specialist scoped, minimal context rather than the whole conversation: isolation stops one agent's context contaminating another's.

9

Context drift: silent and measurable

Context decays. Four causes cover most incidents: stale data, context dilution (early material crowding out what matters now), retrieval errors and summarization loss. A well-known 2025 news-summary failure shows the shape: summaries that ignored which source was satire and which was reporting, which the book calls source-blind summarization. Four mechanisms help: freshness tagging, periodic refresh at decision points, relevance re-scoring and explicit forgetting. Try freshness tagging with tiered SLAs.

SLAs from the book's fix for "stale by schedule": earnings data within 1 hour, sector reports within 24 hours, slower reference material weekly.
