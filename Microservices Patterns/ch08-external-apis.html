External API Patterns

Mobile apps, browsers and third parties should not talk to dozens of fine-grained services directly. An API gateway gives each kind of client the API it needs and handles the edge concerns in one place.

Why clients shouldn't call services directly

FTGO's consumer app shows an order's status: order details, ticket status, courier location, payment. If the app called each service itself, it would suffer from many round trips over a slow mobile network, lack of encapsulation (the app is coupled to how the backend happens to be split today, and mobile apps take weeks or months to update), and client-unfriendly protocols such as gRPC or AMQP. 2

The API gateway pattern

An API gateway is a service that is the single entry point for API requests from outside the firewall, much like the Facade pattern. Tap each responsibility to see a request flow through it.

Benefits and drawbacksIt encapsulates the internal structure, gives each client a client-specific API, and cuts round trips. But it is one more highly available component to build, deploy and run, and it risks becoming a development bottleneck when every team must update it to expose their APIs.
3

Who owns the gateway? Backends for frontends

A gateway has an API layer (one module per client: mobile, browser, public API) and a common layer for edge functions. Ownership matters. A single central gateway team becomes a bottleneck, so the book recommends Netflix's approach: client teams own their API modules, and an API gateway team owns the common layer and operations. The Backends for frontends pattern goes further: a separate gateway per client type, each owned by that client's team.

At Netflix scaleNetflix's gateway handles billions of requests a day; each API call fans out to six or seven backend services on average. Client teams first wrote Groovy scripts in a shared gateway; Netflix then moved to a BFF-like design with per-client Node.js modules in their own containers.
4

Gateway design issues

Four issues to get right. The first is performance: a gateway handles a flood of concurrent requests, mostly waiting on backends. Compare blocking and non-blocking I/O.

Thread-per-request is simple but each thread costs memory and scheduling. NIO frameworks (Netty, Vert.x, Spring Reactor, JBoss Undertow) use a few event-loop threads. When Netflix rewrote its Zuul edge server for NIO, I/O-bound routing got about 25% more throughput and 25% less CPU; CPU-bound work such as decryption saw no gain.

A GraphQL-based gateway

REST gateways struggle when clients want different shapes of the same data. GraphQL lets the client say exactly what it needs. The gateway defines a graph-oriented schema (types such as Consumer, Order, Restaurant and their relationships) and resolvers that fetch each field from a service.
