Introduction to Multi-Agent Systems

The model is the brain, but dependable agency comes from the architecture around it. This chapter places multi-agent systems in the arc of AI and gives you a test for when a team of agents is worth its overhead.

Each wave removed one ceiling and exposed the next

AI did not march toward agents by destiny. Each era solved the limit of the one before and then hit a new wall. Tap through the waves to see what each added and where it got stuck.

The unit of engineering in this bookNot the model, but the agentic system: a model running inside a control loop that has goals, tools, memory, evaluation and recovery. A multi-agent system (MAS) is one topology for that system, worth it when responsibilities benefit from separate boundaries.
2

Why organize, if models keep getting smarter?

Rich Sutton's "bitter lesson" says hand-built structure tends to lose to more compute. So will agent architectures age badly? The authors' answer is no, and the argument comes from civilization: the smartest individual brain still doesn't run a hospital alone. Institutions are the cognitive architecture for distributed problem-solving, and peer review matters more as scientists get better. Stronger models raise the level at which we organize; they don't remove the need.

Each institution maps to a concrete design lever. Tap a card.

Why interaction helps

  • Specialization shrinks the search space each step faces.
  • Independent evidence catches silent errors, but only if the reviewer really has different evidence, tests or context. A second persona on the same model is not independence.
  • Parallel exploration covers more hypotheses in the same wall-clock time.
  • Explicit handoffs turn hidden reasoning into logged, replayable artifacts.

When it backfires

  • Correlated reviewers: a critic that agrees by default adds cost, not checks.
  • Shared bad context: one agent writes "no record exists" after a timeout; everyone inherits it.
  • Weak aggregation: a thin synthesis step wastes the parallel work.
  • Coordination cost > benefit: then one agent is strictly better.

A community teardown of one coding agent found only a tiny slice of its code was model-facing decision logic; the rest was harness. Most of an agent is the system around the model.

3

What is an agent, anyway?

The classic textbook definition says an agent is anything that perceives its environment through sensors and acts on it through actuators. A thermostat qualifies. What matters is the closed loop. An LLM agent puts a language model in the "decide" seat: it reads prompts, API payloads and records, plans, and acts through function calls and scripts.

The loop repeats until the goal is met or a budget runs out.

Ask "how agentic?", not "is it an agent?"

Borrowing from the self-driving levels, the book names five levels of agenticity by what the system takes responsibility for, not by raw capability. Agenticity and topology are separate axes: one runtime can be very agentic, while a many-agent workflow can stay tightly bounded.

Start at the minimum viable levelToo little agenticity gives brittle, over-prompted systems; too much gives unpredictability and coordination overhead. Move up a level only when you hit a structural limit you can name.

The four-criterion test

A separate agent boundary is justified when the problem shows at least one of four structural properties. "MAS is more powerful" is not one of them. Load a preset or tick your own.

What coordination costs you

Distributing work across loops trades local simplicity for system complexity. The first cost is latency and tokens. Chain agents sequentially and add revision rounds to watch it compound.

The infinite loop trap

Agent A asks for a fix, B proposes one that breaks something, A reports it, B reverts. Repeat.

8

Microservices: a useful, limited analogy

If you've run chatty microservices, a badly orchestrated agent team will feel familiar: cascading calls, tail latency, confusing failures. But the analogy breaks on one dimension: services talk through deterministic typed APIs, agents through probabilistic, context-heavy dialogue. Pick a dimension.
