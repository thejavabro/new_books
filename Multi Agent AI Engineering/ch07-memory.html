Context and Memory Management

What an agent remembers, and what crosses between agents, is an architectural decision with a daily cost. Memory needs a lifecycle: write, retrieve, consolidate and forget.

A bigger window is not memory

Strip an agent of memory and it's an expensive autocomplete. A larger context window adds capacity, not memory: it's rebuilt from scratch on every call, and attention degrades as it fills. The context propagation problem

Split a task across agents and every memory gets an owner and an audience. If everyone sees everything, windows fill with noise and private data leaks; if nobody shares, agents redo work. When an orchestrator spawns a sub-agent, it chooses what that new window starts with.

Short-term memory: managing the window

Fifty tool calls at 500 tokens each is 25,000 tokens of history. Long contexts don't just get slow and costly; they fail in named ways. Click each mode.

Compaction over a 40-turn task

A useful order for conversational agents: prune obvious waste first, then summarize, and truncate only as a last resort. Watch for compaction's own failures: summaries keep fluency and drop specifics (brevity bias), and repeated summaries of summaries drift. Platform-managed compaction and model-learned compaction are newer options.

Long-term memory and its lifecycle

Long-term memory outlives the session: user modeling, task continuity, learned lessons. Keeping something is a decision, not a default; the research assistant keeps vetted claims with provenance, not raw passages. Memory moves through seven stages. Click one.

6

Shared memory with least privilege

Shared stores need access control, namespacing, a consistency story and an audit trail. Write authority matters more than read: who may create, who may overwrite, who may delete. Pick an agent to see its permissions across a software team's namespaces.

Concurrent agents read, think, and write much later, so use optimistic versioning: a write that finds the record changed since it was read is forced to re-read rather than silently losing an update. For small, session-bound needs, a file-backed memory tool the agent reads and writes is a lightweight alternative: no retrieval, TTL or ACLs, but nothing to operate.

Context assembly on a budget

Retrieved memories get at most about a third of the budget so the past doesn't crowd out the present, and they're delimited as untrusted data, each line carrying its source and confidence. For caching, place them after the settled history, just before the current turn.

9

Diagnosing memory failures

Bad memory throws no exceptions; it produces plausible answers on the wrong foundation. Match the symptom to the failure.

Symptom → failure

Production signals: retrieval precision (used vs. retrieved), context-assembly latency, store growth, supersession lag and conflict counts. Benchmarks show long-context use is far less effective than the advertised window suggests, so measure your own.
