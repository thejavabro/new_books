Design Patterns for Multi-Agent Collaboration

A handful of collaboration patterns cover most agent teams. Each has its own forces, cost profile and failure signature, and real systems compose them.

1

Patterns: named answers to coordination problems

Every multi-agent system solves two problems: the domain problem and the coordination problem. A pattern fixes the coordination: topology, communication flow, aggregation rule and termination condition, and accepts a specific profile of latency, quality, cost and robustness. Answer the forces for your task and watch the candidates narrow.

Concurrent specialists: fan-out, fan-in

Several specialists analyze the same input in parallel from different angles; an aggregator combines them. Latency is the slowest specialist, not the sum. A good aggregator survives a failed specialist and says what's missing.

The echo chamber: diversity, not headcount

Five voters, each right 70% of the time. How correlated are their errors (same model, same prompt, same sources)?

3

Sequential workflows: cascade or relay

Sequential patterns divide work by stage. A cascade is an assembly line: fixed order, one job per stage, only the artifact moves. A relay transfers ownership: each hop decides what happens next, so the handoff carries what was done, why, and what remains. Switch between them.

Cascade weaknessesLatency adds up (four 5 s stages = 20 s). A failed stage blocks everything after it (cheap fix: per-stage retry, then abort). Errors only flow forward: a stage that reads only its predecessor can't see an earlier constraint it silently dropped.
Relay costContext grows each hop: more tokens, more latency, and eventually the window. The weight buys protection from context loss. Keep the remaining-goals list updated, or hop three redoes what hops one and two already did.
4

Task decomposition: plan, execute, reassemble

A supervisor splits the problem into sub-tasks with dependencies, workers run what's ready (in parallel where possible), and the supervisor reconciles the results. Supervisor decides what; workers decide how: bounded autonomy again. Step through a run.

5

Debate and reflection: structured disagreement

Generation is easier than verification. Debate pits a proposer against a critic under a judge; reflection has one agent generate, grade against criteria, and revise. Both only work if the errors are independent: a critic that shares the proposer's model, prompt and sources draws the same wrong conclusions. Explore how rounds pay off.

Practical controls: a hard round cap (most gain arrives in the first two or three rounds; after that agents oscillate), a structured convergence flag rather than scanning text for "YES", and a judge that synthesizes both sides instead of picking a winner. A graded rubric lets a separate evaluator return actionable feedback. The research assistant only debates the contested claim, with advocate and skeptic each handed different sources.

6

Mixture of experts: route, don't broadcast

A router reads each task and activates only the best-suited specialist: a resource optimization. The router is the single point of failure, so it reports a confidence; below a threshold, broaden to a generalist or the whole panel. Set the threshold and route the tickets.

Composing patterns, safely

Real systems combine shapes: route support tickets with mixture of experts, resolve inside each expert with a cascade, and debate only high-stakes resolutions. Four grammar rules keep compositions sane. Rule 1 is arithmetic: chaining adds cost, nesting multiplies it.

Anti-patterns and failure signatures

Each pattern degrades in a recognizable way. Instrument the signal, and treat sustained drift as evidence the pattern no longer fits.
