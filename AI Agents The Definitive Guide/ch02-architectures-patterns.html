Architectures and Patterns

Most agents are built from a small set of control patterns. Knowing which pattern fits a task, and what it costs, matters more than which framework you pick.

Why architecture matters: one shot versus a loop

Give two agents the same job: summarize this document and make a bar chart of its key statistics. A single-step agent reads the request once, plans everything internally, runs it and hands back the result without ever looking at intermediate output. A multi-step (ReAct) agent alternates thought and action, storing each observation and adapting until it is satisfied or out of budget. Step through both.

      Before the patterns, one cheap trick: give agents personas. A planner framed as a methodical strategist and a critic framed as a tough evaluator reason differently, and their exchanges in a team become more purposeful.       Chain of thought: think out loud

      Chain-of-thought (CoT) asks the model to solve intermediate steps before the final answer. In an agent it is more than a prompting trick: the visible stages guide control flow, leave an audit trail, and often let a smaller, cheaper model handle a task that would otherwise need a big one. Pick a scenario to see a stage structure you could prompt for.

      The book's data-analysis agent combines a CoT system prompt (describe the data, find patterns, conclude) with a sandboxed Python tool. Pyodide runs Python compiled to WebAssembly, so the agent's code executes in isolation, prints to stdout and surfaces errors as tracebacks.

      3

      Tree of thoughts: propose, prune, pursue

      Tree of thoughts (ToT) turns the single chain into a small search. One stage proposes several candidate approaches, a second evaluates and prunes, a third executes the winner. The stages can be graph nodes or separate LLM calls with different models. A neat cost trick: let a small model propose and a stronger model judge, because the judge's routing decision is the high-impact one. Wiring the stages together with edges is a handoff: who acts next, and when.

      ToT as an engineering shortcutA lightweight propose-and-judge setup can sometimes replace a full multi-agent system. The "roles" are just workflow stages, which keeps the design simple and avoids repeated calls to a large reasoning model.

      ReAct: reasoning and acting, folded into state

      Reasoning alone never leaves the page; acting alone never learns. ReAct treats every step as a choice between producing a thought in language and taking an action in the environment.       Human in the loop: pause before it stops being funny

      An agent calling the wrong tool in a demo is funny. The same mistake against access control, payments or customer data is not. Human-in-the-loop (HITL) lets the graph pause at critical points, wait for a person and continue only when it is safe. It also leaves an accountable, traceable record of who approved what.

      6

      Supervisors, hierarchies and swarms

      When one agent starts struggling, split the work. A supervisor architecture has every worker report to one router that decides who acts next. A hierarchical architecture adds supervisors of supervisors: teams of teams. A swarm drops the boss: peers hand control to each other with handoff tools, and the system remembers who was active last. Note the difference from ToT: ToT branches over alternatives for one task; a multi-agent system routes work across specialists.

      PatternUse whenBenefitsTrade-offs
      SupervisorSmall team, clear rolesSimple; strong control; fewer deadlocksCentral bottleneck and single point of failure
      HierarchicalLarge, multi-team workflowsModular, scalable, mirrors an org chartHarder to debug; needs careful design
      SwarmPeers bouncing work back and forthFlexible, natural flowLess predictable; handoffs must be robust
      Tuning handoffsHandoff tools are ordinary tools. You can rename them so their purpose is obvious, add arguments (such as a task description for the next agent), and filter what context travels with them instead of passing the full message history.
