1

Rewards to reasoning: reinforcement learning, plainly

Arthur C. Clarke said sufficiently advanced technology looks like magic. Agents that seem to improve themselves are that kind of magic, and the trick underneath is reinforcement learning (RL). The core is simple: act, get a signal saying how well it went, adjust so the next choice is better. For an LLM agent the loop runs in language. Every message, tool call and intermediate output is part of a trajectory, the full record of how an answer was reached. Several trajectories for a task are rollouts, and comparing them is where learning happens.

2

Better in groups: relative ranking and the KL leash

Absolute scores for creativity or depth of thought are hard to define. Relative ranking sidesteps that: sample several answers to the same prompt, score them, and normalize within the group. The scores only need to be consistent inside the group. Each answer's advantage is Ai = (ri − mean) / std. Above-average answers get pushed up, below-average ones down. This is the heart of GRPO (Group Relative Policy Optimization), and it needs no separate critic model.

Learning too fast is dangerous: if the new policy drifts far from what the model already knows, it forgets useful behavior. The KL divergence measures how far the updated distribution Q has moved from the reference P, and a KL penalty in the objective acts as a leash. The agent can explore, but not run away.

3

Token level or sequence level: GRPO versus GSPO

GRPO computes an importance ratio for every token: how much more or less likely the new policy is to produce that token than the old one. Each ratio is clipped to [1−ε, 1+ε] to stop wild updates. On long answers those per-token ratios fluctuate independently and the noise adds up, which can destabilize very large or mixture-of-experts models. GSPO (Group Sequence Policy Optimization) takes one ratio for the whole response, the length-normalized geometric mean, and clips that. The reward belongs to the sequence, so the update does too.

4

RULER and ART: teaching an agent a skill

RULER is a general-purpose reward function built on an LLM judge. It runs several trajectories for one task, strips the shared prefix, and asks a judge to score each from 0 to 1 against a short rubric, side by side. Comparing is easier for a model than grading one answer in isolation, and GRPO only needs within-group consistency, so no labels or handcrafted rules are required. ART is an open-source trainer that collects those groups of tool-using rollouts and applies GRPO updates.

When correctness can be checked by code, check it by code. The book trains an agent on countdown puzzles: reach a target using given numbers once each with + − × ÷. A deterministic judge gates the reward; RULER then ranks how well the valid answers explain themselves. That is a hybrid reward: precision first, quality second. The same idea fits code agents (tests pass, then judge readability).

5

Test-time compute: think longer instead of growing bigger

Making models ever larger gets unsustainable. A different lever is to spend more compute at inference: sample several paths, reflect, revise. Reward models move from training into the reasoning loop itself, scoring branches as they unfold, and small models can match bigger ones this way. Two flat strategies frame the trade-off: repeated sampling (breadth only: many independent answers) and sequential refinement (depth only: improve one answer again and again).

Monte Carlo Tree Search balances both with four steps: select, expand, simulate, backpropagate. Selection uses UCT: UCT(s) = V(s) + c·√(ln N(parent) / N(s)). The first term exploits what looks good; the second rewards children that have been visited little. Tune c and watch which child gets picked.

6

Adaptive branching: go wider or go deeper?

Standard MCTS uses a fixed branching factor, but one prompt can produce endless different answers. AB-MCTS adds a GEN option under every node, meaning "write a brand-new candidate". The alternative is to refine an existing answer (a CONT step in the aggregation variant, AB-MCTS-A). Thompson sampling decides: draw a plausible score for each option from its posterior and take the highest. Uncertain options occasionally draw high, so they get explored; proven ones get refined. The mixed-model variant, AB-MCTS-M, builds a per-node Bayesian model from scores observed in subtrees instead.

Answer quality is hidden; the judge sees noisy scores.
7

Training whole workflows: rLLM

Once agents combine roles, branches and search, you want the whole system to learn, not one policy. rLLM is an open-source framework where a workflow engine runs complex programs (solver and judge, planner and executor, tree search) and a trainer gathers every component's trajectories, computes relative advantages and applies KL-regularized updates. You subclass a workflow, implement run(), and return an episode with trajectories and rewards. The book's example is the 24 game (make 24 from four numbers like 3, 3, 4, 5): solvers propose, a judge picks, and each is rewarded for its own part.
