Deploying Agents in Real Products

A deploy button is not the finish line. Real products need observation from day one, fuses against runaway loops, tested fallbacks, and respect for the physics of GPUs and caches.

1

Shipping is a loop, not a button

Vendors make "deploy to endpoint" look like the finish line. In real production models flake, latency spikes, and agents make perfectly logical decisions that wreck data or burn the budget. The book avoids vendor tutorials and focuses on what survives provider changes: fallbacks, inference abstraction, feedback loops, failure modes. Think of it as rehearsing a cast of nondeterministic actors so opening night is not your first debugging session. The loop is build, observe, harden, integrate, optimize.

2

The MVP is a diagnostic lab, and you monitor from day one

An agent MVP is not a feature-thin product; it is an experiment harness. A lightweight UI (Streamlit, Gradio) and a managed PaaS that redeploys on every commit within minutes let you tweak a prompt or a route and immediately see how real users react. You are collecting evidence: where agents hesitate, where reasoning breaks, where cost spikes. And you cannot improve what you cannot observe, so monitoring starts with the MVP, at the agent level as well as the system level.

Trace sampling budget

Rules of thumb from the book: define redaction rules first (PII, card data, secrets, tokens never captured). Log everything in development. In production keep every error but only 10 to 25 percent of successes. During incidents or big changes go back to 100 percent.

Stream, don't waitLong agent runs blow past typical 30-second request timeouts. Use WebSockets or Server-Sent Events to stream progress and user-safe intermediate results instead of a single blocking POST.
3

Hardening the backbone: checkpoints, a context janitor, fuses

Moving to a production API is where "agent vibes" become "system physics". You are handing a nondeterministic actor your infrastructure and your wallet. Three patterns carry most of the weight: checkpointing every turn (crash at step 4 of 10, resume at 4), a context janitor that keeps the system prompt and the last N turns and replaces the middle with a summary, and a circuit breaker with a budget fuse and a turn fuse. 4

The fallback guy (or it's you at 3 a.m.)

The primary model will fail: timeouts, outages, outputs that parse but are wrong. Design the fallback with the system and test the second-choice model through the whole pipeline, because a fallback that struggles with JSON still breaks you. The book builds three enforcement tiers for structured output. At minimum implement the first two.

Tier 1 · strict schemaProvider-side constrained decoding. Best shape guarantee, for one call only.
Tier 2 · Instructor + PydanticValidate, normalize, retry with the error. Works with any JSON-capable model.
Tier 3 · degraded + canonicalizeBlunt prompt, accept key aliases, map values, infer priority conservatively.

Model drift is the quiet killer: different models say the same thing with different labels. Normalization maps translate every variant into a small stable vocabulary, and anything unmappable is rejected rather than guessed (priority drives paging, so it is strict).

5

Self-hosting: cold starts, caches and deployment physics

Host models yourself and the agent is talking to a GPU process with physics. Weights must load into VRAM before the first token; in the book's test a 3B model on an A100 took 124.6 s to start versus 0.277 s for a warm request, about 450× longer for the first user after a deploy. Scale to zero saves money but turns every idle gap into a cold start. Store weights on a persistent mounted volume so new workers read from disk instead of re-downloading gigabytes.

One simulated day of bursty traffic. Red = request that hit a cold start.

Long histories cost three ways: time-to-first-token rises because prefill attends over the whole prompt, the KV cache grows and squeezes batching, and each decoded token reads more cache. Prefix caching helps (the book measured 1.1× to 1.2× on short requests; shared long prompts gain more), until the prefix changes. Swapping system prompts, injecting RAG context or forking a conversation pays the cache invalidation tax.

Don't guess, measureEvery GPU and model size moves the bottleneck. Benchmark your own setup under concurrent load, keep agent code backend-agnostic behind the OpenAI-compatible API, and remember quantized checkpoints can cut both hardware needs and cold-start time.
