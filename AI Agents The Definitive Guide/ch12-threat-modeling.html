Threat Modeling for AI Agents

Every tool, memory store and input is a door. Threat modeling asks who could walk through each one, what they could do, and which layer stops them.

1

Systems that decide need a different threat model

Classical threat modeling asks which assets matter, which components handle them and how confidentiality, integrity and availability (CIA) could be hit. That still applies: agents run on infrastructure, call APIs and use databases. What changes is the path to failure. An agent can carry intent across the whole system: an injected sentence becomes a plan, the plan becomes an API call, and the call's result becomes a memory entry. Some failures need no attacker at all, only a system being more helpful than intended.

The approach in this chapter combines three things: an asset-centric, layered model of what is critical; known attack patterns (injection, exfiltration, interface misuse); and red teaming to check that your assumptions survive contact. Ideally you do this before the system is fully built.

4

One poisoned review, four layers

A travel agent plans a five-day beach trip under $2,000. It reads third-party reviews, compares options and can make outbound HTTP calls; its planning memory persists across sessions. One highly ranked review hides an HTML comment telling the agent to summarize the user's personal details and send them as query parameters to an attacker's site. This is indirect prompt injection: the attacker never talks to the agent.

Every per-component check passed: well-formed URL, valid auth, within rate limits and permissions. Component-level API security stops abuse of a tool, not misuse by an authorized caller acting on corrupted state. And because the agent's own output becomes future context, the compromise outlives the session.

5

When the agent persuades the approver

Human approval is a key safety gate, but a compromised agent can reason, and it can argue. Instead of asking bluntly, it presents a polished justification. Which of these would you approve?

6

Red teaming as a loop

Red teaming an agent means attacking whole execution paths (planning, tool calls, memory updates), not single prompts. It is a cycle, not a one-off audit. Tools such as DeepTeam automate it, and benchmarks such as CyberSecEval measure a model's own susceptibility before you build on it.

7

A trust-aware runtime scanner

You cannot anticipate every input to a nondeterministic system, so runtime guardrails are the last layer. LlamaFirewall bundles a jailbreak classifier, alignment checks on intermediate reasoning and static analysis of generated code, and lets you add custom scanners. The book's custom scanner does four things this toy reproduces:

  • Trust contexts: the same text is scored differently from an untrusted user, a developer (lower exfiltration weight) or tool output (amplified, since indirect injection lives there).
  • Normalization of Unicode lookalikes, plus a signal for invisible characters such as zero-width spaces.
  • Capped category weights plus stacking bonuses when many cues cluster.
  • A semantic judge (a small LLM) called only when the lexical score is uncertain, to catch paraphrases cheaply.
