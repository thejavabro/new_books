Core Components: LLMs, Prompting and Agents

An LLM is a probabilistic token machine. Learn how it picks the next token, how sampling knobs change the pick, how a good prompt steers it, and how a few lines of code turn it into an agent with tools.

An LLM predicts one token at a time

Given the text so far, the model produces a probability for every token in its vocabulary, samples one, appends it, and repeats. That is all generation is. Pick the next token yourself and watch the sentence grow.

What is a token?

Models read and bill in tokens: common words are one token, rare words split into pieces, and spaces and punctuation count too. Text length is not token length, so measure tokens (with a tokenizer such as tiktoken, or the SDK's usage numbers) to keep cost and context windows under control. Temperature and top-p reshape the odds

Temperature flattens (high) or sharpens (low) the whole distribution before sampling. Top-p keeps only the smallest set of tokens whose probabilities add up to p, cutting off the unlikely tail. Providers advise tuning one or the other, not both. Neither is a hard guarantee: temperature 0 still is not perfectly repeatable.

Different agents, different knobs

Settings follow the agent's job. A coder wants strict, repeatable output; a creative writer wants variety. Penalties push the model away from tokens it has already used: presence penalises any reuse, frequency penalises repeated reuse. Max tokens caps the length of the answer.

Build a prompt, piece by piece

The core techniques: a clear persona, instructions up front, delimiters that separate instructions from data, few-shot examples, and chain-of-thought ("think step by step"). Toggle each one and watch the prompt, its token cost, and how predictable the output becomes.

Anatomy of a minimal agent

  
With the OpenAI Agents SDK, an agent is a small object: a name, instructions (the persona), a model and settings, optional tools, and an optional typed output. A runner executes it. Click a part of the code to see what it controls.

Tools and tracing

  
Give the agent tools and it chains them on its own. Built-in tracing records every LLM turn and tool call as spans, so you can see the decision path and where time goes. Run the agent and watch the trace build.

9
Every tool has a price

  
Each registered tool's name, description and schema ride along in every model call, whether used or not. More tools mean more tokens and more chances to pick the wrong one. Keep each agent's list short and on-topic; the book suggests fewer than ten.
