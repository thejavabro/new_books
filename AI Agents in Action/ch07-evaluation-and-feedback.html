Robust Agents: Evaluation and Feedback

An agent you cannot measure is an agent you cannot trust. Bake evaluation and feedback in from day one: write benchmarks first, check answers against their sources, score fuzzy output with rubrics, and trace everything.

Evaluation and feedback around an agent

The agent's own Learn step (from sense-plan-act-learn) is only the start. External checks surround it, and each sends feedback either straight back into the loop or into an evaluation store for later analysis, where a feedback agent can watch for trouble. Click a component.

2

Three kinds of check

Deterministic tests for exact things (schema, tool called, known answer). LLM or agent evaluators for fuzzy natural-language judgement. Humans for edge cases, policy, tone and real-world judgement. Which fits?

Pick the evaluator

3

Test-driven agent development

TDAD flips the order: write benchmarks first (including tempting wrong answers), watch the bare agent fail, make the smallest change to the prompt, tools or model that passes, re-run each test several times, then refactor. Step through building a small knowledge agent.


  






  
4
Benchmark for stability, not one lucky pass

  
LLMs are stochastic. A test that passes once may fail on the next run. Run each test repeatedly and watch pass rate, latency and token use. Simulate an agent with a given true reliability.

When benchmarks fight each other

  
Sometimes fixing one test breaks another: "be concise" versus "include every policy detail". Decide explicitly. Tap each option.

  

  
Tool tip from the chapter: put tool guidance in the tool's name and docstring, not in more prompt text. Renaming search to search_special_knowledge_db with a clear docstring often fixes tool choice without touching the persona.






  
6
The grounding agent

  
Grounding checks whether each claim in an answer is supported by the source the agent retrieved. Wrapped as an output guardrail, it trips on ungrounded answers and lets policy decide: regenerate, block with a safe reply, or annotate. Run a check.

7
Rubrics turn taste into numbers

  
For high-variance output (reports, charts, images), a critic agent scores against a rubric of criteria and scales, and returns typed feedback. Loop generate → critique until the score passes or attempts run out. Set the bar and run.

Observability: traces, sessions, experiments

  
OpenAI Traces shows every tool call and LLM turn. Arize Phoenix (built on OpenTelemetry) adds projects, sessions, cost and latency metrics, datasets built from spans, experiments, evaluators and human annotations. Click a span.
