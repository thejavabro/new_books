Understanding the Agentic Loop

The agentic loop is the engine behind any agent that must iterate toward a goal rather than answer in one pass. It comes in three layers, and every loop needs a goal, an iteration strategy and explicit reasons to stop.

1

Three loops, nested

Layer 1 is the agent's own sense-plan-act-learn cycle. Layer 2 moves the plan and state outside the agent, usually into code, so it can pursue long-horizon goals. Layer 3 puts agents in charge of the loop. Click a ring.

2

Anatomy of one loop

Every loop rests on a goal (what to achieve), a plan or iteration strategy (what to do each cycle), state (what carries over), a tool (how it acts) and a decision (when to stop). What makes it agentic rather than a plain while-loop is that the agent makes those decisions. Watch state accumulate.

3

Why externalise the loop?

A short goal fits in one agent run. A long one (a deep research report, a migration of 300 files) would overflow the context window, and general-purpose LLMs are not built for very long iterations. So layer 2 keeps the plan and state outside the agent and calls the agent once per step. Slide the horizon.

4

A deep research loop with a termination gate

Each iteration: search, read, add findings to the state, generate follow-up questions, report a typed result (goal satisfied? confidence?). A termination gate in code checks layered conditions: hard iteration limit (safety net), budget (cost), goal satisfied (ideal exit), quality threshold (evaluator), stagnation (diminishing returns). Tune the gate and run.

5

Control what each iteration sees

The state accumulator grows every cycle. Feed it back raw and the context window fills; truncate, summarise or compress earlier findings to keep each call lean. Typed iteration output (Pydantic) is what lets the controller do this reliably.

6

Repetitive task loops

Not every loop is research. A task loop works through a queue: track completed, failed and pending items; retry transient failures and feed the previous error back to the agent. When items are independent, run them in parallel (Python's asyncio.gather), within rate limits.

7

Adaptive iteration budgets

Let the agent estimate how many iterations a task needs and request them, while the developer's hard ceiling always wins. Never ship a loop without both an iteration limit and a cost ceiling.

8

Layer 3: agents running the loop

In an orchestrated meta loop, one delegating agent holds the decision, state and plan, and uses sub-agents as tools. In a collaborative meta loop, several agents share in the decision and may or may not share state and plan.
