Deploying Agents and Agentic Systems

How people consume an agent decides how you deploy it. From a browser voice agent to a queue of background workers, this page covers runtimes, wires, containers, reliability, cost and the security model that turns a demo into a production system.

3

Agents as containerised microservices

Agents are self-contained, so they make natural microservices: easy to scale, swap and version. Docker standardises runtime and dependencies; Compose stands up the whole stack (UI, worker agents, tool services) with one command; a tunnel such as localtunnel shares a local prototype for a quick demo.


  






  
4
The front-door agent pattern

  
A light front-door agent talks to the user and routes intents to specialised workers, each with its own wire and latency budget. Keep the front door simple; push complexity into typed, well-scoped workers. Pick an intent.

  

    

    

    

  






  
5
State and idempotency

  
Agents retry and replay tool calls. An idempotent call gives the same result however many times it runs, so it can be cached by a key derived from its inputs and replayed safely. A weather lookup is idempotent; sending an email is not. Keep short-term chat state (Redis, Postgres) apart from long-term knowledge (vector indexes).

6
Release engineering for agents

  
Prompts, tools and models are all code. Version them, promote through gates, and pin exact versions so an incident can be reproduced. Change something and push it through the pipeline.

  

    

    

    

  






  
7
Timeouts, fallbacks, circuit breakers

  
Tools and models misbehave. Timeouts stop waiting forever, fallbacks try a cheaper model or a cached answer, a circuit breaker stops hammering a failing dependency, and graceful degradation keeps the agent useful. Turn up the failure rate and send traffic.

8
Cost control and model routing

  
Route by intent: small, cheap models for simple jobs, big ones only where needed. Trim context and cache deterministic results. Fewer tokens usually means lower latency too. Prices below are made-up units.

10
Prompt injection, direct and indirect

  
Injected instructions arrive through the same channel as legitimate context. Direct injection comes from the user; indirect injection hides in content the agent reads (a web page, a document, an email, a tool result). Turn on defences and summarise a poisoned email.
