Robustness and Fault Tolerance Patterns

LLM agents fail in new ways: they hang, loop, misread prompts, get hijacked by their input, and give different answers to the same question. Seventeen patterns turn those failures into recoverable, measurable events.

Robustness is a spectrum of five levels

Do not implement everything at once. Adopt patterns in layers as the system's importance grows. Pick a level to see what it adds.

Where the patterns live

2

Pattern chaining: what happens when an agent fails

Patterns hand off to each other. Choose a failure and watch the loan workflow escalate from the cheapest fix to the most expensive one, logging every step for the audit trail.

3

Redundancy: parallel consensus and majority voting

One agent's answer is one sample from a non-deterministic system. Ask two and compare (Parallel Execution Consensus), or ask three or more and vote (Majority Voting). Set the error rate of each agent and simulate 1,000 credit decisions.

4

Watchdog timeouts and incremental checkpoints

Watchdog Timeout Supervisor: every agent call runs against a timer; a hung agent is killed and the task re-routed instead of freezing the workflow. Set the timeout and run five calls.

Incremental Checkpointing: a five-stage document pipeline fails at stage 4. Compare restarting from scratch with resuming from the last checkpoint.

5

Three rings of defence

Self-Defense protects one agent from its input, Mesh Defense stops a compromised agent from reaching others, and Execution Envelope Isolation contains whatever the agent runs. Try each attack.


    

  






  
6
Translation overhead and rate limits

  
Optimizing for Translation Overhead passes a reference to data in a fast store instead of stuffing the data into every prompt. Grow the document.

  

    

    

    

  

  
Rate-Limited Invocation keeps an agent under the credit bureau's quota (here 5 calls per 10 s). Fire a burst and watch the limiter queue the excess instead of getting the key banned.

  

    

    

    

  






  
7
Fallback models, trust scores and canaries

  
Fallback Model Invocation: if the primary model errors, times out or fails a format check, reroute to a backup and keep serving. Trust Decay and Scoring: route more work to agents that have recently done well. Degrade one summariser and watch traffic move.

  

    

    

    

  

  
Canary Agent Testing (shadow mode): the new version gets a copy of live traffic in the background; only the stable version answers users. Promote it when the comparison log looks good.
