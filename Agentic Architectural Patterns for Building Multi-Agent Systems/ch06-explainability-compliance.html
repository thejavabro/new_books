Explainability and Compliance Patterns

Agents fail quietly: each step looks fine, yet the original instruction is lost somewhere down the chain. Four patterns keep a system faithful to its instructions and able to explain itself to an auditor.

1

The failure mode: instruction drift

An instruction passes down a chain of agents. Each hop summarises, reframes and adds context, and the constraint that mattered most slowly fades. Turn the protections on and send the instruction again.

2

Instruction Fidelity Auditing

An auditor agent does no work itself. It compares a worker's output with the instruction the worker was given and blocks anything that breaks a constraint. Step through the discount example.







  
3
Fractal Chain-of-Thought Embedding

  
Ordinary chain-of-thought is a straight line written once. Fractal CoT treats reasoning as units that can be revisited, zoomed in or out, and corrected when another agent supplies new evidence. Watch a literature review on climate-resilient urban design revise itself.

  

  






  
4
Persistent Instruction Anchoring

  
Models favour what they read last. A constraint stated once at the top of a long, growing context gets buried. Anchors repeat it in a tagged, standard form in every hand-off. Grow the context and compare.

5
Shared Epistemic Memory

  
A port closes. If agents pass that news along by chatting, some hear it late or garbled. With a shared memory, one write updates everyone's view. Trigger the event in both designs.

Composing all four into one defence

  
The patterns stack: memory is the ground truth, anchors carry the mission, fractal CoT governs reasoning from the inside, and the auditor checks the outcome from the outside. Click each layer.

DriftSub-tasks succeed locally while the overall instruction is silently missed.

    
AuditA separate auditor verifies outputs against the original instruction and blocks violations.

    
Fractal CoTRecursive, multi-scale reasoning that can revise past conclusions with new evidence.
