The database solutions architect

Database SAs design, implement and maintain database systems that fit the business, then keep them fast, safe and available. Interviews cover modeling, engine selection, SQL, HA, scaling, tuning and migration.

2

What a DBMS gives you

Know the components: DDL and DML (SQL), query and reporting, security, integrity constraints (primary and foreign keys), backup and recovery, concurrency control with locks and transactions, indexing and optimization, replication and distribution, and scaling through partitioning and sharding. Then know the two consistency philosophies.

Indexes and joins

  
An index (usually a B-tree) turns a full table scan into a short tree walk. Slide the table size and compare the work.

  

    
    

    
Every extra index costs storage and slows inserts and updates, because each index must be maintained. Index the columns you filter, join and sort on, and read the execution plan.

7
Availability, scale and trade-offs

  
HA: replication, automatic failover, redundancy and backups. Scale: vertical, read replicas, partitioning, sharding, caching. Every choice trades something. The biggest one is how replicas are kept in sync.

  

    

    

    

  

  

    
Read vs writeDenormalization, caches and materialized views speed reads but slow writes.

    
Space vs speedNormalized saves disk; denormalized stores more for faster queries.

    
PartitioningSmaller segments, parallel work, easy archiving; choose the key carefully.

    
CachingBig read wins; invalidation and staleness to manage.

    
IndexesFast reads, slower writes; index for frequent queries only.

    
Managed cloud DBsAutomatic backups, patching, scaling and cross-region DR.

  






  
8
Database migration

  
Three approaches: migrate (move with minimal change, e.g. MySQL to PostgreSQL), modernize (adopt managed features on the way, e.g. to a managed cloud database), transform (redesign structure and logic). Types include homogeneous, heterogeneous, on-prem to cloud, cross-cloud, version upgrade, consolidation and platform migrations. The book's whiteboard walks a heterogeneous move to the cloud with a migration service.
