Security architects build protection into every layer rather than bolting it on. Expect questions on least privilege, defense in depth, encryption and key management, compliance, and incident response.

1

The security solutions architect

Security SAs design protection into systems from the start: architecture and threat modeling, policies and standards, identity, data protection, compliance, security operations and incident response, and teaching everyone else to do their part.

2

Security design principles

The chapter's principles are the classic ones: least privilege, defense in depth, fail-safe defaults, economy of mechanism, complete mediation, open design, separation of duties and least common mechanism. Name the principle each situation breaks.

Which principle is violated?

3

The cloud shared responsibility model

The provider secures the cloud: data centers, hardware, network, and the platform software it runs. You secure what you put in it: data, identities, endpoints, application code, and configuration. The split moves with the service model.

Orange = you, white = provider, half = shared.

4

Identity, encryption and keys

IAM decides who can do what: users, groups, roles, policies, MFA, federation and single sign-on, with least privilege and regular access reviews. Encryption protects data at rest and in transit, and key management protects the keys. Cloud services usually use envelope encryption: step through it.

At restStorage, database and backup encryption with managed keys; customer-managed keys for control.
In transitTLS everywhere, including between internal tiers.
Key managementA KMS or HSM, rotation, separation of key admins from data users, audit logs.
Compliance and governanceMap controls to GDPR, HIPAA, PCI DSS; continuous checks and audit trails.
5

Cloud security frameworks

Cloud Security Alliance (CSA)

  • Security Guidance: best practices across 14 domains
  • Cloud Controls Matrix (CCM): control framework for providers and customers
  • STAR registry: public record of providers' security controls and assessments

NIST

  • SP 800-145: the definition of cloud computing
  • SP 800-146: cloud technology and security considerations
  • SP 800-53: comprehensive security controls catalog
  • NCC-SRA: cloud computing security reference architecture
6

Whiteboard: harden a three-tier app

The book's whiteboard secures an e-commerce three-tier app layer by layer. Presentation: TLS, authentication (OAuth, SAML), CDN, WAF, DDoS protection, only port 443. Application: security groups and network ACLs, encryption, IAM roles, patching, bastion access, IDPS, monitoring, audits. Database: encryption, least-privilege users, access only from the app tier, hardened config, secrets in a vault, logging, separate prod and non-prod. Switch controls off and launch attacks.

7

Scenario: a public bucket with sensitive data

"An intern left a storage bucket with sensitive data open to the public. What do you do?" The book's tips: fix the immediate exposure first, then analyze the root cause, communicate, and prevent recurrence. Step through it.
