The building blocks of infrastructure

Infrastructure architecture is the foundation every application sits on. The book walks through eleven components using a banking application used by millions. Tap a component to see its job in that bank.

What an infrastructure SA does

Infrastructure SAs design and plan solutions, lead infrastructure projects, assess requirements, draw architecture roadmaps, evaluate and select technologies, run risk assessments, optimize and troubleshoot performance, and keep improving. Their life follows a cycle.

3

Large-scale migration to the cloud

In the book's reference picture, servers in the corporate data center run a replication agent that streams data to a cloud replication service and a staging area, then a cutover launches the migrated servers and volumes, with monitoring and a systems manager watching the whole time. Whiteboard a highly available hybrid architecture

  
The chapter's whiteboard: on-premises users and servers connect to a cloud region; inside a virtual network, a load balancer fronts web instances in a public subnet, app instances sit in private subnets, and the database runs active/standby in another private subnet. 6
RTO, RPO and disaster recovery

  
Every DR conversation starts with two numbers. RPO: how much data you can afford to lose (time since last good copy). RTO: how long you can be down. The book asks you to define both, replicate data across locations, and test restores regularly. A common way to discuss options is a spectrum of four DR patterns (general industry framing, not from the book). Pick one.
