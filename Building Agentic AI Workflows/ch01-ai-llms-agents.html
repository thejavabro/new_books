An Introduction to AI, LLMs, and Agents

1

A language model fills in blanks, one token at a time

Most of the "AI" in this book is a language model: a probability engine that fills in blanks in text. It doesn't see words or letters. It sees tokens, chunks of text decided once when the model is built and never changed afterwards unless the developer retrains the tokenizer. Common words are often one token; rarer names split into several.

There are two big branches of the family. Autoregressive models (GPT, Claude, Llama, Mistral, Qwen, DeepSeek) are the writers: trained to predict the next token from only the tokens before it. Autoencoding models (BERT is the classic) are the readers: trained to rebuild corrupted text, so they look both left and right. They can't chat on their own, but they're excellent at embedding and classification, which this book uses a lot.

2

Size, and the context window as short-term memory

Parameter count is the first stat to check on an unfamiliar model: the learned weights, a rough guide to capacity and to how much GPU memory you'll need. It's only one signal; data, architecture and alignment matter too.

The context window is how many tokens the model can handle in one go, input and output together. The model has no memory beyond it: start a new thread and everything is gone. Ask for more output than the window has room left for and the request is refused.

Window: 128,000 tokens (the size all four Llama 3.2 variants share). Blue = prompt, orange = room reserved for the answer.

3

Lost in the middle: positional bias

Bigger windows created a new problem. Hide one fact (the author used his own birth date) inside a pile of trivia, ask the model to repeat it, and as the pile grows the model starts missing it, even though it's right there in the prompt. Facts near the start are recalled best, the end next, and the middle worst. The formal name is positional bias. Models differ a lot: in the author's runs one model degraded past about 50k tokens while another held up much better.

Schematic: the shape follows the book's experiment (fine on short prompts, a dip in the middle on long ones); the exact numbers are illustrative.

Engineer around itDon't just stuff the prompt. Retrieve the few relevant pieces first and add only those. That's Retrieval Augmented Generation, the subject of Chapter 2.
4

Four kinds of alignment

Alignment has no strict technical definition. Broadly, it's how a model is shaped to behave the way users expect. The book boils it down to four kinds. They matter because they decide which model fits your job, and because they can get in each other's way: tuning hard for guardrails can make a model worse at following style instructions.

5

Prompt order: for accuracy and for the cache

An autoregressive model reads left to right. When it reads your first sentence it hasn't seen your last one. So put whatever contextualizes everything else first. The book's default layout: the ask and the guardrails at the top, then static documentation and examples (company info, database schemas), then the changing bits (retrieved documents, the user's question). A quick test: if understanding section A depends on section B, B goes first.

Order matters for money too. A prompt cache stores the computation for a repeated prefix. It works from the top down, and the first token that differs breaks it for everything after. Move the block that contains today's date and watch.

7

Inference knobs: temperature, top_k, top_p

At generation time you can reshape the next-token distribution. Lower temperature sharpens it (more deterministic); higher flattens it (more random). top_k keeps only the k most likely tokens. top_p keeps the smallest set whose probabilities add up past p. Try the book's example: with top_p = 0.9, "It", "The" and "We" (0.48 + 0.34 + 0.09 = 0.91) survive.

Practical defaultsThe only way to get true determinism is top_k = 1 (always pick the top token), and not every provider lets you set it. Temperature can't be exactly 0 mathematically (it divides by it), and as it grows the distribution heads toward uniform, which destroys next-token prediction. The author has yet to see a case where going above 1 helped.
8

Structured outputs and tool calls

Structured outputs nudge (not quite force) the model to answer in a JSON schema your code can parse. Tool calling extends that: you describe tools, the model answers with which tool to use and the arguments. The crucial detail: the model never runs the tool. Your system does, then hands the result back as a tool message.

# a tool is just a described function; the model only proposes calls
def get_weather(city: str) -> dict:
    """Current weather for a city."""
    ...
call = model.propose(messages, tools=[get_weather])   # {"name": "get_weather", "args": {"city": "Lisbon"}}
result = TOOLS[call.name](**call.args)                  # your code runs it
messages.append({"role": "tool", "content": result})
9

Workflows follow rails; agents choose a path

An LLM workflow is a series of LLM calls with predefined pathways, known edge cases and clear start and stop triggers. An agent is an LLM with tools and the freedom to decide what to do next. An agent setup has an environment to act on, a conversation (or one-off command), and the agent itself: the LLM and its prompt, its tools (each with an input the LLM writes and an output that comes back as a tool message), and some notion of memory, at minimum the conversation so far.

The most common agent pattern is ReAct (Reasoning + Action, 2023): reason about which tool might help, act by proposing a tool call with its input, read the observation the system returns, repeat until no more tools are needed, then report to the user. It's basically chain of thought turned into a problem-solving loop.

What agency buysNo need to foresee every pathway; the agent can solve new tasks in its own way.
What it costsIt may ignore your rules or loop into compounding failures, so you need auditing to know what it actually did.

The strongest real systems blend both: predefined workflows where the path is known, an agent picking up the slack where building fixed paths gets awkward.
