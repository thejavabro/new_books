Appendix 4: the dangers of handoffs and queues

Wait time at a work center grows with how busy it is: roughly percent busy divided by percent idle. At 50% busy the wait is 1 unit; at 90%, 9; at 99%, 99. Each handoff adds another queue. In The Phoenix Project a "thirty-minute" change needed seven handoffs at 90% busy: 63 hours in queues, so only about 0.8% of lead time was real work. Try it.

Appendix 6: the Toyota Andon cord

How can a plant work if the Andon cord is pulled more than five thousand times a day? Not every pull stops the line. The team leader has fifty seconds to fix the problem. Only if the car crosses a line on the floor before then does the whole line stop. Pull the cord, then choose whether the leader fixes it in time.

Appendix 7: COTS software in version control

Commercial off-the-shelf packages such as SAP, IBM WebSphere or Oracle WebLogic often install through point-and-click tools. To get them into version control, install on a clean server image, diff the file system, and commit the added files. Files that are the same everywhere go into a base install; files that differ by environment go into their own folders. Then installing becomes a version control operation. Configuration can move into version control too, for example by turning settings into XML.

Appendix 9: the Simian Army

After the 2011 AWS US-East outage, Netflix built Chaos Monkey to make its systems cope with failure automatically. It grew into the Simian Army. Raise the blast radius, then tap the helpers.

Appendix 10: transparent uptime

Lenny Rachitsky argues for a public health dashboard. Users can see whether a problem is theirs or global without contacting support, support costs fall, and one broadcast replaces many one-to-one messages. He argues that real-time honesty during incidents builds the trust a SaaS business depends on, and that users will soon expect it. Break something and see the page.
