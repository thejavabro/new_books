Code Search: understanding code at scale

Code Search is Google's web tool for browsing and searching its codebase. It began as a grep-type tool combined with the ranking and UI of Google's external code search, and became central once cross-references (Kythe/Grok) let people jump to definitions. Its guiding principle: answer the next question about code in a single click. Engineers use it to answer questions about code, and every other tool links into it: a Code Search URL is the canonical way to point at code at Google.

Scale shapes the design: latency

Code Search handles well over a million queries a day. One extra second per query across a million queries is about 35 engineers idle every day; the backend team is about a tenth of that. Below ~200 ms a UI feels responsive; after a second attention drifts; after ten, people switch context. Try it.

how it feels
Index latency matters tooDevelopers expect to find code they just submitted, like in an IDE. Code Search indexes incrementally: only files touched by a change are reindexed, so changes appear within seconds and the cost grows linearly.
4

Implementation: index, ranking, retrieval

Any short string appears thousands of times in a huge codebase, so ranking is essential. Ranking combines query-independent signals (how often a file is viewed, how many files reference it) and query-dependent ones (is the match a definition or just a string literal? in the file name?). Results are also diversified so one directory doesn't dominate. Search a toy codebase and toggle signals.

Under the hood: the early index used trigrams (every three-character sequence). Today Code Search indexes about 1.5 TB, serves about 200 queries per second with a median server-side latency under 50 ms, and makes new commits searchable in under 10 seconds (median). Brute-force grep at that speed would need on the order of 300,000 cores.

Selected trade-offs

Trust is everything: people use Code Search only if they believe it shows all the code and the best results first. That forces choices.
