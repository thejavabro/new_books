You probably already have fitness functions

Metrics suites such as SonarQube, linters such as ESLint, pyLint and cpplint, source checkers such as PMD: many teams already run these occasionally. Using a tool now and then does not make it a fitness function. Tick the ingredients to convert one.

Governing calls between microservices

A cycle check works because a compiler sees one codebase. Microservices may be written in different languages, live in different repositories and use different protocols, so no single tool sees them all. The trick is to standardize one thing, a log format (itself enforced by a fitness function on the shared container image), then write a few lines of script that read the logs. Rule here: domain services may only talk to the orchestrator.

for entry in read_logs(hours=24):

This is the reactive version: no runtime overhead, but violations surface up to a day late. A proactive version uses real-time monitors and catches them at once, with a little overhead. Pick by criticality: security-relevant calls deserve the proactive one.

4

Same goal, two fitness functions

A student answers questions in a TestTaker service, which sends each answer asynchronously to an AutoGrader that stores it. The requirement: never drop an answer. Option 1 instruments each container to compare messages in and out. Option 2 tags every answer with a correlation ID at the start and checks at the end that each ID resolved. Drop some messages and see which catches it.

Counting is simple and atomic, enforced through consistent infrastructure, but proves only service-level reliability. Correlation IDs prove end-to-end reliability, but someone must keep state for the whole workflow. Which is right? It depends, and there is never only one way to implement a fitness function. On the real project, the chart from this check exposed lost messages and triggered a forensic hunt.

5

DevOps fitness functions: the Simian Army

Netflix ran on someone else's cloud and worried about latency, outages and elasticity it could not control. So it built tools that cause trouble on purpose, continuously, in production. Teams had no choice but to build services that survive. Switch resilience on or off and unleash a monkey.

Holistic, continual, operationalThe Simian Army ran all the time against many parts of the system at once. When a mistyped command once took down a large chunk of a cloud region, Netflix kept running because the tools had already forced its engineers to plan for that. The original army is retired; the janitor lives on as Swabbie.
6

Enterprise architects govern capabilities, not technologies

When applications call fine-grained services all over the enterprise, implementation details leak everywhere and everything becomes brittle. Enterprise architects can instead define platforms: business capabilities behind slow-changing contracts, with fitness functions guarding what each platform must deliver. Toggle the two shapes.

7

Case study: refactoring while deploying 60 times a day

GitHub merged code with a shell script around command-line Git: correct, but it did not scale. A new library implementation was ready, but merging had worked flawlessly for years. GitHub's open source Scientist framework runs the old code (the control) and the new code (the candidate) on a sample of real requests. It randomizes their order, times both, compares results, swallows and logs candidate exceptions, publishes everything, and always returns the control's answer. Run the experiment.

# illustrative shape of an experiment
def merge(base, head)
  science "merge-engine" do |e|
    e.use { shell_merge(base, head) } # control
    e.try { lib_merge(base, head) }   # candidate
  end                                  # returns control
end

A fidelity fitness functionThe general idea: when replacing an old system, run both side by side behind a proxy that can call old, new or both, and compare until every piece of behavior has moved. The legacy code becomes the consistency test. GitHub ran its experiment for days, saw no mismatches or slow cases for a full day, then deleted the old path.
8

A checklist, not a stick

Fitness functions are not a tool for architects to torture developers from an ivory tower. Think of a pilot's or surgeon's checklist: professionals use them not because they forget their jobs, but because repetitive complex work makes people skip steps. Everyone knows not to ship a container with debug ports open; under deadline pressure someone eventually does.

Developers must understand each check so that fixing it is not a nuisance. Pick a way to document one.
