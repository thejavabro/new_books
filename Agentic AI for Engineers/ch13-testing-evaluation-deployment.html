Testing, Evaluation and Deployment

Shipping an agent is less like launching a product and more like onboarding an employee: you train, observe and coach it over time. This chapter covers what to decide before launch, how to test behaviour rather than exact outputs, how to evaluate across many dimensions, and how to roll out, watch and roll back safely.

Test behaviour ranges, not exact strings

The same prompt can yield different wording each run. An exact-match test fails on perfectly good answers and passes nothing useful. Behavioural assertions check what matters: constraints, tool use, safety. Run the refund agent ten times.

3

Eight ways it goes wrong, and how to be ready

Match each failure to its first line of defence. Tap a failure, then the defence you would reach for.

4

Prompt regression: catch drift after every change

A model upgrade throws no errors. It just behaves a little differently. Keep golden cases with expected behaviour and replay them on every change to the model, prompt or tools.

5

You cannot trust what you cannot see

Log the reasoning, not just the answer: every step, tool call and confidence under one trace ID, then let an evaluator agent score it. Open one medication-order review.

9

Shadow mode: real traffic, zero risk

Before launch, the agent reviews the same cases as physicians but its output is only logged, never shown. Weeks of agreement data tell you where it is ready and where it is not.

10

An experiment: which prompt reads clearest?

Three phrasings ran through the same two-agent pipeline (researcher → content strategist), and an LLM judge labelled each output clear or unclear with a reason. Judge the judge's calls.

11

Rolling out: containers, CI/CD, canaries, breakers

Prompts, tools and memory settings are versioned artifacts that pass the same pipeline as code. New versions reach a small slice of users first and roll back automatically when guard metrics slip.
