The Art of Prompting

With LLMs you program in words. A prompt sets the goal, the boundaries and the method all at once, and in an agent it becomes program logic that runs again and again. This chapter turns prompting into an engineering discipline: structure, technique, testing, caching and versioning.

1

Build a prompt, piece by piece

A useful formula is role + clear task + context + constraints/format + an accuracy-and-bias check + optional style. It covers the four Cs: clarity, context, constraints and care. Toggle each piece and watch the prompt and the likely output change.

2

Prompts are a cockpit, not a keyboard

A pilot does not write code mid-flight; they turn knobs. A prompt exposes the model's capabilities the same way. Turn these knobs and read the instructions they add.

3

Six years of prompting

From a user-facing curiosity to a system design layer, and now to prompts that agents write for other agents.

4

Twenty techniques, five failure modes

Each technique exists to fix a specific way models fail. Filter by the failure you are seeing, then tap a technique for when to use it and a sample.

5

Four reasoning styles side by side

Chain of thought is a straight line. Tree of thought branches, scores and prunes. ReAct loops through the outside world. Reflexion takes a second pass over its own answer. Same model, four shapes of thinking.

6

Few-shot: programming by example

Show a handful of labelled examples and the model infers the pattern in context, with no retraining. More examples cost context; biased examples produce biased output. Add or remove examples and classify a new ticket.

7

Structure in, structure out

Wrapping instructions in tags (<instructions>, <reasoning>, <reflection>, <output>) removes ambiguity about where the answer begins. Pair it with a schema validator and every hand-off in the agent loop becomes machine-checkable. Validate three model outputs against the schema.

8

In a loop, small prompt errors compound

A chatbot prompt is judged on one answer. An agent prompt sets off a chain of thoughts and actions, so a slight bias at step one can snowball. Nudge the first step off-target and watch the trajectory drift, then switch on a self-critique step.

9

Prompt caching: static first, dynamic last

System prompt, tool schemas and examples are usually identical on every request; only the user's question changes. Providers can reuse the computation for a repeated prefix and charge far less for it. But a single changed character in the prefix breaks the cache. Rearrange the blocks.

10

Prompts are production artifacts

Inline strings scattered through code drift apart and nobody can tell which version produced which output. Keep prompts in versioned files with metadata and test cases, load them at runtime, log the version on every call, and roll back like code.
