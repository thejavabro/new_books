Transformer Models and LLM Architecture

Every agent in this book has a transformer at its core. This chapter opens the box: why attention beat recurrence, how text becomes tokens and vectors, what each block of the architecture does, and how scale and prompting turned a next-word predictor into a reasoning engine.

One word at a time vs. all at once

A recurrent network reads like a person with a short memory: one word, update the memory, next word. By the end, the first word has been rewritten dozens of times and fades. A transformer looks at every word at once and lets each one reach any other directly. Run both on the same sentence.

How machines read: tokens

Whole words make the vocabulary explode and leave rare words untrained. Single characters make sequences very long. Subword tokenizers (such as BPE) split text into frequent chunks: common words stay whole, rare ones break into reusable parts. Embeddings: a map of meaning

Each token becomes a long vector of numbers. No single number means "animal" or "plural"; read together they act like coordinates, so related words land near each other. This is a two-dimensional cartoon of a space with hundreds of dimensions. Tap a word to see its neighbours, or run the famous analogy.

5

Self-attention: which words matter to this one?

For every token, attention asks which other tokens help explain it, and mixes in their information by weight. Multi-head attention runs several of these in parallel, each tuned to a different kind of relation, like a team of analysts pooling notes. Tap a word, then switch heads.

6

Positional encoding: putting order back

Because a transformer sees all words at once, it has no built-in sense of order. Without help, "the cat chased the mouse" and "the mouse chased the cat" look like the same bag of words. A position vector is added to each embedding so meaning and place travel together.

7

Inside the block, and three ways to stack it

The encoder is the reader: it builds a context-rich representation of the input. The decoder is the writer: masked self-attention so it only sees what it has written, plus cross-attention back to the encoder. Tap a component; then compare the three families.

8

How an LLM gets its "language brain"

Pretraining reads enormous amounts of text and makes the model guess hidden or upcoming words. Later stages teach it to follow instructions and to prefer answers people rank higher. Try each objective.

9

The context window is the model's working memory

Everything the model considers at once must fit in the window: system prompt, conversation history, tool results, its own reasoning and the answer. Shrink the window on this 40-turn support chat and watch the original request fall off the edge.

10

Scale: when bigger starts to look different

Grow parameters, data and compute together and quality improves along a smooth power-law curve. At some sizes, abilities become useful enough to notice: step-by-step reasoning, knowing when to call a tool, using long context. Recent work suggests many of these jumps are gradual improvements crossing a usefulness threshold rather than sudden magic.

11

Prompting turned prediction into cognition

The architecture barely changed; how we talk to it did. A few prompt patterns unlocked reasoning, tool use and self-correction from the same pretrained model. Watch one model answer the same question under each pattern.

12

The LLM is the brain, not the whole body

An agent wraps the model with tools, memory and a control loop. Each lap the model sees the user request plus observations from tools and past steps. Step a scheduling agent through observe, reflect, act.

13

Limits you must design around

LLMs hallucinate, forget beyond their window, take time per token and cost money per call. Agents multiply all of that, because one agent turn can be several model calls. Estimate a single task.
