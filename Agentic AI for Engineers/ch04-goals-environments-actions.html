Agentic AI Fundamentals

An agent starts with intent: you tell it what to achieve, not how. This chapter assembles the minimum parts of an agentic system (goals, tasks, agents, tools, memory, coordination) and the engineering that keeps them reliable: tool errors, loops, conflicting subgoals, randomness and guardrails.

The six parts of an agentic system

Goals set the destination and tasks map the route. Agents are the workers that walk it, using tools to touch outside systems and memory to keep context. Coordination stops several agents from tripping over each other. Tap a part.

2

Goals come in sizes, and they move

A task is one rung ("summarize this paragraph"). An objective is a defined outcome ("extract the financial risks from this loan agreement"). A mission is open-ended ("support the finance team in reviewing loans daily"). Expand the retail-support mission into its tree, then watch an evolving goal change shape.

3

Reactive or proactive?

A reactive agent waits to be asked. A proactive agent watches its environment and acts on triggers. The catch: tune the trigger too sensitive and people drown in alerts; too dull and real problems slip by. Run a week of events.

4

Fully or partially observable?

In chess every piece is visible. In a crowded airport with poor signs you see only what is near you and must guess the rest. Most agent environments are the second kind: documents, APIs and users show only part of the picture. Toggle the fog and help the agent find its gate.

5

Tools are hands and eyes

An LLM alone can only advise. With tools it can search, query, compute and read files. When several tools could fit, it matches your intent to each tool's description, checks it has the arguments, and prefers the most specific one. That makes the description the most important line you write. Ask a question, then flip the descriptions from vague to clear.

6

When tools fail

Networks time out, tokens expire, IDs do not exist. The difference between a frustrating agent and a reliable one is the recovery path. The order of preference is retry, fall back, degrade, then ask a person. Throw a failure at the agent.

7

Four ways to chain tools

Real tasks need several tools. Sequential chains pass each output to the next step. Parallel calls gather independent data at once and must survive partial failure. Conditional chains branch on an intermediate result. Iterative loops repeat until done, with a ceiling. Play each.

"Cheapest direct flight": a hidden conflict

The cheapest flight has a stop; the only direct one costs more. A good agent spots the clash early and resolves it in the open instead of quietly dropping one goal. Try each strategy.

10

Memory: the invisible thread

Without memory every message starts from zero. Tell a travel agent you are allergic to seafood, then come back six months later. Switch memory types on and off and see what it can still do.

11

Five layers of reasoning

No single prompt or framework covers all of an agent's thinking. Production systems engineer each layer on purpose. Tap a layer.

12

Conductor, relay or hybrid

A loan-review mission split into three agents (dates, financial risks, summary): one agent, one subgoal. How they hand work around matters. Too much reporting back and everything waits on the coordinator; too little and agents drift out of sync.

13

Stochastic brains: the temperature dial

An LLM does not know one right next word; it holds a probability for every word and samples. Temperature reshapes that distribution. Low is consistent (good for support replies), high is varied (good for brainstorming). Sample a few times.

14

Calibrate autonomy to risk

Automation is not on/off. Mix levels inside one product: notify only, recommend and confirm, act then notify, or act silently for proven, low-stakes work. Add decision points, an LLM judge, monitoring and templates where they help. Pick a level for each action.

What, not howAgents get objectives and choose the path; engineers design the scaffolding.
Goal treesMissions → objectives → tasks, replanned as the agent learns more.
Proactive needs tuningBalance sensitivity against noise; evaluate cheap filters before costly reasoning.
Tools need great descriptionsSay when to use, when not to, and what it returns. Return structured errors.
Recover gracefullyRetry → fall back → degrade → ask the user. Cap loops; track progress.
Surface conflictsPrioritise, relax, balance or ask. Never silently drop a goal.
Memory comes in kindsWorking, long-term, episodic, semantic, procedural, tool quirks.
Guardrails are infrastructureRate limits, permissions, budgets, approval gates and audit logs from day one.
