Collaborative Agents

Hard problems are solved by teams, and agents are no different. Multi-agent systems combine specialisation with coordination, and human–AI teaming combines the agent's speed and scale with human judgment and context. This chapter covers eight team shapes, how agents talk, where teams go wrong, and how to test them.

Scouts, assistants, coordinators, swarms

Collaboration takes different forms in different industries. In every case the strength comes from many specialised agents and humans working together, not one super-agent.

Eight ways to organise an agent team

Each shape mirrors a human way of organising work. Pick one, press run, and watch how work flows.

3

Which shape fits the problem?

Start with a sequential pipeline and add complexity only when the problem demands it. Describe your problem.

4

Voting: paying for confidence

If each agent is right more often than not and their mistakes are independent, a majority vote is right more often than any one of them. Each extra voter costs another call. Correlated mistakes (same model, same prompt) erase much of the gain.

5

Auction: let work find the specialist

Each agent bids its confidence and expected quality for a task; the best combined score wins. No central router needs to know everyone's strengths, but it relies on honest self-assessment.

6

How agents talk, and who owns which tool

Agents exchange structured messages, read and write shared memory, or post to a blackboard. They also need clear tool ownership: three agents hammering the same API is how you meet a rate limit. Toggle the switchboard.

7

Sequential or parallel?

Sequential is easy to trace. Parallel is faster but two agents can collide on the same record. Mix them: parallel where tasks are independent, sequential where they depend on each other or the stakes are high.

8

Humans on the team: in, on, or beside the loop

Three ways to put a person on the team. Pick a mode and play the same week of work.

9

Where teams go wrong

Teams add new failure modes: agents disagree, the manager becomes a bottleneck, one agent's mistake flows downstream, and a compromised agent poisons the rest. Pick one.

10

Shared memory meets the context window

"Shared memory" is not free: every model has a finite context window. Five agents writing detailed analysis can overflow it. Choose a memory pattern and see what the final agent has to read.

11

Testing a team, not just its members

An agent that passes alone can fail in company, and bugs hide in the gaps between agents. Tap each layer of the test strategy.

12

When to add another agent

More agents means more cost, latency and coordination. Tick the signals you actually see.
