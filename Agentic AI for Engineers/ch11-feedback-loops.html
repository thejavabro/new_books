Engineering Agent Feedback Loops

Without feedback an agent is a script with better branding. It repeats the same mistake politely forever. Feedback loops let it notice, adjust and earn more autonomy over time. This chapter covers where feedback comes from, how to wire it in, how it goes wrong, and how to tell whether the loop is actually working.

1

The scheduler that never learned

"Push my meeting with Alex to after lunch." A scheduler that only understands exact times answers with the same error forever. Give it a feedback loop and run the same week of requests.

2

Autonomy is earned, one reviewed decision at a time

Early on every action is reviewed (human in the loop). As corrections and confirmations pile up, control shifts to humans on the loop, and finally to trusted autonomy with audits. Slide through the agent's track record.

3

Four kinds of feedback

Some loops act in the moment, some carry lessons for weeks, some come from outside. Strong systems combine them. Tap each.

4

Second thoughts, built in

A reflection step makes the agent review its own draft as an impartial reviewer, list the weaknesses, and revise before anyone sees it. It is the agent re-reading its email before pressing send. Play the three passes.

5

Let the environment be the reviewer

Tests pass or fail, APIs time out, cases reopen, clinicians edit drafts. These outcome signals are honest because they track what matters. Turn them into rewards, smooth them, and let the planner prefer the tool that actually works. Watch two tools over 40 calls.

6

A thumbs-down is only useful if you know what caused it

Log every run with its prompt version, tools, retrieved documents and temperature, then join user feedback to those records. Group the same 12 sessions different ways and see which factor the complaints follow.

7

Correct now, remember later, change globally

Invalid JSON gets fixed in milliseconds. A student who always stumbles on fractions gets remembered. A complaint that hundreds of users share changes the base prompt. Slide how many users raised "too formal" and see where the fix belongs.

8

One research assistant, six feedback layers

A medical-trial summariser drafts, reflects, gets a peer review, a human rating, stored lessons and periodic red-teaming. Each layer catches a different class of error. Note step 5: the model does not change; its instructions do, after a human approves.

9

Feedback can drift, overload, leak and be poisoned

A group of users keeps rating sarcastic replies as "helpful". Without safeguards the agent's tone slides toward snark. Add the defences and replay the month.

10

Pick mechanisms by failure mode and budget

Each mechanism trades signal quality, speed, cost and nuance. Pick the failure you fear most, or the constraint you live under, and see which layers of the stack light up.

11

Is the loop actually working?

Feedback can flow in while nothing flows out. Treat the loop as a system with its own health metrics. Drag the values and read the scorecard.
