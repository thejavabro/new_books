Java SE API Tips: Collections to Serialization

Pick the right collection and size it, know when streams beat loops (and when they don't), and make serialization move only what it must.

1

Choose the collection for the access pattern

The biggest collection win is algorithmic: a LinkedList or ArrayList searched linearly where a HashMap lookup was needed costs far more than any tuning gains back. Then consider synchronization. Vector and Hashtable lock on every call; ArrayList and HashMap don't; ConcurrentHashMap and the copy-on-write and concurrent-queue classes handle sharing with little or no locking.

Uncontended locks are cheap; contended ones aren'tA synchronized collection used by one thread costs only a little. It is not worth agonizing over that case; pick the unsynchronized class in new code. Under real contention the choice matters a lot: use the concurrent classes. When unsure whether something will be shared, being thread-safe is the safer default.
2

Sizing collections

Array-backed collections (ArrayList, HashMap's table, StringBuilder, ByteArrayOutputStream) start small and grow by allocating a bigger array and copying everything across. If you know roughly how many elements are coming, say so up front. Oversizing has a cost too: empty slots are heap the GC has to carry, and a default-sized map for two entries is mostly empty.

Memory efficiency varies a lot by class: each HashMap entry is a separate node object; LinkedList adds a node per element; boxing primitives adds an object per value. For millions of small entries, the overhead can exceed the data. Empty collections are cheap in JDK 8+ (the backing array is created on first add).

3

Lambdas vs. anonymous classes

A lambda looks like shorthand for an anonymous inner class, but it isn't compiled that way. An anonymous class is a real class file, loaded at startup. A lambda becomes a private static (or instance) method plus a call site linked at first use through invokedynamic; a non-capturing lambda is even reused as a single instance. In steady state both perform about the same, so choose by readability. Where class loading counts (startup with thousands of callbacks), lambdas come out slightly ahead.

// one more class to load: Pricer$1.class
list.sort(new Comparator<Quote>() {
  public int compare(Quote a, Quote b) {
    return a.price().compareTo(b.price());
  }
});
// a private method + an invokedynamic call site
list.sort((a, b) -> a.price().compareTo(b.price()));
// or
list.sort(Comparator.comparing(Quote::price));
4

Streams are lazy

Intermediate operations like filter() and map() do nothing on their own; they just link stages together. Only the terminal operation pulls elements, one at a time, through the whole chain, and a short-circuiting terminal like findFirst() stops as soon as it has an answer. Step through a search for the first symbol that passes four filters:

symbols.stream()
  .filter(s -> s.charAt(0) != 'A')
  .filter(s -> s.charAt(1) != 'A')
  .filter(s -> s.charAt(2) != 'A')
  .filter(s -> s.charAt(3) != 'A')
  .findFirst();

Even when every element is processed, one filter is a little faster than an iterator loop. Many chained filters add per-stage overhead: put the most selective test first, or combine conditions. Parallel streams are covered in chapter 9.

5

Object serialization

Java serialization writes every non-transient field reflectively, plus class descriptions, so its cost is mostly about how much data you send. Four levers:

class History implements Serializable {
  private transient SortedMap<Date,Price> prices;   // big; rebuilt on demand
  private transient BigDecimal stdDev;              // derived: recompute lazily
  private byte[] zipped;                              // what actually travels
  private void writeObject(ObjectOutputStream out) throws IOException {
    if (zipped == null) zipped = zip(prices);
    out.defaultWriteObject();
  }
  private void readObject(ObjectInputStream in) throws IOException, ClassNotFoundException {
    in.defaultReadObject();                            // unzip later, only if asked
  }
}
