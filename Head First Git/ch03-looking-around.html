1

Reading the history with git log

Brigitte is job hunting. She keeps her resume in a repository and commits each edit her friends suggest, on three branches: master, add-skills and edit-per-scotty. Commits tell you that things changed; git log lets you read the story back.

Plain git log is verbose: full ID, author, date and full message for each commit, newest first, in a pager (press q to leave). Flags trim and enrich it. Toggle them and compare:

The combo you'll type mostgit log --oneline --graph --all: one line per commit, ASCII lines for the parent links, and every branch rather than only the one you are on. Order of flags doesn't matter. (Chapter 8 shows how to shorten it with an alias.)
2

How git log decides what to show

Without --all, git log starts at the commit HEAD points to, prints it, follows its parent, prints that, and keeps going until it reaches a commit with no parent. Commits that are only reachable from other branches never come up. Pick the branch you are standing on:

git log, git diff, git status and plain git branch are all safe: they only read. Run them as often as you like.

3

Anatomy of a diff

Commits record snapshots; git diff computes what differs between two of them, or between any two of the three areas. Its output is dense, so take it a line at a time. Tap a line:

Git doesn't print whole files. It shows only the regions that changed, each a hunk, with a few unchanged lines around it for context. A small edit gives one hunk; edits scattered through a long file give several.

4

Which two things is diff comparing?

Every diff compares exactly two sets of content. The first is labelled a/ and its lines appear with −; the second is b/ and its lines appear with +. What changes between the variants is which two things go in those slots.

"Nothing to show" isn't "nothing changed"After git add, plain git diff goes quiet: the folder now matches the index. The changes are still uncommitted; look with --cached (synonym: --staged).
Order mattersPut the thing you are merging from, or the newer commit, second, so its changes show as additions. Swap the arguments and every + becomes a −.
5

Comparing two branches is comparing two tips

Naming a branch in git diff means "the commit at its tip". Because each tip contains all the history behind it, comparing tips compares everything each branch did since they split. The shared history from master cancels out.

6

Easier on the eyes: word diffs, one file, new files

Line-based diffs are clumsy when one word in a long line changed: the whole line shows as removed and re-added. --word-diff marks just the words. You can also narrow any diff to one file by naming it at the end: git diff --cached resume.md.

Prefer pictures? git difftool hands the comparison to a visual tool such as the one in Visual Studio Code, which shows the two versions side by side.
