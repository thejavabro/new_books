1

What a pattern actually is

After a whole book of patterns, the formal definition is short: a pattern is a solution to a problem in a context. The context is the recurring situation; the problem is the goal plus the constraints in that context; the solution is a general design anyone can apply to resolve them. The tension between goal and constraints is often called the forces. If you only have a solution to a one-off problem, it isn't a pattern; it has to recur. Try it on an example.

Most catalogs, starting with the Gang of Four's Design Patterns (Gamma, Helm, Johnson, Vlissides, 1995), describe each pattern with sections like the ones above. And a candidate earns the name only after it has been applied successfully in at least three real-world solutions: the Rule of Three.

2

Sorting patterns into categories

The GoF group patterns by purpose. Creational patterns are about how objects get instantiated, decoupling clients from the objects they create. Structural patterns compose classes or objects into larger structures. Behavioral patterns are about how classes and objects interact and distribute responsibility. Tap a pattern, then tap the bin it belongs in.

Patterns to place
A second axis: class or objectClass patterns describe relationships fixed at compile time through inheritance: Template Method, Factory Method, class Adapter, Interpreter. Object patterns describe relationships between objects, mostly via composition, which can change at runtime: everything else. Categories are just a tool for thinking and comparing; plenty of patterns could argue for more than one bin.

Use the vocabulary

Patterns pay off most as a shared language. Use them in design meetings ("this is a State machine; each status is a class"), with other developers, in architecture documentation ("the parser is an Interpreter"), in code comments and naming (ReportExporterFactory, PaymentGatewayAdapter), and in study groups. A name says more than a paragraph.

Being a pattern writerDo your homework on existing patterns, reflect on what has recurred in your own work, write it down in a form others can follow, then have others try it and refine it, again and again. Most "new" patterns turn out to be variations of known ones.
6

Anti-patterns

A pattern tells you how to get from a problem to a good solution. An anti-pattern tells you how you get from a problem to a bad one: why the bad solution is attractive, why it hurts in the long run, and which good patterns to reach for instead. Open the book's example.

7

Beyond design patterns

The pattern idea reaches far beyond object design. Architectural patterns (client-server, layered, event-driven), application patterns (MVC for web apps), domain-specific patterns, business process patterns, organizational patterns (how teams are structured) and user interface patterns all use the same "solution to a problem in a context" format.
