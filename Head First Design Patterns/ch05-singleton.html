One-of-a-Kind Objects

Some things should exist exactly once. Singleton guarantees one instance with a global access point, and this chapter shows how easily two threads can quietly break that guarantee.

1

Objects there should be only one of

Thread pools, caches, registry settings, a logger, the driver for a single piece of hardware. Two of them would mean inconsistent settings, wasted resources or conflicting commands. A global variable gives one shared object, but it gets created at startup whether you need it or not, and nothing stops someone calling new again. Singleton is the textbook-sized answer: about the simplest class diagram in the catalog, with surprisingly subtle details.

Dissecting the classic implementation

Three moves: hide the constructor, keep the one instance in a static field, and hand it out through a static method that creates it the first time it's asked for (lazy instantiation). Tap the lines to see what each one does.
