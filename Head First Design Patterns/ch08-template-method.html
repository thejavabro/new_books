Encapsulating Algorithms

When several classes run the same steps with small differences, put the skeleton of the algorithm in a base class and let subclasses fill in just the steps that differ.

1

Same recipe, small differences

A CI server builds projects in several languages. A Node build and a Java build look different on the surface, but line them up and they follow the same algorithm: check out the code, install dependencies, compile, run tests, package. Some steps are identical; others differ only in the command. Duplicating the whole sequence in each class means every fix to the process is made several times.

2

Putting the skeleton in one place

The base class gets a final method, build(), that calls the steps in order. Steps that are the same for everyone are implemented in the base class. Steps that vary are abstract, and subclasses supply them. A hook is a step with a default (often empty) implementation that subclasses may override. Pick a subclass, choose whether it overrides the hook, and run.

abstract class Build {
  final void build() {                    // the template method; final so subclasses can't reorder it
    checkout(); install(); compile(); test(); archive();
    if (shouldDeploy()) deploy();          // hook decides an optional step
  }
  void checkout() { git("checkout"); }      // same for everyone
  abstract void install();                // subclasses must supply
  abstract void compile();
  abstract void test();
  void archive() { store("dist/"); }
  boolean shouldDeploy() { return false; }  // hook: default, optional override
  void deploy() { push("prod"); }
}
The Template Method Pattern

Defines the skeleton of an algorithm in a method, deferring some steps to subclasses. Template Method lets subclasses redefine certain steps of an algorithm without changing the algorithm's structure.

3

Don't call us, we'll call you

Design principleThe Hollywood Principle: Don't call us, we'll call you.

Low-level components can hook themselves into a system, but the high-level component decides when and how they're used. That prevents "dependency rot", where high-level code depends on low-level code that depends back on high-level code. In Template Method, NodeBuild never calls build()'s steps itself; the base class calls it. Compare the two shapes.

4

Template Method in the wild: sorting

Java's Arrays.sort() is a static method that runs the sorting algorithm and calls compareTo() on your objects for the one step it can't know: how two elements compare. It isn't a textbook Template Method (no subclassing; your class implements Comparable instead), but the spirit is the same: the framework owns the algorithm, you fill in a step. Choose how planets compare and sort them.
