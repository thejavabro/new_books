Four ways to put GenAI in a product

Photo erasers, suggested email replies, meeting summaries, coding assistants, ticket helpers, marketing copy: products everywhere now carry GenAI features. Underneath, there are four ways to get the content you need from a model.

2

Calling models from code

Web chat is convenient, but software needs APIs. You get an API key from a provider (OpenAI, Google, Anthropic, Groq for open models…) and send it with each request; billing is by tokens in plus tokens out. A library such as LangChain wraps all providers in one interface. The pieces snap together into a chain: a prompt template with a slot for the part that changes, the model, and an output parser that always hands back a plain string.

prompt = PromptTemplate.from_template(
    "Classify this restaurant review as Positive, Negative or Mixed "
    "and list the aspects discussed.\n**Review**: {review_text}")
chain = prompt | llm | StrOutputParser()
chain.invoke({"review_text": "A real gem of Cantonese cooking…"})

Even with a parser, two models format answers differently (one terse, one chatty), and the same model varies run to run. Software wants structured outputs. DSPy asks you for a signature instead of prompt text: inputs on the left of the arrow, outputs on the right. It writes the prompt, calls any provider (or a local model via Ollama or Hugging Face) and returns an object with those fields. Edit the signature:

Changing the model itself

  
Classic transfer learning fine-tunes a foundational model on a small dataset. With GenAI that turned out to be needed far less than expected, thanks to prompting and agents. And retraining all weights on a small dataset risks catastrophic forgetting: the model loses much of what it knew. So customization usually takes one of three lighter forms. Pick one to see which weights change.

Teaching in the prompt instead

  
Instructions alone are zero-shot: it works only if the model trained on something similar. Three techniques push a model beyond its training, and also make results more consistent, without touching any weights.

  

    

    

  






  
6
One call is rarely enough

  
One giant prompt turned a grocery flyer into a week of recipes and a shopping list, but the stir-fry never cooked its chicken, and nobody could tell whether every ingredient reached the list. A single call gives you no chance to inspect intermediate results or use trusted data (a nutrition database beats invented calorie counts). Prompt chaining breaks the job into steps whose outputs feed the next, each with a structured format you can validate.
