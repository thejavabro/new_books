RAG Agents

Retrieval-augmented generation grounds a model in documents it never saw during training. The trick is to search by meaning, not by keyword.

1

RAG = an indexing pipeline + a generation pipeline

A very common agent answers questions from a small, trusted set of documents: an insurance policy, vetted medical texts, a company wiki. Retrieval-augmented generation (introduced by Facebook researchers) needs two pipelines. Indexing runs ahead of time; generation runs for every question.

2

Embeddings put meaning on a map

Keyword search matches words. RAG matches embeddings: vectors placed so that texts with similar meaning sit close together. "The art gallery is open now" lands near "The museum is open today"; "The zoo closes at 5" sits farther away, and the distance reflects how much the meaning changes. Because they are vectors, you can measure distances, cluster and reduce dimensions. Real embeddings have hundreds of dimensions; this map is a hand-drawn 2D sketch. Pick a query.

3

How an embedding model learns: skipgrams

The earliest embedding model, Word2Vec, learns by predicting which words can appear near a given word. The network's narrow middle layer must squeeze in just enough about the input to make that prediction, and that compact layer is the embedding; the rest is thrown away afterward. Training pairs come free from books: every word within n positions of the target is a positive example (a skipgram). Negatives are words drawn at random from the vocabulary, which is why words like "the" and "of" end up appearing on both sides and matter little.

In practice you use a pretrained embedding model (such as the small open MiniLM, or models hosted by cloud providers) and compare candidates on Hugging Face's MTEB leaderboard against your memory and price budget.

4

Indexing: chunk, embed, store

The book indexes an 1878 geology textbook from Project Gutenberg: download the HTML, split it into paragraphs (one chunk per <p> tag), embed each chunk, and store vectors with their text and metadata in a vector store (Chroma, persisted on disk in SQLite). Alternatives range from Pinecone and Faiss to cloud services and vector columns in Postgres, DuckDB, BigQuery or Snowflake; LangChain lets you swap them. Retrieve, augment, generate

For each question, find the closest chunks, paste them into a tested prompt template (the book pulls a standard RAG prompt from LangChain Hub), and let the model answer from that context. Step through "What rocks do you find in the Upper Lias?"

rag_chain = (
    {"context": retriever | join_docs, "question": RunnablePassthrough()}
    | rag_prompt | llm | StrOutputParser())
rag_chain.invoke("What rocks do you find in the Upper Lias?")
6

Three upgrades to basic RAG

1. Hypothetical answer. A textbook is not an FAQ; the answer may sit in sentences that look nothing like the question. So first ask the LLM to answer from memory (wrong details are fine, it is the shape of the answer that matters), then search with that hypothetical answer. It costs a second LLM call; the gain is small but consistent.

2. Reranking. Nearest is not the same as relevant. Cross-encoders (rerankers) judge relevance well but are too slow to run on everything, so retrieve 10 cheaply and rerank down to 3.

      7

      Do we still need to chunk?

      Chunking used to be forced: context windows held about a thousand tokens, and models favored the start (primacy bias) and end (recency bias) of their input. A 2023 Stanford study found accuracy dipping for facts in the middle. By 2024, Anthropic showed near-identical recall across a 200,000-token window, so for some uses you can skip chunking. But tokens are billed, so long prompts cost more.
