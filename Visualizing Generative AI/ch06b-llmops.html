Operations for a nondeterministic product

Shipping is not the finish line. LLMOps is the set of practices, tools and workflows for running LLM applications in production, a specialization of MLOps. MLOps already brings faster deployment, models that stay good through monitoring and retraining, scale, reproducibility and collaboration. LLMs add their own twists. Flip between them.

    Track runs, and mock everything you are not testing

    Experiment tracking saves everything about each run: prompts, code, environment and data versions (including the RAG index or SQL source), parameters, metrics and hardware. Tools such as W&B Weave and MLflow log runs, chart them and store versioned models. But comparing runs is hard when the model and live tools answer differently every time. The book's fix: record a tool's response once and patch the call so every experiment sees the same data.

    @patch("weather_agent.fetch_forecast", Mock(return_value=saved_chicago))
def test_rain_question():
    reply = weather_agent.ask("Is it raining in Chicago?")
    assert "not raining" in reply     # saved data has 0 mm of rain

    Simulated scores, my own illustration. The same idea applies to any step, including the LLM call itself: isolate the one change you are testing.

    4

    Evaluate the model, the people, and the system

    Accuracy tests are necessary, not sufficient. The book asks for three layers, measured separately and together: capability (does it work, in every language and for every user?), human interaction (trust, persuasion, anthropomorphism, skill loss) and systemic impact (inequality, misinformation, jobs, resources). Its example is a tax-filing assistant; pick a metric and see where it sits.

    Tap a metric.

    The evaluation gapMost evaluation stops at the model. Gaps to close: alignment with all stakeholders (not just users), trust metrics, long-term effects of human-like design, misinformation risk, and equitable access. Many of these only show up in real use, so combine user studies, adversarial testing and expert review, and keep monitoring. Product teams alone have mixed incentives; governance needs legal, ethics, HCI and policy voices plus a way to seek redress.

    Watermarking: a fingerprint in the sampling

    Detectors that guess from style are unreliable. SynthID-Text (Nature, 2024) instead lets a secret key steer the random choices during sampling, without changing quality; a checker with the key measures how well a text fits. The toy below uses a simpler "green list" scheme to show the idea: the key marks half the words green, and the generator prefers green ones when several are plausible.

    7

    Five rails around the model

    NVIDIA's open-source NeMo Guardrails sits between the app and the LLM. Input rails reject or rewrite what goes in (jailbreak checks, masking personal data); dialog rails choose between an action, an LLM call or a canned reply; retrieval rails drop or mask RAG chunks; execution rails guard tool inputs and outputs; output rails reject or edit the answer (fact and hallucination self-checks, moderation). Send a message through.

    rails:
  input:  { flows: [check jailbreak, mask sensitive data on input] }
  output: { flows: [self check facts, self check hallucination] }
