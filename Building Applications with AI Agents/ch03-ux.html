User Experience Design for Agentic Systems

An agent is only as useful as people find it. Which interface fits the task, how much the agent remembers, how it signals what it can and cannot do, and how it earns trust.

People judge the agent by the experience

Capable agents still fail if people cannot tell what they do, lose their place, or stop trusting them. The chapter covers four threads: which modality to use, how context is kept over time, how the agent communicates capabilities and uncertainty, and how it earns trust.

3

Voice: fast to say, slow to take in

Latency used to sink voice agents; newer speech-to-speech models respond fast enough, handle mid-sentence corrections and can call tools. Two design facts remain. People speak at about 150 to 180 words a minute but read 250 to 300 and skim beyond 500, so long answers belong on screen. And the agent must stop talking the moment the user does.

Barge-in: interrupting the agent

Press "Agent speaks", then interrupt it.

A good voice server cancels the remaining audio as soon as it detects the user's voice, and remembers how much was actually heard.

4

Generative UI: the agent draws the interface

Graphical interfaces reduce cognitive load: dashboards show pending tasks and errors at a glance; AI IDEs show diffs you can accept. A newer idea is the generative UI, where the agent builds a context-specific interface on demand, mixing language flexibility with buttons you can see.

"Find me a train to Boston tomorrow morning"

The old challenges still apply: do not overload the screen, and balance automation with control. Users should see what the agent did and be able to override it.

5

One journey, several modalities

The most compelling experiences flow across modalities: start by voice while driving, continue by text walking into a meeting, review a dashboard at a desk. That only works if state and context follow the user. Tap through the journey.

6

The autonomy slider

Different users, tasks and moments need different amounts of agent independence. The book borrows the idea from AI code editors: manual, ask (the agent suggests, you approve each change), agent (it acts on its own within limits). The same three levels can coexist in one product.

drag the slider
Five design rules for the sliderShow the levels clearly. Make switching effortless. Keep behavior predictable at each level. Say what users gain and risk by moving up. Suggest more autonomy as the agent proves reliable. The slider is a trust-building mechanism, not just a setting.
7

Synchronous, asynchronous, and not being annoying

Synchronous experiences (a chat, a voice call) need immediacy, brevity and quick recovery from errors. Asynchronous ones (an agent working on a report overnight) need clear status, persistent context and well-set expectations. Both need judgment about when to interrupt. Proactive help that is irrelevant becomes noise. Set the bar below.

8

Remembering, so users do not repeat themselves

Context retention looks technical but is really UX: it decides whether the agent feels like an attentive collaborator or a tool that makes you repeat yourself. Keep session state outside process memory once you have many users, give sessions clear boundaries, validate stored data, and have fallbacks when state is lost. Personalization builds on top.

9

Say what you can do, and how sure you are

Text agents suffer from poor discoverability: a blank box hides what is possible. Fix it with onboarding, suggested prompts, capability cards, or the agent simply saying "I can cancel orders, check delivery status or update your account". And since outputs are probabilistic, signal confidence through words, visual cues or by offering suggestions instead of firm answers. Slide the agent's confidence.

10

Ask for guidance, fail gracefully

Ambiguous requests deserve one focused question, with the reason for asking, not an interrogation. Failure is inevitable, so design for it: acknowledge the problem, explain briefly, suggest next steps, keep the work done so far, apologize like a person, and learn from it. 11

Trust is gained in drops and lost in buckets

The chapter's closing theme in one line. Transparency (clear capabilities and limits, without drowning users in detail), predictability (consistent behavior), and reliability (handling edge cases, resilience, meeting expectations) all feed it. Play a week of interactions and watch the meter.
