Knowledge and Memory

A model forgets everything between calls. Memory is everything we do to put the right facts back into the window at the right time, without overflowing it.

1

Memory is what you put back in the window

A model remembers nothing between calls. Chapter 5 framed context engineering as assembling the best inputs into the window; memory is how we find those inputs. The simplest memory is the window itself. Windows are large now (hundreds of thousands of tokens, up to a million for some models) but they are still a finite, costly resource. A rolling window keeps the newest turns that fit and drops the oldest.

2

Keyword search: precise, but literal

Full-text search is mature and fast. Documents are indexed by their words and ranked with BM25, which rewards rare terms that appear often in a short document. It nails exact terms such as product codes or error IDs, but it misses paraphrases. Try a query. Scores below are computed live with real BM25 over five past support notes.

3

Embeddings: search by meaning

Embeddings turn text into vectors so that similar meanings land close together. A vector store (FAISS, Annoy and similar) finds the nearest neighbors of the query's vector. Now "get my money back" lands next to the refund note even though no word matches. Click a query to place it on this (two-dimensional, simplified) map.

4

Retrieval-augmented generation

RAG combines the two halves: retrieve relevant chunks from a corpus, then generate an answer grounded in them. Indexing happens once, retrieval on every query.

Semantic experience memoryA knowledge base still leaves the agent starting each session blank, and long tasks slide out of the window. The fix: embed every user input (and useful outcomes) as it happens, store them, and retrieve the relevant past interactions into future prompts. The same machinery as RAG, pointed at the agent's own history.
5

GraphRAG: connecting the dots

Baseline RAG retrieves similar chunks. It struggles when the answer is spread across documents or needs a summary of a whole collection. GraphRAG extracts entities and relationships into a knowledge graph, then retrieves subgraphs, enabling multihop reasoning. Ask a question and watch the hops.

Building a knowledge graph in seven steps

Open source tooling makes a first GraphRAG pipeline a few command-line calls; for production the book points to a graph database such as Neo4j, populated with deduplicating Cypher statements and queried with traversals like shortest path.

6

Dynamic knowledge graphs: promise and peril

A dynamic graph updates in real time and adapts as the agent learns. That is powerful, and harder to run than a static one.

7

Why not just stuff everything in?

Million-token windows tempt you to skip retrieval entirely. The book's caution: processing huge inputs every call costs compute, money and latency, and can cancel out the simplicity gain. Compare for your corpus size.

8

Note-taking as working memory

The context assembled for one request is effectively its working memory. A research technique, self-notes, has the model write notes on parts of the context before it sees the question, like filling the margins of a book, then interleave those notes when answering. Compare the three flows.
