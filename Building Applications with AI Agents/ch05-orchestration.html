Orchestration

Orchestration decides which tool to call, in what order, with which arguments, and what to do when a step fails. It is the agent's control loop.

Six ways an agent can think

Orchestration starts with the agent's overall pattern. The book lists six archetypes, from instant reflexes to hours-long research. Pick one to replay how it would handle the same kind of question, and compare speed and cost.

2

Choosing the tool: standard, semantic, hierarchical

Tool selection is the foundation for any planning. Standard selection hands every tool to the model: simple, but it scales poorly. Semantic selection embeds tool descriptions once, then retrieves the few most similar to the query: very scalable and fast, the book's recommended default, though similar descriptions can collide. Hierarchical selection picks a group first, then a tool within it: scalable and often more accurate, but slower because the calls are sequential.

3

Filling in the arguments

Once a tool is chosen, the model parametrizes it: the tool's schema and everything known so far go into the prompt, and the model fills each argument with the right type. Then execution runs, and the result returns to context. Missing information should trigger a question, not a guess.


  






  
4
Single, parallel, chain, graph

  
Most chatbots today do a single tool call without planning. Complexity grows in steps: run several tools in parallel; chain steps where each depends on the last; or design a graph with branches and merges for workflows with many decision points. Graphs are the most expressive and the most expensive, so cap their depth and branching.

Rule of thumbStrictly linear task? Use a chain. Branches and merges? A graph. Sketch it on paper first: nodes for steps, arrows for allowed transitions, and mark where branches reunite. Above all, keep it as simple as possible.






  
5
Context engineering

  
Context engineering decides what goes into the window, how it is structured, and how it fits the token budget. A support agent might combine its system prompt, the user's message, a summary of the order, the relevant policy and recent turns. Build a context and see whether it fits and stays relevant.

  

    

    
    

    

  






  
6
Choosing an approach

  
The chapter closes with three pieces of advice: match the strategy to the task, respect the clear trade-off between latency and accuracy, and build a representative set of test cases to compare planning approaches on your own workload.
