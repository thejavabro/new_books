Load Balancing Approaches and Techniques

A load balancer turns many servers into one service. Where it sits, which layer it reads and which algorithm it uses decide how evenly, and how safely, traffic spreads.

1

Four boxes that sit in the middle

Load balancers, reverse proxies, forward proxies and API gateways all intercept traffic, which makes them easy to confuse. The difference is whose side they are on and what they decide.

2

Global and local load balancing

Large sites balance at several tiers. Global server load balancing (GSLB) picks a region or data center, using DNS (answer with the nearest data center's IP), application delivery controllers (that know each site's health and capacity) or a CDN. Local balancing then spreads traffic inside the data center, often behind a virtual IP shared by several LB machines so one can fail without changing the address. Step through one request.

Inside a three-tier app, LBs also sit between web and application servers, and in front of database read replicas, so each tier scales and fails independently.

3

Balancing algorithms, live

Static algorithms follow fixed rules: round robin takes turns, weighted round robin gives bigger servers more turns, hash maps a request attribute such as client IP to a server. Dynamic algorithms ask the servers: least connections, least response time, least loaded (CPU, memory). Server C below is half the size of the others, and some requests are slow. Run the traffic.

4

Stateful or stateless balancing

If a server keeps a user's session (cart, login) in memory, later requests must return to it. A stateful LB remembers the mapping, by source IP or a session cookie (sticky sessions). A stateless LB treats every request on its own, which works when session data lives in a shared store such as Redis. Log in three users, then lose a server.

5

What each kind of LB can see

By function there are four kinds. DNS LBs answer name lookups with different IPs. ECMP routers spread packets over equal-cost paths at the network layer. Network (L4) LBs see IPs and ports only, forward TCP/UDP connections at very high speed, often via NAT or direct server return. Application (L7) LBs terminate HTTP, read paths, headers and cookies, and can route by content, terminate TLS, rewrite and cache. Toggle the layer to see what is visible.
