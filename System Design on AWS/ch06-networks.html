Communication Networks and Protocols

Servers only cooperate by sending messages. This chapter climbs the network stack and compares the protocols and API styles systems use to talk.

1

Layers: OSI and TCP/IP

Machines can only talk if they share rules. The OSI model splits networking into seven layers, each serving the one above. It is a reference model; the internet actually runs the leaner TCP/IP suite, which folds the top three OSI layers into one application layer and the bottom two into a link layer. Click a layer.

Encapsulation on the way down
2

IP: best-effort packets

IP delivers packets between addresses, hop by hop, with no promise they arrive, arrive once or arrive in order. Large payloads are split to fit the link's maximum transmission unit, typically 1,500 bytes on Ethernet. Tools like ping (ICMP) and traceroute work at this layer.

3

TCP and UDP

TCP builds a reliable, ordered, full-duplex byte stream on top of IP. It opens with a three-way handshake (SYN, SYN-ACK, ACK), numbers every byte, retransmits what is not acknowledged and controls its sending rate. UDP just sends datagrams: no handshake, no retransmission, no ordering, tiny header. Where a late packet is useless (voice, video, games, DNS), UDP wins.

Once connected, TCP probes for bandwidth. Slow start doubles the congestion window each round trip until a threshold, then congestion avoidance grows it by one segment per round trip. A timeout or duplicate ACKs signal loss: the window is cut and growth starts again. Inject a loss.

4

HTTP requests and responses

HTTP is the application protocol of the web: a client sends a method, a target, headers and maybe a body; the server answers with a status code, headers and a body. Methods carry meaning. Safe methods do not change state; idempotent ones can be repeated with the same effect, which matters when a retry follows a timeout.

Getting updates: polling, long polling, WebSockets, SSE

  
Your food order changes status three times in a minute. How does the app find out? Short polling asks every few seconds, mostly for nothing. Long polling holds each request open until there is news or a timeout. WebSockets upgrade one HTTP connection (status 101) into a persistent two-way channel. Server-Sent Events keep one HTTP response open and stream events one way, server to client, with automatic reconnect.

  

    

    
    

    

    

  






  
6
API styles: RPC, REST and GraphQL

  
A restaurant page needs the restaurant's name and the names of its vegetarian dishes. Here is that need met three ways. RPC (gRPC, Thrift) calls a typed remote function, usually with binary encoding over HTTP/2, popular between internal microservices. REST models resources with URLs and HTTP verbs, stateless and cache-friendly. GraphQL exposes one endpoint where the client describes exactly the shape it wants.

  

    

    

    

    

  






  
7
WebRTC, STUN and TURN

  
For calls, routing media through a server adds latency and cost. WebRTC connects browsers peer to peer. The snag: most devices sit behind NAT and do not know their public address. A STUN server tells each peer how it looks from outside so they can connect directly. When strict firewalls block that, a TURN server relays the traffic.
