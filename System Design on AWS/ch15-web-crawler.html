Two systems and their scale

A search engine is really two systems. The crawler fetches pages and keeps them fresh; the search engine indexes them and answers queries in milliseconds. The book scopes it to English text search and estimates from about 200 million active websites. Adjust the assumptions.

3

The URL frontier: priority and politeness

Which URL next? The Mercator-style frontier has two layers. A prioritizer scores URLs (page rank, change rate) into front queues by priority. A back-queue router puts each host in its own back queue, and a heap tracks when each host may next be contacted, so no site is hammered. robots.txt rules and crawl delays are cached per host. 4

Have we seen this URL? Bloom filters

Billions of URLs, each checked before enqueueing. A global key-value store (DynamoDB) works but costs a lookup each time. A Bloom filter answers "definitely new" or "probably seen" from a compact bit array: each URL sets k bits chosen by k hash functions. No false negatives, some false positives, which here means occasionally skipping a page that was actually new. Content duplicates are caught separately with checksums or similarity hashes of the page body.

5

Forward and inverted indexes

A forward index maps document → words (what the parser produces). The inverted index flips it: word → list of documents (posting list), with positions and other signals. Queries become intersections of posting lists. Edit the pages and search.

6

Relevance: PageRank in miniature

Matching is only half the job; the results must be ordered. Signals include term frequency and rarity (TF-IDF, BM25), where words appear (title, headings), freshness and the link graph. PageRank treats links as votes: a page is important if important pages link to it. Iterate it.
