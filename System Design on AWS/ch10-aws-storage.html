EBS volumes live in one AZ and usually attach to one instance; protect them with snapshots (stored in S3). Instance store disks are faster but vanish when the instance stops. For Windows or high-performance file systems, Amazon FSx offers managed Windows File Server, Lustre, NetApp ONTAP and OpenZFS.

S3 storage classes and what they cost

S3 stores objects (up to 5 TB each) in buckets, addressed by key, with 11 nines of designed durability. Storage classes trade storage price against retrieval price, retrieval time and minimum storage duration. Describe your data and compare monthly costs. Prices are rough us-east-1 list prices for illustration only.

Lifecycle rules move objects between classes as they age (transition actions) and delete them when they expire (expiration actions). Intelligent-Tiering does the moving automatically based on observed access, for a small monitoring fee. Build a rule.

RDS and Aurora

  
Amazon RDS runs MySQL, PostgreSQL, MariaDB, Oracle, SQL Server and Db2 for you: provisioning, patching, backups with point-in-time restore, monitoring. Two features are often confused. Toggle them.

  

    

    

    

  

  
Aurora re-architects the database for the cloud: compute instances sit on a shared, distributed storage volume that keeps six copies across three AZs and grows automatically. A write needs 4 of 6 copies; a read 3 of 6. Knock out an AZ, then a further copy.

  

    

    

    

  

  






  
4
DynamoDB: capacity and indexes

  
DynamoDB is AWS's serverless key-value and document store: single-digit millisecond reads at any scale, data spread over partitions by partition key and replicated across three AZs. You pay in capacity units. A read capacity unit (RCU) is one strongly consistent read per second of up to 4 KB, or two eventually consistent reads. A write capacity unit (WCU) is one write per second of up to 1 KB. Transactions cost double.

  

    

    

    

    
Capacity modes: on-demand charges per request and absorbs unpredictable traffic; provisioned reserves RCUs and WCUs (with auto scaling) and is cheaper for steady load. Hot partition keys still throttle, so spread writes.

The rest of the database shelf

  

  
DAX deserves a closer look: it is a write-through cache that speaks the DynamoDB API. Eventually consistent reads are served from its item cache in microseconds; strongly consistent reads pass straight through to DynamoDB; writes go to DynamoDB first, then update the cache.
