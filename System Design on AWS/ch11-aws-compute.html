1

The compute spectrum

AWS compute runs from renting a virtual server to handing over a single function. The further right you go, the less you manage and the less you can tune. Orange is yours, blue is AWS's.

2

EC2: AMIs, instance types and pricing

An EC2 instance is a virtual (or bare-metal) server launched from an Amazon Machine Image: an OS, software and volume mappings, owned by AWS, a vendor, the community or you. Then you pick an instance type. Its name encodes the family, generation, extra attributes and size. Try decoding one.

The same instance can be bought three ways. Spot uses spare capacity at a deep discount but can be reclaimed with a two-minute warning, so it suits interruption-tolerant work like batch jobs and stateless workers.

Discounts are typical ballpark figures (1-year Savings Plan about 35% off, Spot often 60 to 90% off) for illustration.

3

Auto Scaling groups

An Auto Scaling group keeps between a minimum and maximum number of instances, replaces unhealthy ones, and scales on a policy: target tracking (keep CPU near 50%), step scaling on alarms, scheduled changes, or predictive scaling from history. New instances need time to boot and warm up, so sudden spikes still hurt. Run a day of traffic.

4

Lambda: functions on demand

With Lambda you upload code (a .zip up to 250 MB unzipped, or a container image up to 10 GB) and AWS runs it in isolated micro-VMs when an event arrives, scaling out per request and billing per millisecond. Memory is configurable up to 10 GB and CPU grows with it; a single invocation can run for at most 15 minutes. Layers share libraries between functions; Graviton (arm64) is usually cheaper.

Cold starts and cost

CPU scales with memory (one full vCPU at about 1,769 MB), so more memory can be both faster and cheaper for CPU-bound code. A cold start (new environment: download code, start runtime, run init) adds roughly 100 ms to over a second; provisioned concurrency or SnapStart keeps environments warm. Prices are approximate.

5

Containers: ECS, EKS and Fargate

ECS is AWS's own orchestrator. A task definition describes containers (image, CPU, memory, ports, IAM role, logging); a task is a running copy; a service keeps N tasks running behind a load balancer; a cluster is the capacity they run on. EKS runs upstream Kubernetes with a managed control plane, for teams who want the Kubernetes API and ecosystem. Either can run on EC2 instances you manage or on Fargate, serverless capacity per task or pod.
