EMR: managed Hadoop and Spark

Amazon EMR runs open source big data frameworks (Spark, Hive, Presto/Trino, HBase, Flink) on clusters it builds for you, on EC2, EKS or serverless. A cluster has a primary node that coordinates, core nodes that run tasks and store HDFS data, and optional task nodes that only compute, perfect for Spot. With EMRFS the data lives in S3 instead of HDFS, so clusters can be transient: start, process, terminate, and keep the data.

Glue catalogs it, Athena queries it

AWS Glue is serverless data integration. Crawlers scan S3 and databases, use classifiers to infer schemas and write table definitions into the Data Catalog (a Hive-compatible metastore shared by Athena, EMR and Redshift). Glue jobs then transform data with Spark, Ray or plain Python, billed per data processing unit. Amazon Athena runs SQL directly on S3 using that catalog, serverless, billed per terabyte scanned. Layout decides the bill: partition folders let Athena skip data, columnar compressed formats shrink what is left.


  

  
Glue or EMR Serverless? Glue is the end-to-end, opinionated ETL tool with catalog, crawlers and visual jobs; EMR gives more control over frameworks, versions and tuning.

Redshift: the data warehouse

  
Redshift is a massively parallel, columnar data warehouse. A leader node parses queries and plans them; compute nodes, split into slices, each scan their share in parallel. How rows are spread across slices (the distribution style) decides whether joins need data shuffled over the network. Pick one and load the orders table.
