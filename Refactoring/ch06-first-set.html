Extract Function and Inline Function

The rule of thumb for extracting is the separation between intention and implementation. If you have to spend effort reading a fragment to work out what it does, put it in a function named for what it does. Length is not the test: a one-line function is fine if its name explains more than its body. Short functions only cost you something if their names are bad.

Extract Variable and Inline Variable

The same pair at a smaller scale. A local variable gives a name to part of an expression, which also makes it easy to inspect in a debugger. If the name would make sense outside the function, prefer Extract Function instead, so others can use it too.

4

Change Function Declaration and Rename Variable

Function declarations are the joints of a system. A good name lets you understand a call without reading the body, and good parameters decide how widely a function can be used. Fowler offers two routes: a simple one-shot edit when you can see and change every caller, and a migration route when you can't, where the old function becomes a forwarding wrapper that you deprecate and later remove.

5

Encapsulate Variable

Functions are easy to move: leave the old one forwarding to the new. Data is harder, because every reference has to change at once. Wrapping widely used mutable data in access functions turns a hard data problem into an easier function problem, and gives you a single place to watch who changes it.

6

Grouping data and the functions that use it

Data that travels together wants a home. A parameter object names the clump. A class or a transform then gives the calculations on that data a single place to live. The difference between the last two matters most when the source data can change.

Split Phase

When one stretch of code deals with two topics, split it so each can change alone. The classic case is a compiler: tokenize, parse, then generate, each phase handing a clear data structure to the next. Smaller programs benefit too. The tell is code where the first half works out data and the second half uses it, or where parsing input is mixed with acting on it.
