Simplifying Conditional Logic

1

Conditionals: power and confusion

Conditional logic gives programs their power, and it is also where they become hardest to follow. Chapter 10 has six tools: name the parts of a condition, merge checks that lead to the same result, flatten nesting with early returns, move type-based switching into classes, give a special value (like "unknown customer") its own object, and state assumptions out loud.

2

Decompose and consolidate

A long condition tells you what is happening but hides why. Extracting the condition and each branch into well-named functions turns code into intent: if (summer(date)) instead of a date comparison. And when several different checks all lead to the same result, combining them into one condition, then extracting it, says "this is one rule".

3

Replace Nested Conditional with Guard Clauses

If-then-else says both legs are equally normal. A guard clause says "this is rare: deal with it and leave". The old rule of "one entry, one exit" is not worth nesting for; clarity is the point. Replace Conditional with Polymorphism

Not every conditional needs this. It pays off when the same switch on a type appears in several places, or when there is a base behavior with variations. 5

Introduce Special Case

When many clients check for one particular value and react the same way (for example, "if the customer is unknown, use the name 'occupant'"), that duplicated reaction belongs in one place. A special-case object behaves like the real thing but carries the default behavior. The best-known form is the Null Object. Special cases can be classes, or plain records produced by a transform.

6

Introduce Assertion

Code often works only if something is true: a value is positive, at least one field is set. An assertion states that assumption where readers and debuggers can see it. It should never be needed for the program to work correctly; if it fails, that is a programmer error. Only assert things that must be true, not things that might be (validate input from outside differently).
