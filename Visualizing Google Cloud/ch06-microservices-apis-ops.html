Microservices, APIs and Operations

Once an app is split into services, you have to decide how they talk, how outsiders reach them through APIs, and how you see what is going on when something breaks.

1

From one big app to many small services

Containers, orchestration and serverless made it practical to split an application into microservices: small services, each owning one business capability and its own data, talking over APIs or events. Teams can deploy, scale and pick languages independently, and a failure in one service is contained. The book's example is an online shop: when a user places an order, the Order service has to coordinate Payment, Inventory and Shipping. Media is another fit: images and video handled by separately scaled services.

The price is a distributed system. Services must find and call each other reliably, transactions span services, and debugging means following one request across many hops. The rest of this page is about those three problems.

2

Choreography or orchestration?

There are two ways to coordinate the order flow. In choreography, every service listens for events and reacts on its own; nobody is in charge. In orchestration, a central coordinator calls each service in turn and decides what happens next, including what to undo when something fails.

The glue services

Google Cloud offers a service for each style plus two that help with both. Open the cards, then test yourself on the classic confusion: Pub/Sub or Cloud Tasks?

Pub/Sub vs. Cloud TasksPub/Sub is implicit invocation: the publisher emits an event and doesn't know or care who consumes it. Cloud Tasks is explicit invocation: the producer names the handler and controls delivery (rate limits, scheduled time, retries, deduplication).

APIs: the front door to your services

APIs are how modern apps are composed and how partners and mobile clients reach you. Publishing an API safely needs more than a URL: authentication, rate limits, versioning, monitoring and documentation. That's API management.

API Gateway

A fully managed gateway for serverless backends (Cloud Functions, Cloud Run, App Engine) and more. You describe the API in an OpenAPI spec (the API config), deploy it to a gateway, and get authentication (API keys, JWT, service accounts), monitoring and quotas. Simple, pay per call.

Apigee

A full API management platform. API services (proxies, policies, traffic routing, security), analytics on usage and performance, a developer portal for partners to discover and sign up, and monetization. It works across hybrid and multicloud backends. The book's framing: API Gateway is a small subset of what an API management platform does.

5

Cloud Operations: seeing inside the system

The Cloud Operations suite (formerly Stackdriver) collects signals from Google Cloud, other clouds and on-premises. Cloud Logging stores and routes logs; the Log Router can send them to BigQuery, Cloud Storage or Pub/Sub. Cloud Monitoring gathers metrics, uptime checks, dashboards and alerting. Application performance tools go deeper: Cloud Trace (latency across services), Cloud Profiler (CPU and memory per function in production), Error Reporting (grouped exceptions) and, in the book's time, Cloud Debugger.
