Machine learning is mostly not about models. It is a lifecycle, from raw data to an insight someone acts on, and Google Cloud offers tools for every level of ML expertise along it.

AutoML turns months of work into days. You define the target label and features; it generates data statistics, then searches over feature engineering, model architectures (simple linear models for small data, deep and ensemble models for larger) and hyperparameters, with guardrails at each step. Evaluate: the confidence threshold

a fraud classifier on 1,000 test transactions, 100 truly fraud

A classifier outputs a score per label. You pick the threshold above which you call it "fraud". Moving it trades precision (how many flags are right) against recall (how many frauds you catch). There's no single right answer; it depends on what a mistake costs.

5

MLOps: models decay

Most people think the hard part is building the model. It's actually running it. Data changes, the world changes, and a model trained on last year's behavior slowly gets worse. MLOps applies DevOps discipline to ML: formalize workflows into reproducible pipelines, version data, code and models, test and validate before release, monitor in production, and make collaboration between data scientists, ML engineers and operators part of the system.

Model monitoring: when to retrain

accuracy over 12 months

Vertex AI Pipelines runs ML workflows serverlessly as a graph of containerized steps. You write pipelines with the open-source Kubeflow Pipelines SDK or TensorFlow Extended (TFX); each run's artifacts and lineage go into Vertex ML Metadata, so you can trace which data produced which model. Under the hood each step is a container with inputs and outputs, and the service handles scaling and security with IAM and VPC Service Controls.

from kfp import dsl

@dsl.pipeline(name="churn-train")
def pipeline(table: str):
    data  = extract_op(table=table)
    model = train_op(data=data.outputs["dataset"])
    eval_ = evaluate_op(model=model.outputs["model"])
    with dsl.Condition(eval_.outputs["auc"] > 0.85):
        deploy_op(model=model.outputs["model"])
6

Forecasting: what will demand be next week?

Retailers forecast demand, call centers forecast call volume, finance forecasts revenue. A univariate series is one variable over time; multivariate adds related signals like price, promotions or weather. Classic statistical methods (ARIMA, exponential smoothing) fit one series at a time; deep learning models learn across thousands of related series and use extra signals. Vertex Forecast (AutoML forecasting in Vertex AI) brings those models without writing them, and BigQuery ML offers ARIMA_PLUS in SQL.

7

BigQuery ML: models in SQL

BigQuery ML lets analysts create, evaluate and predict with models using SQL, where the data already lives. No exporting data, no new language, fewer handoffs. It also offers explainability for predictions, hyperparameter tuning and export to Vertex AI.

CREATE OR REPLACE MODEL shop.churn
OPTIONS (model_type = 'logistic_reg', input_label_cols = ['churned']) AS
SELECT tenure_months, orders_90d, support_tickets, churned
FROM shop.customers;

SELECT customer_id, predicted_churned_probs
FROM ML.PREDICT(MODEL shop.churn, (SELECT * FROM shop.customers_today));
