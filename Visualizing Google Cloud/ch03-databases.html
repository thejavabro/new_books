Relational or nonrelational?

Cloud databases are managed (Google does backups, patching and replication), scalable and secured by default. They fall into two families. Relational databases keep data in tables of rows and columns with a fixed schema, join tables with SQL, and give ACID transactions: atomic, consistent, isolated, durable. Nonrelational (NoSQL) databases trade some of that for flexible schemas, horizontal scale and a data model tuned for one kind of access. Cloud SQL: familiar engines, managed

  
Cloud SQL runs MySQL, PostgreSQL or SQL Server for you: provisioning, storage growth, patches, automated backups and point-in-time recovery. Setup is short: pick the engine, region and zone, machine size and storage, and whether to make it highly available. It scales up (bigger machine) and adds read replicas for read-heavy load. Database Migration Service moves an existing MySQL database in with minimal downtime, and Cloud SQL Insights helps find slow queries.

Cloud Spanner: relational, at global scale

  
Cloud Spanner is the database you pick when you need SQL and transactions and horizontal scale, up to global. Compute nodes serve reads and writes but don't own data; the data sits in Google's Colossus file system, replicated across zones. Each table is sorted by primary key and cut into splits. Every split is replicated, and the replicas form a Paxos group that elects one leader to handle writes. Leaders for different splits live in different zones, so the work is spread out.

TrueTime and commit wait
why the uncertainty matters

    
TrueTime combines GPS receivers and atomic clocks, so every machine knows the time to within a small interval ε. Between syncs the uncertainty grows like a sawtooth (a few milliseconds at most). To make timestamps globally ordered, a write picks a timestamp and then waits out the uncertainty before it becomes visible. Smaller ε, shorter wait.

    
    

  






  
4
Firestore: a backend for apps

  
Firestore is a serverless document database that works as a whole backend-as-a-service: mobile and web SDKs, offline support, live sync, security rules, and ACID transactions with strong consistency. Data is documents (sets of fields) inside collections; a document can point to subcollections. Queries are shallow: reading a document doesn't drag its subcollections along. Native mode lets clients connect directly (with real-time listeners); Datastore mode is server-side only and scales writes without limit.

      Cloud Bigtable: billions of rows, single-digit milliseconds
      
  
      Cloud Bigtable is a wide-column NoSQL store for huge amounts of single-keyed data: time series, IoT, ad tech, financial ticks, personalization. Tables are sparse, scale to billions of rows and thousands of columns, and speak the HBase API. Each node adds roughly 10,000 reads and writes per second, and because storage is separate from nodes, Bigtable can rebalance or add nodes without moving data. Replicate across up to four clusters for higher availability (99.999% across three regions with multi-cluster routing). Everything hangs on the row key: rows are stored sorted by it.

      6
      Memorystore: sub-millisecond, in memory
      
  
      Memorystore is managed Redis or Memcached. Redis Basic tier is a single node: fine for a cache that can survive a cold restart. Standard tier adds a replica in another zone with automatic failover. Memcached scales out over nodes. Uses: caches, session stores, leaderboards, distributed locks, rate limits, real-time analytics.

      Cloud SQLManaged MySQL, PostgreSQL, SQL Server. Regional, HA with a standby, read replicas. The default for typical apps.
      
    
      SpannerSQL plus horizontal, even global, scale. Splits, Paxos leaders, TrueTime for external consistency. Up to 99.999%.
      
    
      FirestoreServerless documents, real-time sync, offline, ACID. Backend for mobile and web.
      
    
      BigtableWide-column, petabyte scale, low latency, HBase API. Design the row key to spread load.
      
    
      MemorystoreManaged Redis and Memcached for sub-millisecond caches and transient state.
      
    
      Rule of thumbStructured and transactional → relational. Huge scale or flexible shape → nonrelational. Often both.
