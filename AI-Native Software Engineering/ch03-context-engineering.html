Context Engineering Fundamentals

Everything the agent knows about your task arrives through one door: the context window. Context engineering is choosing what goes through that door, in what order and at what moment, so the model can reason well.

1

Correct in general, wrong for you

You ask an agent to add an endpoint to a Node service. It uses Moment.js (your team banned it), skips the Zod validation your architecture requires, and writes a unit test when CI gates on integration coverage. Nothing is wrong in the abstract. It just never knew your system. A prompt engineer rewrites the request. A context engineer asks: did the model have what it needed? Add the missing context and regenerate.


    

  

  
A better prompt helps one session. A rules file in the repo helps every engineer, every session. That is why context engineering compounds and prompt tweaks don't.






  
2
The window is finite and unevenly lit

  
Attention compares every token with every other token, so the work grows with the square of the context length. Longer windows don't come with proportionally more attention, and training mostly involves short text. The result is a slope, not a cliff. A practical rule: treat about half the advertised window as reliable.

Try it: your own working memory

  
People hold roughly four chunks in working memory. Overload it and things quietly drop out, not because you are incapable but because the resource is shared. A full context window behaves the same way. Memorize the list, do the sum, then see what survived.

4
Two failure modes, one golden balance

  
Too little context and the agent fills gaps from training-data averages. Too much and the signal drowns, attention thins, cost and latency rise. Only the user's query is strictly mandatory; everything else must earn its place.

  

    

    

    

  

  

    
Two questions for every component
  • How often does it actually improve the output?
  • What would break if it were missing for a session?
"Rarely" and "nothing obvious" means it belongs in on-demand loading, not always-on.

    
The right-time problem
Migration rules are noise while fixing CSS. Scraper tool schemas are noise while refactoring types. Load project-wide constraints always; load task-specific workflows only when that task starts.

  






  
5
The curse of instructions

  
If each rule is followed with probability p, the chance that all N are followed at once is about pN. Every rule you add lowers the odds that every rule holds. Ten focused rules beat thirty that try to foresee everything.

7
Assemble a context window

  
Before your first message reaches the model, the runtime stacks a static foundation: system prompt, tool schemas, rules, environment notes. Then your message, then the dynamic stream of tool results. A fat foundation leaves less room for real work. Toggle components and watch the window.

  

    

      

      

    

  

  

    
    
    
    
    
  






  
8
Skills load in three tiers

  
Skills solve the cost problem with progressive disclosure. Only a catalog of names and descriptions (about 50 to 100 tokens each) is always present. The body loads when the skill is triggered, and its scripts or references only when the instructions call for them.

  

    
20

    

    

    

  

  

    
Model-driven
The agent reads the catalog and decides a skill fits.

    
User-explicit
You type /skill-name. A "command" is just a user-invoked skill.

    
Hidden
Not in the catalog. Use for powerful or risky skills, like ones that send email.

How agents explore on their own

  
Agents can find context themselves in three ways. Each is good at different questions. Pick a question to see which works best. Remember: exploration fills gaps; deliberate context prevents them. The agent won't search for a constraint it doesn't know exists.

11
Designing around context rot

  
As a session grows, the early foundation slides toward the dim middle. Mistakes creep in quietly: a banned library returns, an early constraint is forgotten. Watch a long session, then hand off cleanly.
