Coloring Graphs with Backtracking

Coloring a map so neighbors differ, solving a Sudoku and scheduling exams are the same problem in disguise. A general backtracking search, on immutable data, solves them all.

Coloring South America

Argentina, Bolivia, Brazil and Paraguay all border one another, so a map of South America needs at least four colors. Mathematicians proved late in the 20th century that four always suffice for a flat map (real political maps use more: the ocean is usually blue, and French Guiana should match France). Abstract the map into an undirected graph: a node per country, an edge per shared border. Tap a country to cycle its color.

Color the easy nodes last

With c colors, any node with fewer than c neighbours can safely be colored last: whatever its neighbours get, a color remains. So remove such a node, recursively color the rest, then put it back with a free color. Removing it lowers its neighbours' degrees, exposing more easy nodes. The Falklands (degree 0) are trivial; Colombia (degree 4) is hard to leave until last. On graphs full of low-degree nodes this runs in roughly linear time, O(n + e), and at worst O(n² + e). Press "Run the simple algorithm" above to watch it peel and refill.

Where it gives upIf every remaining node has degree ≥ c, there is no safe "last" node and the algorithm fails, even when a coloring exists. In Sudoku every cell has degree 20 and there are only 9 colors.
4

A Sudoku is a graph-coloring problem

Make 81 nodes, one per cell, and connect any two cells that may not hold the same digit. Each row, column and box is a clique of 9 mutually adjacent nodes. The digits are the 9 colors; the givens are pre-colored nodes. Tap a cell to see its 20 neighbours.

5

A general backtracker

An attempt is a multidictionary from each node to the colors still possible for it. A reducer removes impossible colors without guessing: if a node is down to one color, no neighbour may have it, and repeat until nothing changes. The backtracker reduces, then: any node with no colors left? broken, return nothing. Every node down to one? solved, return it. Otherwise pick a node with several options, try each in turn as a guess, and recurse. Immutability makes "go back" free: the old attempt is still there.

IEnumerable<Attempt> Solve(Attempt a) {
  a = reducer.Reduce(a);
  if (a.IsBroken) return [];
  if (a.IsSolved) return [a];
  var n = a.SomeUndecidedNode();
  return a[n].SelectMany(
    c => Solve(a.SetSingle(n, c)));
}
It's a Cartesian product with pruningWith no constraints at all (two islands, four colors) the backtracker returns all 16 pairs: exactly the Cartesian product from chapter 6, built from nested SelectMany calls. The reducer's job is to cut away regions of that space that cannot contain a solution, as early as possible.
6

Why it can be slow: NP-completeness

Graph coloring ("can this graph be colored with k colors?") is NP-complete: a yes-answer is easy to check in polynomial time (look at every edge), but no polynomial-time algorithm to find one is known, and nobody has proved none exists. A fast algorithm for any NP-complete problem would give one for all of them. So backtracking is exponential in the worst case; a good reducer makes typical cases fast.

7

Scheduling and register allocation

Airport gates × hours, classrooms × time slots and CPU registers are all "colors". In a compiler, each local variable is a node, variables whose lifetimes overlap are adjacent, and registers are colors. A coloring means no variable ever has to be spilled to memory.
