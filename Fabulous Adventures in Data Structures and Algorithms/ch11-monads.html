Interlude: Monads

The second interlude: a monad is a type that can wrap a value, transform what it wraps, and flatten a wrapper of wrappers. That small pattern explains LINQ, nullables and async.

1

A design pattern for adding a capability

In category-theory terms a monad is an endofunctor that obeys some laws. In everyday object-oriented terms it is a generic type M<T> that adds a capability to any T while leaving the program's workflow intact. You have almost certainly used several already.

Every monad has two things. Unit wraps a plain value: T → M<T>. And there is a way to take a workflow built from functions on plain values and run it on wrapped values, so that it keeps its meaning and gains the new power. That second part is the interesting one.

2

How hard can it be to divide by 2?

Take DivTwo(int x) => x / 2.0. Lifting it into a monad means unwrapping, dividing and rewrapping, and the monad decides when and how. Pick a monad and run it.

3

Map, then Bind, then Join

Writing a monadic version of each function by hand would be tedious, so write one helper per monad. Map takes an M<T> and a plain function T → R and gives an M<R>. But give Map a function that already returns a monad, T → M<R>, and you get M<M<R>>: a doubly-lazy value or a nullable nullable. That is almost never what you want. Bind takes T → M<R> and flattens as it goes.

The function is Weird(x), which returns a monadic half: for Nullable it gives null when x is odd, for Sequence it returns [x, x/2].

Map(x, Weird)
Bind(x, Weird)
Unit and Bind are enoughMap(x, f) = Bind(x, t ⇒ Unit(f(t))). Join(mm) = Bind(mm, m ⇒ m). Bind threads a new function onto an existing workflow, hence the name.

You already know the sequence monad

For sequences, Unit makes a one-element list, Map is Select (C#) or map, and Bind is SelectMany or flatMap: make a sequence for each item, then concatenate them all instead of nesting. Pick a function and watch the groups form and flatten.

5

Where, built from Unit, Bind and zero

Option 3 above is a filter. Filtering is the same as turning each item into a sequence of zero or one items and concatenating. Absurdly wasteful, but it uses nothing except Unit, Bind and the empty sequence. Sequences form an additive monad: two instances can be added (concatenated); there is a zero (MZero, the empty sequence) that is the identity for addition; and binding anything to MZero gives MZero.

a + MZero = aConcatenating [] changes nothing.
Bind(MZero, f) = MZeroMapping over nothing gives nothing.
Where = Bind + Unit/MZeroKeep t as Unit(t), drop it as MZero.

Chapter 6 used SelectMany for Cartesian products, a kind of multiplication, and multiplying by an empty sequence gives empty. So Bind behaves rather like multiplication of monads. Part 3 makes surprising use of a Where on a monad that is not a sequence.
