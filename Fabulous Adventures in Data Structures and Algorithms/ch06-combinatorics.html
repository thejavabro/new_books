Combinatorial Algorithms

Enumerating every combination, permutation or product sounds like brute force. Done well, it is a lovely bridge between sequences and the integers, and the source of shuffles and bell-ringing patterns.

1

The Cartesian product: a nested loop with a name

Characters × weapons → "who can wield what?" Any nested foreach over two collections walks the Cartesian product A × B, every pair with one item from each (SQL calls it a CROSS JOIN). Wrapping it in a helper, ideally with a projection function instead of returning tuples, makes code say what it means. The harder question: what if the number of sequences is only known at run time?

Edge cases decide the designThe product of n sequences is a sequence of n-item sequences. So the product of zero sequences is a sequence holding one empty sequence, [[]], which is exactly the right starting point for building up one sequence at a time. Each step appends to the right without copying, using the immutable deque from chapter 3, and the whole thing is a lazy query nested n deep, so building it is O(n).
2

Every product is a way of counting

Take the product of [0…9] with itself four times and you list 0000 to 9999 in order: decimal notation is a Cartesian product. Any base works, and the bases needn't even match: mixed radixes count just as well. Hold that thought; permutations and combinations give two stranger number systems.

3

Next permutation in dictionary order

Narayana Pandita's 14th-century algorithm mutates an array into the next lexicographic permutation, and it copes with duplicates. Four moves: find the rightmost item with a bigger item just to its right; find the rightmost item bigger than it; swap them; reverse everything after the first position. Average cost is about 3 comparisons and 1.5 swaps: amortized O(1), worst case O(n).

4

Jump straight to permutation number p

Lay the n! permutations in a table of n rows and (n−1)! columns: row r holds the ones starting with r. Then permutation p starts with p ÷ (n−1)!, and the rest is permutation p mod (n−1)! of the remaining numbers. The successive quotients are the digits of p in factorial base: 9 = 1·3! + 1·2! + 1·1! + 0·0!, written 1110. Each digit says which of the remaining numbers to take next.

Fisher–Yates, seen againThe classic fair shuffle draws random ri between 0 and i and swaps item i with item i + ri. Those random numbers are just factorial-base digits of a random permutation number. Used as an index scheme, swaps (O(1) each) replace list removals (O(n) each), so it's cheaper than the lexicographic version, at the price of a less natural order. Flip the toggle to compare.
5

Change ringing: one swap at a time

English bell ringers since the 1600s have played every ordering of n bells where each new "change" swaps just one adjacent pair. Lexicographic order fails at once (012 → 021 → 102 swaps a non-adjacent pair). The recursive solution inserts the biggest bell into each (n−1)-bell change, sweeping right-to-left then left-to-right. Shimon Even's version tracks a direction per number: the largest mobile number (one with a smaller neighbour in its direction) moves, and everything bigger reverses. O(n) per permutation.

6

Combinations: what if we skip things?

Permutations test different orders; combinations test skipping things. The k-combinations of 0…n−1 are increasing k-item subsequences, here listed in lexicographic order read from the right. Next combination: find the rightmost increasable number (it can grow without colliding with its right neighbour or passing n−1), increment it, and reset everything to its left to 0, 1, 2…

Counting: n choose k

nCk = (n−1)C(k−1) + (n−1)Ck: a combination either contains n−1 or it doesn't. Compute it with the running product nC(k−1)·(n−k+1)/k, and multiply before dividing: r = r * a / b, never r *= a / b.

7

A combination's number, without knowing n

If a combination is x₀ < x₁ < … < xk−1, its position in the right-to-left lexicographic list is (x₀ C 1) + (x₁ C 2) + … + (xk−1 C k). n never appears! Every number p has exactly one such representation for each k: the combinatorial number system (Macaulay's representation; its use for ranking combinations is due to D. H. Lehmer). Pick k digits.
