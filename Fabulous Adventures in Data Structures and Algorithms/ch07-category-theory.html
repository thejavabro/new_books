Interlude: Category Theory

The first "abstract nonsense" interlude: categories are just things and arrows that compose. Seen that way, generic types such as sequences and nullables are functors, covariant or contravariant.

1

Generalized abstract nonsense

Programming is stacking abstractions: electrons, then bits and instructions, then variables and loops, then our own data structures. Category theory goes one level higher still. Created in the mid-20th century, it studies relationships between stuff, whatever the stuff is. Its own practitioners call it "generalized abstract nonsense". Three short interludes in this book dip into it.

2

Objects and arrows

A category is a bunch of objects (anything at all) and morphisms, arrows between objects, obeying two rules. Reflexive: every object has an identity arrow to itself. Transitive: if A→B and B→C then A→C. Read an arrow as "you can get from here to there". Toggle arrows below and see whether you have a category. (Identity arrows are always there; like most drawings, these omit them.)

Posetal categoriesWhen the arrows come from a "greater than or equal" kind of relation, the category is posetal (from partially ordered set). The numbers 0, 1, 2 with an arrow from each to every number at least as big form one. So do four generations of a family with "is an ancestor of, or the same person as".
3

Functors: maps that keep the arrows

Map each object of one category to an object of another. If every arrow X→Y has a matching arrow F(X)→F(Y), the map is a covariant functor. If it maps a category into itself, it is an endofunctor. Choose where the numbers go and the checker tells you whether arrows survive.

4

The category of types

Now let the objects be types, and draw X→Y when an expression of type X can be assigned to a variable of type Y (assignment compatibility). Object, Animal, Giraffe and Tiger give a posetal category: Giraffe→Animal, Tiger→Animal, Animal→Object, and no arrow between Giraffe and Tiger. Then apply a generic type to every object and see what happens to the arrows.

Where the jargon comes fromImagine two points walking along arrows. If one moves Giraffe → Animal and the other can make the matching move IE<Giraffe> → IE<Animal>, they vary together: co-variant. With a comparer the second point must go IC<Animal> → IC<Giraffe>: they vary in opposite directions, contra-variant. An animal comparer can compare giraffes, so it is a giraffe comparer. Apply IC twice and the arrows flip back.

Bonus: the most specific common type

The category of types is a semilattice: for any two types you can find the most specific type both can be assigned to. Compilers use this kind of lattice reasoning for type inference, optimizations and safety checks. (And category theorists call this infinite category "small", because it is only infinite.)
