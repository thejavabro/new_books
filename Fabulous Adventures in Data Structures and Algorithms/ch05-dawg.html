2

A sorted list and binary search

Keep the words sorted and binary-search. Each of the log n comparisons is a string comparison costing O(m). For StartsWith, find where the prefix would go and walk forward while words still match. Simple and decent. Try a prefix.

How many bytes is a list of strings?For ENABLE in .NET: about 3 MB of 2-byte chars, 1.3 MB of references, plus a length and a 16-byte header per string object: nearly 8 MB, and 172,820 objects for the garbage collector to track. Packing UTF-8 bytes into one big array indexed by integers might get it to about 2.5 MB, at the cost of fiddly code.
3

Share the prefixes: the trie

With a small alphabet and many words, prefixes repeat (ENABLE has over 750 words starting with anti). A prefix tree, or trie ("for retrieval"), stores each shared prefix once. Edges carry letters; nodes are the gaps between letters; a double circle marks the end of a word. Contains just follows edges: O(m), independent of n.

4

A trie is a finite state automaton

A finite state automaton has finitely many states and moves between them on each input, like a vending machine. Read the trie that way: nodes are states, letters are inputs, the root is the start state and double circles are accepting states. The words it accepts are its language. The trie above has more states than it needs; the classic question "what is the smallest automaton for the same language?" is exactly how to shrink it. Type below to run the current graph as a machine.

Why not build a trie, then minimize it?Classic minimizers partition states into groups that might be equivalent (accepting vs. non-accepting first) and refine. They are fiddly and costly, and if the trie is too big for memory in the first place, building it first defeats the purpose. Better: build the minimal graph directly.
5

Build the DAWG one word at a time

The Daciuk–Watson–Watson algorithm (1998) adds sorted words one at a time and keeps an invariant: the graph is minimal everywhere except along the word just added. Before adding a new word, it finds the common prefix with the previous word, then walks the previous word's leftover suffix from its end backwards, replacing each node with an equivalent node already in a canonical set, or adding it to that set. The building cost stays O(mn): every node is fixed up once, and each fix-up is a constant number of hash-set and dictionary operations. The canonical set never exceeds the final DAWG's size.

7

Fitting it in 640 KB

Old word games packed a DAWG into one byte array. Each node is a 4-byte header: 1 bit for "end of word" plus 1 bit per letter that has an outgoing edge. Then one 3-byte offset per set letter bit, pointing at the target node's header. Click letters to build a header.

ENABLE: 54,167 nodes × 4 bytes + 122,975 edges × 3 bytes = 585,593 bytes, comfortably under the old 640 KB limit.
