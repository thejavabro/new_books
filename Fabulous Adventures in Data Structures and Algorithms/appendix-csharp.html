Value types and reference types

C# sorts most types into two kinds. A value type variable (int, double, any struct) holds the value itself. A reference type variable (string, arrays, interfaces, any class) holds a reference to an object, or null. The author of a type chooses its kind when declaring it. Java has only built-in value types so far. C++ lets each variable choose value, reference or pointer. Assign and then mutate to see the difference.


    

    

    

  

  
Delegates are objects you can call, like C++ function pointers or Java single-method interfaces, and are usually written with Func<…>. Interfaces list the members that an implementing class or struct must supply.

Three ways to do generics

  
The code for List<T> is written once, but each language makes the concrete types differently. C#'s generics are reified: the runtime builds List<int> as a real type the first time it is used.

Two kinds of nullable

  

    
Nullable value typesint?, also written Nullable<int>: a principled "missing" instead of sentinels like −1. These are like Java's Optional and C++'s std::optional. Nullable was the first monad in chapter 11.

    
Nullable reference typesstring? is only a compile-time annotation. The compiler warns about possible nulls, but nothing is checked at run time. ! and where T : notnull silence those warnings, much like Java's @Nullable and @Nonnull.

Extension methods, iterators and lambdas

  
An extension method is a static method in a static class whose first parameter is marked this. It looks like a new method on an existing type, and it is how the book adds Histogram(), Samples() and friends to every distribution. Add iterators (yield return produces items on demand) and lambdas, and you get fluent pipelines built from the three basic sequence operations: project (Select), filter (Where) and flatten (SelectMany).

  
var big = customers
    .Where(c => c.City == "Leeds")
    .SelectMany(c => c.Orders)
    .Where(o => o.Total >= 1000);
