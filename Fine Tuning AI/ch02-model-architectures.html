Model Architectures: The DNA of AI

Before you tune a model you should know what is inside it: tokens, embeddings, attention, feed-forward layers, and the efficiency tricks that separate the open model families you will actually fine-tune.

1

How text flows through a transformer

A mechanic who does not know how an engine works can change the oil but cannot rebuild the transmission. Fine-tuning is similar: the decisions that separate a good adapter from a mediocre one depend on knowing what is inside. The big picture is a pipeline from text to a probability for the next token.

2

Attention: the highlighter

Attention is like reading with a highlighter: for each word, you glance back at the words that help explain it. Each token gets three learned vectors. The query asks "what am I looking for?", the key says "what do I contain?" and the value carries "what I can pass on". Scores come from multiplying one token's query with every key, a softmax turns them into weights that add up to one, and the output is the weighted mix of values. In the paper's compact form: softmax(QKᵀ/√d)·V.

None of these numbers is designed by hand. Training predicts the next token billions of times, measures the error with cross-entropy, and backpropagation plus an optimizer such as AdamW nudges the Q, K and V matrices until useful patterns like "it → cat" emerge.

3

Many heads, many layers

One attention operation captures one kind of relationship. Multihead attention runs several in parallel, each with its own Q, K, V. The hidden vector is split among heads so the total work stays about the same, then an output projection mixes the heads back together. Interpretability research suggests specialization happens more across layers than within them: early layers track local syntax, deeper layers build meaning. Heads do not neatly map to human labels.

Self-attention means queries, keys and values all come from the same sequence. Cross-attention takes queries from one sequence and keys and values from another, as in encoder-decoder translators and in multimodal models attending to image features.

4

The feed-forward network stores knowledge

After attention gathers context, each token passes through a two-layer feed-forward network: expand (for example 4,096 to 14,336 dimensions), apply a nonlinear activation such as SiLU or SwiGLU, then contract back. Each expanded neuron acts like a pattern detector, and the second layer holds what to output when the pattern fires, so FFNs are often described as key-value memory. A handy mental model: attention decides what to look at, the FFN decides what to do with it. That is why LoRA often targets these layers too.

5

Decoder-only and the causal mask

The original transformer was an encoder-decoder built for translation, where the whole source sentence must be read before writing (Gaelic, for instance, puts the verb first). Generation is different: future tokens do not exist yet, so each position may only look backward. That causal mask is all you need, so most open models are decoder-only: one stack, one objective (next token), and every position in a training example gives a learning signal.

6

Grouped query attention and the KV cache

When generating, the model caches the keys and values of every earlier token (the KV cache) so it does not recompute them. With standard multihead attention each head has its own K and V, and the cache balloons with long contexts. Grouped query attention lets several query heads share one K/V head. Llama 3 8B groups 32 query heads into 8 KV heads: a 75% smaller cache. The cost is some lost nuance, since grouped heads see the same view of the context.

7

Sliding windows and the pyramid

Full attention costs grow with the square of the sequence: 10 tokens means 100 comparisons, 1,000 means a million. Mistral 7B let each token attend only to a fixed window of recent tokens. It sounds lossy, but stacking layers widens the reach: layer 2 sees through layer 1's windows, so the receptive field grows linearly with depth, like a pyramid.

8

Sparse mixture of experts

In a dense model every token passes through every weight. A mixture of experts replaces the FFN with several expert FFNs and a learned router that picks a few per token. Mixtral 8x7B has 8 experts and uses the top 2: 46.7B parameters in memory, about 12.9B doing work per token. You get big-model capacity for small-model compute, but you still need memory for all of it, and fine-tuning is trickier (experts, router, load balance). For most projects a dense model is easier.

Gemma 4, the book's workhorseGemma comes in sizes from about 2B to 31B, as -pt (pretrained, raw) and -it (instruction tuned). It mixes sliding-window and global attention layers (windows of 512 tokens on the small edge models, 1,024 on bigger ones), shares K/V heads aggressively, lets edge-model layers reuse KV tensors from earlier layers, and uses a RoPE variant, reaching 128k to 256k contexts without memory exploding.
9

Tokenizers and byte pair encoding

Splitting on words fails on rare words, typos, code and languages without spaces, so models use subword vocabularies. A bigger vocabulary (Llama 2 had 32k tokens, Llama 3 about 128k) makes sequences shorter but the embedding table larger. An English-centric tokenizer may split Chinese "你好世界" into four characters where a multilingual one finds two words. You cannot swap a model's tokenizer without retraining, so check it handles your domain before choosing a base model.

10

Embeddings and rotary positions

Each token ID maps to an embedding: a direction in a space of thousands of dimensions, where similar meanings point similar ways and the dot product measures relatedness. Order is missing, though: attention alone sees "the cat ate the mouse" and "the mouse ate the cat" as the same bag. RoPE adds position by rotating each vector by an angle proportional to its position, so meaning is kept while nearby words get similar twists. It also generalizes better to longer sequences.

11

Choosing a base model

Beyond architecture, consider instruction following (start from an -it model for chat-like tasks), reasoning depth (hard to add by fine-tuning), and whether a long context really works: many models suffer from lost in the middle, so test recall at different positions first.
