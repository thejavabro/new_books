Automation Building Blocks and Scheduled Work

Automation is a toolbox, not one button. Choose the smallest block that does the job, and give scheduled tasks clear inputs, outputs and a human checkpoint.

1

Spot work worth automating

A task is worth automating when it repeats, follows a pattern and takes time to redo. Listen for "I did this last month too" or "I always have to remind Claude about our format". Multi-step tasks (gather, draft, check against a rule) benefit most from structure. But never automate something you have done only once: you cannot yet tell which parts are stable. Note availability at writing: Cowork and scheduled tasks need a paid plan; skills work on all plans with code execution on; computer use has narrower support.

2

Pick the least complicated block that works

Projects keep context for work that still needs your judgment each time. Scheduled tasks handle when. Skills handle how, consistently. Connectors and MCP bring in outside systems. Plugins package several of these together. Answer the questions about your task.

3

A durable order for building automation

Climb one rung at a time. At every rung ask the same question: what is the least complicated mechanism that reliably handles this? You can always add a skill, connection or sub-agent later, once you know exactly where the plain version falls short.

4

A scheduled task is work plus a trigger

You describe the work once and choose when it runs; Claude starts a fresh Cowork run each time. The work can include a condition: check daily, but only tell me when concert tickets appear. If the notification stops arriving, walk the chain to find the break.

5

Create a scheduled task, and pick the approval mode

Try the prompt once in normal chat first: scheduling an unclear prompt just repeats an unclear result. Then use the Scheduled page (Set up manually, or Create with Claude, or type /schedule). A good prompt says what to do, when, where to get information, what the result contains, when to stay quiet, and what it must never do without you. Match the approval mode to what the task is allowed to do.

6

Will its sources be reachable at run time?

Most scheduled tasks run in Claude's cloud, so they work with your laptop shut. Anything that lives only on your computer (a local folder, a local connector, your browser, a desktop app) needs the machine awake and the desktop app running. A keep-awake setting does not survive closing the lid. Prefer cloud-reachable sources for anything that must run while you are away.

7

Choose a time when fresh data exists

Each run must find what it needs: no "compare with what you found last week". Ask it to fetch both weeks from the source. Schedule after the data lands, and check the time zone. Figures are uploaded Friday 4pm for a Monday 9am meeting; drag the run time.

Start weeklyA daily task that rarely finds anything becomes noise. Name each task so you recognise it months later. If several tasks share context, put them in a Cowork project: the project holds the context, the schedule decides what happens when.
8

Design silence carefully

A watcher that says nothing when nothing changes looks exactly like one that broke. For anything important, review run history or ask for a one-line status. Compare.

9

Review once a month: useful, accurate, working, still safe?

Pause when you may need it again (a paused task keeps its instructions; check the next run time when you resume). Edit when the purpose holds but the instructions or timing need work. Delete when you are done; pause first if unsure. Never rely on a schedule for emergencies, medical warnings, trades, legal deadlines or safety alarms.

Pause, edit or delete?
