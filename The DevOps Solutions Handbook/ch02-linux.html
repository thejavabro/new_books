The Big Picture: DevOps and Linux

Most of what a DevOps engineer touches runs on Linux, usually without a screen. This chapter builds a disposable Ubuntu lab and the terminal habits you will use every day.

A disposable Linux lab with Vagrant

Most servers you will run are Linux, usually with no graphical desktop. The chapter suggests learning on an Ubuntu VM in VirtualBox, but created by Vagrant, a command-line tool that builds VMs from a small text file called a Vagrantfile. The file names a base image ("box"), the provider and the resources; vagrant up builds it and vagrant ssh drops you into its shell. Because it is code, you can destroy and rebuild the lab whenever you like. Tune the sliders and watch the file change.

Only pull boxes from sources you trust: a box is an operating system someone else built.

Read, write, execute: permissions as numbers

  
Every file has three permission sets, for its owner, its group and others. Each set adds up read (4), write (2) and execute (1), so one digit from 0 to 7 describes it and three digits describe the file. chmod changes them, chown changes the owner, and -R applies either to a whole folder. Pipes: awk, cut, sort and xargs

  
Linux commands are small and do one thing; the pipe | feeds one command's output into the next. awk picks columns out of noisy output, cut slices each line by a delimiter, sort orders lines, and xargs turns a list of lines into arguments for another command (or one flat line). 5
Packages and the filesystem map

  
On Ubuntu, apt manages software: refresh the package lists with sudo apt-get update, then sudo apt install figlet or sudo apt remove figlet. Software outside the default repositories (Vagrant, for instance) needs its vendor's signing key and repository added first. Linux itself is mostly configuration files arranged under one root, /. Tap a folder to see what lives there.

  

    

    

  






  
6
Adding a disk: lsblk to fstab

  
Disks appear as devices such as /dev/sda (with partitions sda1, sda2...). lsblk lists them, df -h shows space in human units. A new disk must be formatted, mounted on a folder, and recorded in /etc/fstab or it will not come back after a reboot. Step through adding /dev/sdb.

  

    

    

  






  
7
Editing config files: nano and vim

  
Changing Linux means editing text files, often on a server with no GUI. nano is simple and shows its shortcuts on screen (save and exit with Ctrl+X). vim, descended from 1976's vi, is on almost every system and is modal: you start in normal mode, press i to insert, Esc to go back, and type :wq to save and quit. Drive this miniature vim with the keys below.

  

    

    

    

  






  
8
SSH: a secure tunnel, then keys instead of passwords

  
SSH (Secure Shell) gives you an encrypted command line on a remote machine. The server's SSH service listens on TCP port 22. Vagrant set this up silently; to reach the VM like a real server you add a bridged network adapter so it gets an address on your LAN, check systemctl status ssh, and connect. Passwords can leak, so the better path is a key pair.

Bash scripts: variables, input and decisions

  
A script is just the commands you would type, saved in a file that starts with a shebang such as #!/usr/bin/bash and made runnable with chmod +x. Variables hold values, read captures input, and if / elif / else picks a path using tests like -eq, -lt or file checks such as -f. Type a number and see which branch runs.

Worked example: onboarding usersThe chapter grows a create_user.sh script: take a username as $1, run useradd -m, set a password from $2 with chpasswd, then switch to interactive read prompts, using read -s so the password isn't echoed. Passing passwords as arguments is lab-only: they end up in shell history. The lesson: any task you repeat daily, weekly or monthly is a candidate for a small script.
