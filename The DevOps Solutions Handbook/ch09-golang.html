Why a DevOps engineer learns a language, and why Go

The tools you configure all day are programs. Knowing a language moves you past copy-and-paste automation: you can read a stack trace that points into a tool's source, read the code to see what a flag really does, and write small utilities (a health check, a config validator, an API report) in twenty minutes. Go and Python are the usual picks; Go is the language of the cloud-native stack. One language learned well makes the next one easier: the aim is foundations, not mastery.

Static types: the compiler says no (early)

  
Go is statically typed: every variable's type is fixed at compile time, conversions must be explicit, and the compiler refuses to build programs with type mistakes, unused variables or unused imports. For automation that will touch real infrastructure, failing at compile time beats failing halfway through a production run. var declares, := declares-and-infers inside functions, const fixes a value forever. Will each snippet compile?

Pointers: handing over the address, not the value

  
A variable is a box in memory at an address, like a house number. Normally Go hands a function a copy of what's in the box. fmt.Scanln needs to change the box, so it needs the address: &name. That's all a pointer is: a value that says where another value lives. Step through both versions.

  

    

    

    

  






  
6
Errors are values: check err != nil

  
Go has no exceptions jumping out of your code. Functions that can fail return the result and an error; nil means "nothing went wrong". The convention is to check immediately. Ignore it, and your automation can report success after failing halfway: the silent failure that hurts later. Run a three-step deploy tool where step 2 fails.

A finished program: the challenge tracker

  
The chapter's running example grows one step at a time into a small, complete tool: a constant total, a name and a day count read with Scanln through pointers, a subtraction, formatted output with Printf. Fill in the inputs and run it.

  

    

      
package main

import "fmt"

func main() {
    challenge := "#90DaysOfDevOps"
    const daysTotal uint = 90
    var userName string
    var daysCompleted uint

    fmt.Println("Enter your name:")
    fmt.Scanln(&userName)
    fmt.Println("How many days have you completed?")
    fmt.Scanln(&daysCompleted)

    remaining := daysTotal - daysCompleted
    fmt.Printf("Thanks %v, %v days done.\n", userName, daysCompleted)
    fmt.Printf("%v days left in %v.\n", remaining, challenge)
}

      

        

        
        

        

      

    

  






  
8
One machine, binaries for every platform

  
Go compiles to a single static binary: no runtime to install on the target, which is why Go tools drop neatly into near-empty container images. Set GOOS and GOARCH before go build to target another platform from your laptop (go tool dist list shows them all). Wrap it in a script or Makefile and run it on every release.
