Kafka Connect: integration as configuration

Most data in Kafka comes from or goes to some other system. Hand-written producers and consumers for each one take time and break in a hundred edge cases. Kafka Connect, part of Apache Kafka, is a framework for that job: source connectors read an external system and produce to Kafka, sink connectors consume from Kafka and write elsewhere. Hundreds of connectors exist (databases, object stores, MQTT, JMS, warehouses). Its core idea is the partitioned stream: data that splits into independent streams, each with an offset to remember progress.

2

Workers, connectors and tasks

In distributed mode you run several worker processes with the same group.id; together they are one Connect cluster. They store configs, source offsets and status in three Kafka topics and share work through the same rebalance protocol as consumer groups. A connector splits its work into up to tasks.max tasks. (Standalone mode is a single local process without that state in Kafka: fine for development or reading local files.)

3

The worker configuration, line by line

Two kinds of configuration exist: the worker file, read at startup and valid for all connectors on it, and each connector's JSON, sent through the REST API and shared via the config topic. Click a line.

4

Driving Connect through its REST API

Everything is JSON over HTTP on port 8083. There is no real authentication or authorisation built in (only optional basic auth, which gives everyone full rights), so the authors want no humans on this API in production: let a CI/CD pipeline manage connectors. Try the calls on a simulated cluster.

When a record can't be processed

7

Polling a table versus reading its change log

The JDBC source connector polls with queries such as SELECT * FROM customers WHERE id > 3, using an incrementing ID and/or an update timestamp as its offset. A change data capture connector like Debezium instead reads the database's transaction log (for PostgreSQL: wal_level=logical and a user with the REPLICATION privilege) and sees every change. Run the same edits against both.
