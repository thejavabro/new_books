A three-broker lab on one laptop

Appendix A builds the environment used throughout the book: three brokers on one machine, never for production, but enough to watch Kafka survive failures. Each runs in KRaft dual mode (broker and controller in one process), so each needs two listeners. Appendix B adds Prometheus, exporters, Alertmanager and Grafana, each on its own port. Kafka runs on the JVM, so any major OS works; the authors tested macOS on Apple Silicon and Ubuntu 24.04, and recommend WSL on Windows. The book's examples use Kafka 3.9.0 (download names like kafka_2.13-3.9.0.tgz: Scala 2.13, Kafka 3.9.0) while covering 4.0 features such as KRaft-only operation, queues and the new rebalance protocol.

4

Prometheus and exporters

Prometheus scrapes metric endpoints on a schedule and stores time series with labels; you query them with PromQL and define alerts in rule files. Kafka exposes metrics via JMX, so each broker gets the Prometheus JMX Exporter as a Java agent (set through KAFKA_OPTS), serving HTTP on 9101–9103. Metric names depend on the exporter configuration. Click the components:

scrape_configs:
  - job_name: "kafka"
    static_configs:
      - targets: ["localhost:9101","localhost:9102","localhost:9103"]
# rules.yml
groups:
  - name: Kafka
    rules:
      - alert: Kafka Metrics Not Reachable
        expr: up{job="kafka"} == 0
        for: 1m

Inactive, pending, firing

That rule needs its expression to stay true for for: 1m before it fires. Prometheus evaluates every 15 s here. Stop a broker's exporter and advance time:

The Alertmanager (started on 9095, since 9093/9094 belong to brokers) groups alerts, routes them to recipients, can be silenced during maintenance, and supports inhibit rules that suppress secondary alerts while a root cause is firing, chosen carefully so nothing important is hidden.

6

Dashboards with Grafana

The Prometheus UI is for quick queries; Grafana builds dashboards from many data sources, with variables to switch between clusters or brokers, permissions, its own alerting and plugins. The Strimzi community's Kafka dashboards are an excellent start, but don't adopt them blindly, and get to know them before the night you need them. Good dashboards are the basis for good alerts and the first stop in an incident.
