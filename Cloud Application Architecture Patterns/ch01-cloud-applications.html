More than someone else's computer

The old joke says the cloud is just someone else's computer. The authors point out it is really lots of someone else's computers, managed so that you can grab capacity yourself, use it from anywhere and give it back when you are done. NIST's definition boils down to on-demand network access to a shared pool of configurable resources that can be provisioned and released quickly with little fuss. Nine qualities make that pool easy to share. Tap each to see what it means for you as an application designer.

Why it mattersEvery one of those qualities quietly breaks an assumption that traditional applications make. "Distributed" breaks the idea that your app runs on one machine; "shared" breaks the idea that it owns that machine; "elastic" breaks the idea that capacity is fixed.

3

Reliable apps on unreliable machines

Clouds run on cheap commodity servers and expect both planned maintenance and unplanned failures. The way out is not better hardware but more copies: if each copy is up 99% of the time and failures are independent, the chance that every copy is down at once shrinks fast. That is why a cloud application must be able to run as several identical replicas. Try it.

4

The root pattern: Cloud Application

ProblemHow can I build applications that take the most advantage of the cloud, for the best future-proofing and agility?

Experienced developers fall back on habits that suit a data center. The result is a "new" app that runs barely better in the cloud than an old one copied over as-is, followed by an endless game of Whack-a-Mole fixing problems the design invited.

SolutionArchitect the app as a Cloud Application: a set of services, preferably microservices, that uses backend services offered by the cloud platform and is reached by client applications running outside the cloud.
