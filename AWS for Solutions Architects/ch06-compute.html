Harnessing the Power of Cloud Computing

From virtual machines you size yourself to functions that run for milliseconds, AWS offers compute at every level of control. Pick the right one and pay only for what you use.

1

From servers to functions

The book makes a point about words: AWS says compute, not server, because compute now covers virtual machines, containers and functions. The book opens with an IDC figure: enterprises spend only about 15% of IT budgets on innovation and 85% on keeping existing infrastructure running, much of it servers. Slide along the spectrum: the further right, the less you manage and the finer you are billed.

2

Reading an EC2 instance name

EC2 offers more than 400 instance types, but the names follow a pattern: family, generation, optional attributes, then size. Under the hood the Nitro System moves networking, storage and security onto dedicated hardware so the instance gets nearly all of the host's CPU. Type a name to decode it.

3

T instances and CPU credits

T-family instances (T2/T3 Intel, T3a AMD, T4g Graviton) run at a low baseline and earn CPU credits while idle. When load spikes they spend credits to burst. Once credits run out they drop back to baseline (unless you enable "unlimited" mode and pay for the extra). Change the workload and watch the credit balance.

4

Paying for EC2

The book's e-commerce example mixes models: cover the steady daily baseline with Reserved Instances or a Savings Plan, handle predictable peaks with On-Demand, and push interruption-tolerant work to Spot. Size the fleet and see the monthly bill. (Discounts are typical upper bounds: RIs up to 72%, Spot up to 90%; actual rates vary.)

Assumes $0.10/hour On-Demand, 60% off for 1–3 year commitments, 70% off for Spot.

5

AMIs and EC2 best practices

Every instance starts from an Amazon Machine Image: the OS, architecture (x86 or Arm), launch permissions and a root-volume snapshot. Bake your own "golden AMI" with patches and agents so new instances start ready. Then follow the book's checklist.

6

Elastic Load Balancing and its rules

A load balancer spreads traffic over healthy targets in several AZs and stops sending to targets that fail health checks. On an ALB, a listener (protocol and port) holds rules. Each rule has conditions (host, path, query string, header), an action (forward to a target group, redirect, fixed response) and a priority. Send a request through this ALB.

7

Serverless compute: Lambda and Fargate

Serverless means no servers to provision or patch, automatic scaling, and paying only for use. Lambda runs a function in response to an event (an API call, an S3 upload, a queue message) for up to 15 minutes, billed per millisecond. Fargate runs containers without you managing the EC2 hosts underneath. Play with Lambda's bill.

Illustrative prices: $0.20 per million requests and $0.0000166667 per GB-second, before the free tier. A t3.small running all month costs roughly $15.
