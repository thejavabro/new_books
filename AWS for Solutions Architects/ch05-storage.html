Storage in AWS: Choosing the Right Tool for the Job

Block, file or object? Hot or cold? Storage choices drive both performance and the bill. This chapter sorts the AWS storage family by access pattern.

1

Three kinds of storage

Every storage service in this chapter fits one of three shapes. Block storage is a raw disk attached to one server (the cloud version of a SAN). File storage is a shared folder many servers mount over a network (like a NAS). Object storage keeps whole files with metadata in a flat namespace and serves them over HTTP. Tap one.

2

Choosing an EBS volume

EBS is a durable network hard drive for EC2 that persists when the instance stops and is replicated within its AZ. There are two SSD families, for random I/O measured in IOPS, and two HDD families, for big sequential reads measured in throughput. Describe your workload and get a recommendation.

SnapshotsEBS snapshots are incremental, point-in-time backups stored in S3. You can copy them across Regions and build new volumes from them. Unused old snapshots are the first place to look when trimming storage costs.

S3 storage classes and what they cost

S3 holds objects in buckets with eleven nines (99.999999999%) of designed durability. Every class has the same API; they differ in price per GB, retrieval fees, minimum storage duration and how many AZs hold the data. Set your data size and access rate to compare monthly cost.

Illustrative 2023 us-east-1 list prices (storage plus retrieval only; requests, monitoring and minimum-duration charges ignored). Check the AWS pricing page for real numbers.

5

Lifecycle rules and Intelligent-Tiering

If you know how data ages, write a lifecycle rule that moves (transitions) objects to cheaper classes and eventually expires them. If you don't know, let Intelligent-Tiering watch each object: after 30 days without access it moves to an infrequent tier, and back again the moment someone reads it, for a small monitoring fee per object. Step through a log file's life.

6

Versioning and replication

With versioning on, every overwrite keeps the old copy and a delete just adds a delete marker, so accidents can be undone. Each version is billed, so pair versioning with lifecycle rules that expire old versions. Try it.

Replication copies new objects to other buckets automatically: same-Region or cross-Region, and with multi-destination replication to several buckets or accounts at once, for compliance, latency or disaster recovery. S3 Object Lambda runs your code on a GET to change data on the fly, for example redacting personal data before an analytics app reads it.

7

Making S3 fast

S3 scales per prefix: each prefix supports thousands of requests per second (3,500 writes and 5,500 reads at the time of writing). Spread hot keys across prefixes and parallelize connections. Add a cache layer where reads repeat.

8

Protecting data in S3

Most S3 breaches are configuration mistakes, not hacks. Tick the controls in place for a bucket that holds customer data.

9

Storage Gateway and AWS Backup

Storage Gateway is a VM or hardware appliance on-premises that speaks familiar protocols locally and stores data in AWS, with a local cache for speed. Match each need to the gateway type.

Which gateway?

AWS Backup centralizes backup across EC2, EBS, EFS, FSx, RDS, DynamoDB, Storage Gateway and more. You write a backup plan (schedule, retention, copy to another Region or account) and assign resources by tag.
