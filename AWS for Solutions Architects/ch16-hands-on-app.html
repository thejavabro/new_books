The AWSome Store

The final chapter builds a serverless e-commerce site for a fictional shop, the AWSome Store, using pieces from every earlier chapter. Design starts with Domain-Driven Design (Chapter 14): split the business into bounded contexts (order management, payment processing, fulfillment, shipping, customer management), then identify aggregates (an order with its customer and products), domain services (calculate a total, process a payment) and domain events (order placed, product out of stock). Each context becomes a microservice. Tap any component of the architecture.

Cognito: two pools, two jobs

      
A user pool is the customer directory: sign-up, sign-in, MFA, groups (such as "customers" and "admins") and app clients, returning JWT tokens that API Gateway can verify. An identity pool exchanges those tokens for temporary AWS credentials, with separate IAM roles for authenticated and guest users, when the browser must call AWS directly (for example, uploading a review photo to S3).

The order context's code mirrors the domain: Order, OrderItem, Payment and Customer classes with methods for the actions on them. Configuration goes in environment variables for small values and in Parameter Store or Secrets Manager for shared or sensitive ones. Here is a tiny illustrative handler:

  
// placeOrder.js (illustrative)
export const handler = async (event) => {
  const { customerId, items } = JSON.parse(event.body);
  const order = Order.create(customerId, items);        // domain logic
  await orders.save(order);                             // repository → DynamoDB
  await bus.publish("OrderPlaced", order.toEvent());    // EventBridge
  return { statusCode: 201, body: JSON.stringify({ orderId: order.id }) };
};

DevOps: a pipeline with a rollback plan

  
Code lives in a repository; CodePipeline orchestrates CodeBuild (build and unit test) and deployment (CloudFormation or SAM, with CodeDeploy shifting Lambda traffic gradually). Run the pipeline, or inject a bug.

  

    

    

    

  






  
8
Logging and monitoring

  
Create a CloudWatch log group for the app, turn on X-Ray tracing for each Lambda function, and set alarms on the error rate. The book's tips: log in structured JSON, centralize logs, set retention periods, alarm on what users feel (errors, latency), and review dashboards regularly.
