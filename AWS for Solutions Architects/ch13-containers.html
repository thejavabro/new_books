Containers in AWS

Containers package an app with everything it needs and run it the same way everywhere. AWS offers several ways to orchestrate them; the choice is how much you want to manage.

1

Containers: ship the whole kitchen

A container packages an application with everything it needs (code, runtime, libraries, settings) so it runs the same on a laptop, in a test environment or in production. The book's analogy is shipping containers: a standard box that any ship, train or truck can carry. Companies like Netflix built their platforms this way.

AdvantagesSupports modern microservice apps · less wasted infrastructure (dense packing) · simple, isolated and portable · faster development and deployment.
DisadvantagesSlightly slower than bare metal (overlay networking, shared kernel overhead) · ecosystem inconsistencies between Docker and other tools · more moving parts to secure and monitor.
2

Containers versus virtual machines

A VM virtualizes hardware: each VM carries a full guest OS on top of a hypervisor. A container virtualizes the operating system: containers share the host kernel and include only the app and its libraries. That makes them smaller and quicker to start. (In AWS you usually run containers on VMs, that is, EC2 instances.) Size the host and compare.

Kubernetes: desired state, always

  
Kubernetes, open-sourced by Google, is the most popular orchestrator. Its core idea is a control loop: you declare the desired state ("3 replicas of the web pod"), and controllers keep working to make the current state match. Click a pod to kill it, or change the replica count.

6
Amazon EKS: managed Kubernetes

  
EKS runs the Kubernetes control plane (API servers and etcd) across three AZs, patched and scaled by AWS, and upgrades versions for you. It is certified upstream Kubernetes, so community tools work unchanged. You choose how to run the worker nodes.
