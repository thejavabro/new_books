Getting Started with Terraform

In a few dozen lines of HCL you go from an empty AWS account to a web server, then a self-healing cluster behind a load balancer. Along the way you meet the whole core workflow: init, plan, apply, destroy.

Before the first line of code

Every example in the book runs on AWS, because it is the most popular cloud and its free tier covers most of what you'll deploy. Three habits matter from day one:

$ export AWS_ACCESS_KEY_ID=(your access key id)
$ export AWS_SECRET_ACCESS_KEY=(your secret access key)
# Terraform also reads ~/.aws/credentials and IAM roles, like any AWS tool
2

Anatomy of a resource

Terraform code is written in the HashiCorp Configuration Language (HCL) in .tf files. You first configure a provider, then declare resources. Tap each underlined part.

provider "aws" {
  region = "us-east-2"
}

resource "aws_instance" "example" {
  ami           = "ami-0fb653ca2d3203ac1"
  instance_type = "t2.micro"

  tags = {
    Name = "terraform-example"
  }
}
Use the docsProviders expose hundreds of resources with dozens of arguments each. Nobody memorizes them; the book's advice is to keep the provider documentation open while you write.
3

init, plan, apply: reading the diff

terraform init downloads provider code into a .terraform folder. terraform plan shows what will change without touching anything, like git diff for your cloud. terraform apply shows the same plan and asks for yes. Make edits to the server above and watch the plan change.


    
+ create~ update in place- destroy-/+ replace

  

  
Some arguments, such as tags, can be changed on a live server. Others, such as the image, force Terraform to destroy the old server and create a new one. The plan tells you which before anything happens.






  
4
A web server, and the dependency graph

  
To serve HTTP, the server gets a tiny User Data script that runs on first boot, plus a security group, because AWS blocks all traffic in and out of an instance by default. The instance points at the group with a reference: aws_security_group.instance.id. That reference is an implicit dependency, so Terraform knows to create the group first.

  


resource "aws_security_group" "instance" {
  ingress {
    from_port   = 8080
    to_port     = 8080
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }
}

resource "aws_instance" "example" {
  # ...
  vpc_security_group_ids = [
    aws_security_group.instance.id
  ]
  user_data = <<-EOF
    #!/bin/bash
    echo "Hello" > index.html
    nohup busybox httpd -f -p 8080 &
    EOF
}

Why port 8080?Listening on ports below 1024 needs root. A compromised server running as root hands the attacker root too, so the examples use a high port and an unprivileged process.






  
5
Input variables and outputs

  
Port 8080 now appears twice, which breaks the Don't Repeat Yourself principle. An input variable fixes it. A variable can have a description, default, type, validation rules, and sensitive = true to hide it in logs. You read it with var.server_port. Where does the value come from? Switch the sources on and off.

  

    


variable "server_port" {
  description = "Port for HTTP requests"
  type        = number
  default     = 8080
}

output "public_ip" {
  value = aws_instance.example.public_ip
}

      

        
        
        
      

    

    

  

  
Output variables work the other way: after apply, Terraform prints them, and terraform output public_ip fetches one later. Handy for scripts that need the IP of what you just built.






  
6
A cluster that heals itself

  
One server is a single point of failure. An Auto Scaling Group (ASG) launches a cluster from a launch configuration, keeps its size between min_size and max_size, replaces failed servers and spreads them across subnets. A data source (data "aws_subnets") looks up the subnets of the Default VPC so you don't hardcode them. Tap a server to kill it.

  

    

    

    
Tap a running server to terminate it.

  

  
create_before_destroyLaunch configurations can't be changed once created, and the ASG keeps pointing at the old one, so a plain replace would fail. Adding lifecycle { create_before_destroy = true } makes Terraform build the replacement first, repoint the ASG, then delete the old one.






  
7
One address in front of many servers

  
Users need a single address, not one IP per server. An Application Load Balancer (ALB) has three parts: a listener on a port, listener rules that match requests, and a target group of servers it health-checks. Step through a request.

  

    

    

  

  
The ALB also gets its own security group: it must allow inbound port 80 and outbound traffic so its health checks can reach the servers. Setting health_check_type = "ELB" on the ASG means it replaces servers the load balancer marks unhealthy, not just ones that have crashed.






  
8
Cleaning up

  
Because Terraform tracks everything it made, removing it all is one command. Destroy has no undo, so run it only on experiments.
