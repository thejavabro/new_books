Terraform is declarative, yet it still lets you loop, branch and roll out new code without downtime. Each trick has sharp edges, and this page lets you poke at them safely.

Four ways to loop in a declarative language

HCL has no for statement. Instead, it has four looping tools, each aimed at a different job.

count versus for_each: the deletion test

Create three IAM users from a list. With count, Terraform identifies each copy by its position: aws_iam_user.example[1]. With for_each, by its key: aws_iam_user.example["trinity"]. Now remove a user from the middle of the list. Tap a name to remove or restore it.

count = length(var.user_names)

for_each = toset(var.user_names)

resource "aws_iam_user" "example" {
  count = length(var.user_names)
  name  = var.user_names[count.index]
}
resource "aws_iam_user" "example" {
  for_each = toset(var.user_names)
  name     = each.value
}

count has a second limit: it can't loop over inline blocks. for_each can, and the result is a map, which is easier to work with. Both work on modules too, since Terraform 0.13.

for expressions transform values

  
Need a single value computed from a list, rather than many resources? A for expression works like a list comprehension in Python. Pick an expression.

  

    
    

    

  

  
Strings have their own looping tool, the for string directive: %{ for name in var.names }${name}, %{ endfor }. Add a tilde, as in %{~ ... ~}, to strip the whitespace and newlines around a directive.

If-statements without if

  
The same tools double as conditionals. The classic trick: count = var.enable ? 1 : 0. One copy if true, none if false. The book uses it so the shared cluster module can enable auto scaling in production only. Toggle the inputs.

Zero-downtime deployment

  
You've baked a new image or changed the User Data. How do you roll it across the cluster without users seeing errors? The book's first technique uses create_before_destroy: name the ASG after the launch configuration, so a new configuration forces a whole new ASG, which comes up next to the old one. Step through it.

  

    

    

  


resource "aws_autoscaling_group" "example" {
  name             = "${var.cluster_name}-${aws_launch_configuration.example.name}"
  min_elb_capacity = var.min_size   # wait for this many healthy servers
  lifecycle { create_before_destroy = true }
}

  
The simpler alternative now is instance refresh, built into AWS: add an instance_refresh block and the ASG replaces servers gradually, keeping a minimum percentage healthy. It doesn't need the naming trick and plays well with auto scaling policies.
