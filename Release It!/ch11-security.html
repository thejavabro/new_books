Security is baked in, not sprinkled on

Breaches cost fraud, extortion, fines, cleanup and reputation, and can end careers up to the CEO. In 2017 ransomware disrupted hospitals in dozens of countries, one credit bureau lost the identities of 145 million people, and an email provider disclosed three billion stolen accounts. Attacks also plant data, such as fake identities or shipping documents (possibly behind a wave of nut thefts in California). Having a security team doesn't take you off the hook. This chapter tours the OWASP Top 10 (the 2017 release candidate), least privilege, and handling of configured passwords.

2

Injection: don't bash strings together

Injection attacks a parser fed with user input. The classic: a "name" that closes your SQL string and appends its own statement. Every SQL library supports placeholders; there's no excuse. Type a name and compare.

String concatenation
Placeholder

"From a user" includes data stored earlier by a user. XML has its own trap: external entities (XXE) that make the parser read a local file or URL and maybe echo it back in an error. Most parsers allow this by default; configure them safely, and don't "fix" it by parsing XML with regular expressions.

3

Broken authentication and session management

Session IDs in URLs leak to every proxy, log and person who copies a link. One retailer's marketing email included the marketer's own session ID in a deep link; thousands of users shared one session and the front end collapsed. Attackers can also hijack (steal), fix (plant their ID on a victim who then logs in) or predict session IDs. Check the safe practices.

Good practice or bad?

Beware the pie crustThe old model: authenticate at the edge, then trust anything inside. Boundaries are blurry now. Internal services must authenticate callers too, and never trust an IP address. Use first-party (your own credential store) or third-party proofs (Kerberos, NTLM, OAuth), and check a proof wasn't intercepted and replayed.
4

Cross-site scripting

XSS is injection into HTML: a service echoes user input into a page without escaping. A crafted search term closes your attribute and adds a script that sends the user's cookie elsewhere. Escape on output, and prefer templates that escape by default.

5

Broken access control

Having a URL is not permission to see what it points to. Sequential IDs in URLs (/customers/1023) invite probing. Use unguessable IDs, generic session-relative URLs like /users/me, or a per-session map from random to real IDs, and authorize every request. Also: answering 403 for "exists but forbidden" and 404 for "doesn't exist" leaks which records exist. Probe this API.

Directory traversal

Build a file path from user input and ../ walks out of your directory, to read the password file or, on upload, overwrite something executable. Treat the client's filename as a label stored in the database; name the real file with a random key.

6

Security misconfiguration and sensitive data

Mostly omissions: default admin passwords, unneeded features left on, admin consoles exposed, sample apps in production, servers listening on every interface, shared group accounts. Early in 2017 over 20,000 internet-exposed databases with default credentials were wiped and held for ransom. The install script is the first step of installation, not the last. Container base images that bundle databases bring their own default passwords.

For sensitive data, attackers don't break your strongest crypto; they find the stolen laptop with a spreadsheet extract, or plain HTTP inside the "pie crust". Don't store what you don't need (tokenize card numbers), use HTTP Strict Transport Security, drop SHA-1, hash and salt passwords, encrypt sensitive columns and decrypt based on the user's authorization, and keep keys in a key management service or vault.

The principle of least privilege

Each process gets the least privilege it needs, and that never means root or administrator. Any hole in root-level software is critical, and once root is cracked, the only safe fix is wipe and reinstall. Give each application its own user. The usual excuse, binding a port below 1024, disappears behind a load balancer. Containers help isolate apps, but a fat image with a full OS has its own attack surface and doesn't get patched by IT's tools: treat images as perishable, rebuilt automatically from an updated base, on a timer even for quiet apps.

9

Configured passwords

Servers can't have someone type the database password at every start, so it lives somewhere on disk. Minimum: keep it separate from other config and outside the install directory (operations once zipped up a whole install folder and sent it to developers), readable only by the app's user, maybe read before the process drops privileges. Better: a vault or key service, so the encrypted secret and its key aren't stored together; watch file permissions with intrusion detection; wipe secrets from memory quickly and disable core dumps, since a memory dump contains every password in memory.

Security is an ongoing processFrameworks and one-time reviews don't cover the Top 10. Encryption in transit and at rest, authentication and authorization are cross-cutting architecture decisions. New attacks appear constantly, and new technology has new holes, so you must be able to patch and redeploy at a moment's notice. Two secure components don't automatically make a secure system.
