Processes on Machines

Code, config and connection, and what to call things

An engine needs fuel, fire and air; an instance needs code, config and connection. First, words. "Reboot the server" could mean one process or a whole machine. The book pins down six terms; tap each.

2

Code: an unbroken chain of custody

You must know exactly what code runs on each instance, and nobody unauthorized should be able to slip code in. Each link below is a practice; tap one to see what breaks if you skip it.

3

Layers of stucco versus immutable infrastructure

Configuration management tools (Chef, Puppet, Ansible) apply changes to running machines. Over time, side effects pile up that no script describes: a package's post-install step tweaks network settings, the next version changes half of them back, and now the machine's state depends on its history. Failed runs leave machines half-changed. The alternative: start from a known base image, apply a fixed set of changes, and never patch it. To change anything, build a new image and throw the old machine away.

4

Configuration is a user interface

Hostnames, ports, paths, keys, passwords: get one wrong and the system breaks, maybe only at 1 a.m. when daylight saving time changes. Configuration carries hidden linkages and complexity, the two big causes of operator error, and it is the interface for developers and operators. Guidelines:

Name properties by function

A property called hostname invites the question "which host?" Name it for what it does. Pick the better name.

5

Transparency: hear the engine

Ship engineers hear trouble in the engines. Our servers are silent, distant boxes, so we must build in what the book calls transparency: the ability to see historical trends, present conditions, instantaneous state and future projections. Transparent systems are easier to debug, so they mature faster; without it, decisions get made by whoever has the most clout, and the system decays release by release. It must be designed in, and it must look beyond one server. One retailer sped up its nightly batch by two hours with no effect, because another job finished later anyway. Another found, only once all cache stats were on one page, that every server was flushing every other server's cache.

Black boxOutside the process, observing what's visible: log scrapers, probes. Can be added later by operations. Plain-text logs help.
White boxInside the process: agents and APIs that emit specific events and metrics. Must be built in; couples you to a provider, but gives far more clarity.

Keep monitoring an exoskeleton, not woven into the code: alert thresholds and health roll-ups are policies that change at a different rate, so they live outside the instance.

6

Logging for the people who read logs

Log files remain the most reliable, loosely coupled source of information. Put them somewhere configurable, off the install directory (or on standard output in containers). Write them for operations, not for yourself: ERROR means someone must act. Set the level for each event.

Voodoo operationsAn operator saw "Data channel lifetime limit reached. Reset required." and failed over the production database, every week, during peak hours, for six months. The message was a forgotten debug line about rotating an encryption key, which the app reset by itself. Once, by coincidence, it was the last line before a real database crash. Ambiguous wording plus a coincidence became ritual. Strip debug levels from production configs in the build; write messages that say who must do what; include a transaction or request ID to grep for; log state transitions.
7

Instance metrics and health checks

An instance can't judge system health, but it should emit metrics for central collection, whether as stats lines in a log or through a hosted service. (Netflix engineers joke that Netflix is a monitoring system that streams movies as a side effect.) For a quick summary, give each instance a health check: more than "yup, running". The load balancer uses it to detect crashes and to know when a new instance has finished starting. Toggle conditions to see what it reports.
