Functional style in Java, in a nutshell

Java is not a purely functional language like Haskell, but since Java 8 it supports a functional style through lambdas, functional interfaces, streams and Optional. Three ideas carry the whole chapter. Pure functional programming adds rules on top: no external state, no side effects, immutable variables and a preference for recursion over loops.

The parts of a lambda, and how it shrinks

A lambda is an anonymous function with three parts: a parameter list, the arrow, and a body (an expression, or a block with return). It can only be used where a functional interface is expected, an interface with exactly one abstract method, which gives the lambda its type. Which interface fits?

  
@FunctionalInterface                  // optional, but the compiler then checks it
interface Discount {
    double apply(double price);        // exactly one abstract method
    default Discount then(Discount next) { return p -> next.apply(apply(p)); }  // defaults are fine
}
Discount tenOff = p -> p * 0.9;
double v = tenOff.then(p -> p - 5).apply(100);   // 85.0

Streams: intermediate, terminal, and lazy

  
A stream pipeline has a source, zero or more intermediate operations (filter, map, peek, sorted…) that return a new stream, and one terminal operation (collect, forEach, findFirst, count…) that produces a result. Intermediate operations are lazy: nothing runs until the terminal operation pulls, and then each element travels through the whole pipeline before the next one starts. Short-circuiting terminals stop early. Watch it.

  

    

    

    

    

  

  
Collections versus streamsA collection stores elements and can be iterated many times. A stream stores nothing, computes on demand, can be consumed only once, and does not modify its source.

map() versus flatMap()

  
map transforms each element into exactly one element. When each element turns into a stream of elements, map gives you a stream of streams; flatMap flattens them into one stream.

  

    

    

    

  






  
6
Parallel streams, findFirst and findAny

  
parallelStream() splits the source with a Spliterator into chunks processed on the common ForkJoinPool, then combines results. It helps for large, CPU-bound, easily split data with no shared mutable state; it hurts for small inputs, I/O, or order-sensitive work. In parallel, findAny may return whichever chunk finishes first, while findFirst must respect encounter order.

Optional: a box that may be empty

  
Optional is a return type that forces the caller to think about "no result". Use it for return values, not fields or parameters. Never call get() without checking; prefer orElse, orElseGet (lazy), orElseThrow, map and ifPresent.

  

  
String city = findUser(id)                 // Optional<User>
        .map(User::address)                 // Optional<Address>
        .map(Address::city)                 // Optional<String>
        .orElse("unknown");
