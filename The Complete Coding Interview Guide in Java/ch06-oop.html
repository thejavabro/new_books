Object-Oriented Programming

Interviewers ask about objects in two ways: define the concept crisply, then prove it by designing a small system. Both rest on the same ideas: hide what changes, depend on abstractions, and keep each class to one job.

Objects, classes and the four pillars

An object is a thing with state (fields) and behavior (methods); a class is the blueprint objects are made from. Interviewers want crisp definitions plus a small example, so practise both. Press new a few times: one class, many objects, each with its own state.

public class Car {
    private final String plate;   // state
    private int speed;

    public Car(String plate) { this.plate = plate; }

    public void accelerate(int delta) {   // behavior
        speed = Math.min(speed + delta, 200);
    }
    public int speed() { return speed; }
}

On top of that sit the four pillars. Pick one to see a minimal Java example and the one-line definition you could say in an interview.

Polymorphism: who answers the call?

  
With overriding, the JVM picks the method at runtime from the object's actual class (dynamic binding). With overloading, the compiler picks the method from the declared types of the arguments (static binding). Static, private and final methods are also bound at compile time. Choose a declared type and a runtime object, and watch the call resolve.

  

    

    

    

  

  
class Shape  { void draw() { … } static String id() { return "shape"; } }
class Circle extends Shape { @Override void draw() { … } static String id() { return "circle"; } }
class Square extends Shape { @Override void draw() { … } }
class Printer {
    static void print(Shape s)  { … }   // overloads: chosen by the
    static void print(Circle c) { … }   // DECLARED type at compile time
}

Association, aggregation, composition

  
All three describe one object using another. The difference is ownership and lifetime. Association: two independent objects know each other (a pilot and a plane). Aggregation: a weak "has-a" where the part outlives the whole (a team and its players). Composition: a strong "has-a" where the part dies with the whole (a car and its engine, created inside the car). Destroy the owner and see what survives.

Object design problems: ask first, then model

  
The second half of the chapter is ten "design the main classes of…" problems: a jukebox, a vending machine, a deck of cards, a parking lot, an online reader, a hash table, a file system, a tuple, a cinema booking system and a circular byte buffer. Each one starts with what to ask, because the interviewer deliberately leaves the requirements vague. Below are three of them modelled and running.

  
Parking lot

  
Questions to ask: single or multi-level? Are all spots the same? What vehicles? Paid? Tickets? Assume one level with small, medium and large spots; a motorbike fits anywhere, a car needs medium or large, a van needs large. Park vehicles and watch the "find the smallest spot that fits" rule.

  

    
enum Size { SMALL, MEDIUM, LARGE }

abstract class Vehicle {
    abstract Size size();
}
class Car extends Vehicle { Size size() { return Size.MEDIUM; } }

class ParkingLot {
    private final List<Spot> spots;

    Optional<Ticket> park(Vehicle v) {
        return spots.stream()
            .filter(s -> s.isFree() && s.size().compareTo(v.size()) >= 0)
            .min(Comparator.comparing(Spot::size))   // smallest that fits
            .map(s -> s.occupy(v));
    }
}

Circular byte buffer

  
Ask: resizable? (Yes, in the chapter.) The core is two indexes that wrap around with modulo; when the buffer fills, grow it and unroll the contents.

  

    

      

    
class CircularByteBuffer {
    private byte[] buf = new byte[8];
    private int head, tail, size;   // read at head, write at tail

    void put(byte b) {
        if (size == buf.length) grow();
        buf[tail] = b;
        tail = (tail + 1) % buf.length;
        size++;
    }
    byte get() {
        if (size == 0) throw new IllegalStateException("empty");
        byte b = buf[head];
        head = (head + 1) % buf.length;
        size--;
        return b;
    }
    private void grow() {
        byte[] n = new byte[buf.length * 2];
        for (int i = 0; i < size; i++) n[i] = buf[(head + i) % buf.length];
        buf = n; head = 0; tail = size;
    }
}
