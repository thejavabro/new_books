Recursion and Dynamic Programming

Many interview problems are the same problem nested inside itself. Recursion expresses that directly; dynamic programming makes it fast by remembering answers to the sub-problems it has already solved.

Recursion in a nutshell: the call stack

A recursive method calls itself on a smaller version of the problem until it reaches a base case it can answer directly. Each call waits on the call stack until the smaller call returns. Forget the base case and the stack keeps growing until a StackOverflowError. Step through sum(4) and watch frames pile up, then unwind.

int sum(int n) {
    if (n == 0) return 0;        // base case
    return n + sum(n - 1);       // smaller problem
}

Dynamic programming: memoization and tabulation

When a recursion solves the same sub-problem many times, dynamic programming saves the answers. Memoization (top-down) keeps the recursive code and adds a cache. Tabulation (bottom-up) drops recursion and fills a table from the smallest case upward. The staircase problem shows both: someone climbs n steps hopping 1, 2 or 3 at a time; in how many ways can they reach the top?

// top-down: recursion + cache
long ways(int n, long[] memo) {
    if (n < 0) return 0;
    if (n == 0) return 1;
    if (memo[n] == 0)
        memo[n] = ways(n - 1, memo) + ways(n - 2, memo) + ways(n - 3, memo);
    return memo[n];
}

// bottom-up: fill a table
long waysTab(int n) {
    long[] dp = new long[Math.max(n + 1, 3)];
    dp[0] = 1; dp[1] = 1; dp[2] = 2;
    for (int i = 3; i <= n; i++)
        dp[i] = dp[i - 1] + dp[i - 2] + dp[i - 3];
    return dp[n];
}
3

Robot grid: count paths around obstacles

A robot starts at the top-left of an m × n grid and may only move right or down. Some cells are off-limits. The recursive idea: the number of ways to reach a cell is the ways to reach the cell above plus the ways to reach the cell on the left. Filling those numbers in a table is the DP version, and following non-zero cells back from the end recovers one actual path. Tap cells to add or remove walls.

long paths(boolean[][] wall) {
    int m = wall.length, n = wall[0].length;
    long[][] dp = new long[m][n];
    for (int r = 0; r < m; r++)
        for (int c = 0; c < n; c++) {
            if (wall[r][c]) continue;          // stays 0
            if (r == 0 && c == 0) { dp[r][c] = 1; continue; }
            long up = r > 0 ? dp[r - 1][c] : 0;
            long left = c > 0 ? dp[r][c - 1] : 0;
            dp[r][c] = up + left;
        }
    return dp[m - 1][n - 1];
}

Tower of Hanoi

Move n disks from rod A to rod C, one at a time, never placing a larger disk on a smaller one. The recursive insight: move the top n-1 disks out of the way to B, move the biggest to C, then move the n-1 disks from B onto it. That gives 2n − 1 moves.

void hanoi(int n, char from, char via, char to) {
    if (n == 0) return;
    hanoi(n - 1, from, to, via);   // clear the way
    System.out.println("disk " + n + ": " + from + " -> " + to);
    hanoi(n - 1, via, from, to);   // rebuild on top
}
5

Josephus: who survives the circle?

n people stand in a circle; counting around, every k-th person is removed until one remains. Simulating with a queue is easy to explain; the recursion is elegant. If J(n) is the survivor's 0-based position, after the first removal the circle restarts k places later with n-1 people, so J(n) = (J(n-1) + k) % n, with J(1) = 0.

int josephus(int n, int k) {        // 1-based answer
    return n == 1 ? 1 : (josephus(n - 1, k) + k - 1) % n + 1;
}

// queue simulation, same answer
int josephusQueue(int n, int k) {
    Deque<Integer> q = new ArrayDeque<>();
    for (int i = 1; i <= n; i++) q.add(i);
    while (q.size() > 1) {
        for (int i = 1; i < k; i++) q.add(q.poll()); // skip k-1
        q.poll();                                     // remove k-th
    }
    return q.peek();
}
6

Coins: count the ways to make change

How many ways can you make n cents from quarters, dimes, nickels and pennies? Order does not matter (5+1 equals 1+5), so process one coin type at a time: ways[a] += ways[a - coin]. Each row below adds one coin type to the table.

long change(int n, int[] coins) {
    long[] ways = new long[n + 1];
    ways[0] = 1;                          // one way to make 0
    for (int coin : coins)
        for (int a = coin; a <= n; a++)
            ways[a] += ways[a - coin];
    return ways[n];
}

Five towers: backtracking on a 5 × 5 grid

Build one tower on each row of a 5 × 5 grid so that no two towers share a column or a diagonal (the queens puzzle in disguise). Backtracking places a tower in the current row, recurses to the next row, and undoes the placement when the next row has no safe cell. Watch the search find the first solution, including its dead ends.

boolean place(int row, int[] colOf, int n) {
    if (row == n) return true;               // all rows done
    for (int c = 0; c < n; c++) {
        if (safe(row, c, colOf)) {
            colOf[row] = c;                  // try
            if (place(row + 1, colOf, n)) return true;
        }                                    // else: undo, next c
    }
    return false;                            // backtrack
}
boolean safe(int row, int c, int[] colOf) {
    for (int r = 0; r < row; r++)
        if (colOf[r] == c || Math.abs(colOf[r] - c) == row - r) return false;
    return true;
}

Word break (a famous Google problem)

Can a string be split into dictionary words? ok[i] is true when the first i characters can be split. It is true if some earlier ok[j] is true and the piece from j to i is a word. Without the table, plain recursion re-checks the same suffixes exponentially often.

Dictionary: 
boolean wordBreak(String s, Set<String> dict) {
    boolean[] ok = new boolean[s.length() + 1];
    ok[0] = true;                                  // empty prefix
    for (int i = 1; i <= s.length(); i++)
        for (int j = 0; j < i && !ok[i]; j++)
            ok[i] = ok[j] && dict.contains(s.substring(j, i));
    return ok[s.length()];
}
