Bit Manipulation

Every Java int is 32 switches. Once you can read, set, clear and shift them with masks, a family of interview problems collapses into a line or two of code.

1

A Java int is 32 switches

An int is 32 bits in two's complement. The leftmost bit (MSB) is the sign: 0 for non-negative, 1 for negative. To negate a number, invert all the bits and add one, which is why -1 is all ones. Type a number or click any bit to flip it.

2

Bitwise and shift operators

& keeps a bit only if both are 1. | sets it if either is 1. ^ sets it if they differ. ~ flips every bit. << shifts left, filling with zeros (multiply by 2k). >> shifts right copying the sign bit (divide by 2k, rounding down). >>> shifts right filling with zeros, so negatives become large positives. Summing binaries without +

  
On paper, binary addition works like decimal: 1 + 1 = 10, write 0 and carry 1. In code, XOR gives the sum without carries and AND shifted left gives the carries. Repeat until there is nothing left to carry. Step through it.

  

    

    

    

  

  
int add(int q, int p) {
    while (p != 0) {
        int carry = (q & p) << 1;   // where both are 1, carry left
        q = q ^ p;                    // sum without carries
        p = carry;
    }
    return q;
}
// subtraction: add(q, add(~p, 1))   multiplication: shift-and-add

Power set: every subset is a binary number

  
A set of n elements has 2n subsets. Count from 0 to 2n − 1: bit i of the counter says whether element i is in the subset. No recursion needed.

  

    

    
List<List<Character>> powerSet(char[] set) {
    List<List<Character>> all = new ArrayList<>();
    for (int mask = 0; mask < (1 << set.length); mask++) {
        List<Character> sub = new ArrayList<>();
        for (int i = 0; i < set.length; i++)
            if ((mask & (1 << i)) != 0) sub.add(set[i]);
        all.add(sub);
    }
    return all;
}

A float in binary (IEEE 754)

  
The last challenge converts a float to its bits and back. Float.floatToIntBits exposes 1 sign bit, 8 exponent bits (stored with a bias of 127) and 23 fraction bits; Float.intBitsToFloat reverses it. Try 0.1 and see why it is not exact.
