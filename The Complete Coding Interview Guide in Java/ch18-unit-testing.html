Unit testing in a nutshell

A unit test checks one small unit of code (usually a method or class) in isolation from databases, networks and other classes, which are replaced by test doubles. Unit tests are the wide base of the testing pyramid: many, fast and cheap. Integration and end-to-end tests sit above them, fewer and slower. Interviewers expect Java developers to write their own tests, usually with JUnit and Mockito. Tap a layer.

Arrange, Act, Assert

Structure every test in three blocks: Arrange the objects and inputs, Act by calling the one method under test, Assert the outcome. One act per test keeps failures easy to diagnose. Label each line below.

Test fixtures and the @Before / @After lifecycle

A fixture is the fixed state a test runs against: objects, files, data. Lifecycle annotations build it and tear it down. Per-test methods run around every test, so each starts clean; per-class methods run once and must be static (in JUnit 5's default lifecycle). Play a class with two tests.

class CartTest {
    private Cart cart;

    @BeforeAll static void startDb()  { /* once, expensive */ }
    @BeforeEach void newCart()        { cart = new Cart(); }    // fresh fixture per test

    @Test void emptyCartTotalsZero()  { assertEquals(0, cart.total()); }

    @Test void addingItemRaisesTotal() {
        cart.add(new Item("pen", 3));                            // act
        assertEquals(3, cart.total());                           // assert
    }

    @AfterEach void clear()           { cart = null; }
    @AfterAll static void stopDb()    { }
}
5

Testing exceptions

In JUnit 5, assertThrows both checks the type and returns the exception so you can assert on its message. JUnit 4 offered @Test(expected = …), which cannot tell which line threw, and the ExpectedException rule.

@Test
void rejectsNegativeQuantity() {
    Cart cart = new Cart();
    IllegalArgumentException e = assertThrows(IllegalArgumentException.class,
            () -> cart.add(new Item("pen", -1)));
    assertEquals("quantity must be positive", e.getMessage());
}
6

Mocking versus stubbing

Both replace a real dependency. A stub just returns canned answers so the code under test can run: you assert on the result (state). A mock also records how it was called: you verify the interaction (behavior). Mockito does both. Toggle to see what the test checks.
