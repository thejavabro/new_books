Big O Analysis of Algorithms

Big O describes how the cost of an algorithm grows as the input grows. It ignores constants and small terms on purpose, so you can compare approaches on a whiteboard in seconds.

1

Ordering versus downloading

The chapter opens with a movie. Downloading one takes half a day; ordering it takes a day to ship. Download wins. Now add a large box set: downloading grows with the size, but shipping still takes one day however much you order. Shipping time is constant, O(1). Download time is proportional to the size, O(n). Big O is exactly this: how the cost grows as the input grows, not how fast it is for one small case.

2

The growth curves you must recognize

Constants stop mattering once n is large. What matters is the shape of the curve. Slide n and switch the scale: the gap between n log n and n² is the difference between a sort that finishes and one that does not.

Time column assumes 100 million simple operations per second.

3

Best case, worst case, expected case

The same algorithm can do very different amounts of work depending on the input. Linear search finds the target at the first position (best case, O(1)), at the end or not at all (worst case, O(n)), or on average halfway (expected case, still O(n)). In interviews, Big O normally means the worst case, and a break that may never trigger does not change it.

4

Four rules that simplify every answer

// added: one loop, then another -> O(a + b)
for (int x : a) work(x);
for (int y : b) work(y);

// multiplied: a loop inside a loop -> O(a * b)
for (int x : a)
    for (int y : b) work(x, y);
// halving -> O(log n)
int lo = 0, hi = n - 1;
while (lo <= hi) {
    int mid = (lo + hi) >>> 1;
    if (arr[mid] == key) return mid;
    if (arr[mid] < key) lo = mid + 1; else hi = mid - 1;
}
5

Recursive runtimes: branches to the power of depth

A function that calls itself twice per level builds a tree. Its node count is roughly branchesdepth, so two calls on n-1 give O(2n). Memoization stores each answer the first time, collapsing the tree to one call per distinct argument: O(n). Grow n and toggle the cache.

int fib(int n) {                       // O(2^n)
    return n < 2 ? n : fib(n - 1) + fib(n - 2);
}
int fibMemo(int n, int[] memo) {       // O(n)
    if (n < 2) return n;
    if (memo[n] == 0) memo[n] = fibMemo(n - 1, memo) + fibMemo(n - 2, memo);
    return memo[n];
}
Careful with depthVisiting every node of a balanced binary tree recursively has 2 branches and depth log n. 2log n is just n, so the traversal is O(n), not exponential. Always ask what the depth really is.
