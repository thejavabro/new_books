Sorting and Searching

Knowing how the main sorting algorithms work, and what they cost, lets you pick the right one and adapt binary search to strange inputs such as rotated arrays, lists of unknown size and sorted matrices.

Which sort, and what does it cost?

The chapter splits sorting algorithms into two groups: the simple O(n²) ones you should know but rarely use (bubble, insertion, selection, counting for small ranges) and the ones interviews dwell on. Tap a row to read when you would pick it.

Watch merge, quick and heap sort

Merge sort splits in half, sorts each half, and merges: always O(n log n), stable, O(n) extra memory. Quick sort picks a pivot and partitions smaller elements to its left: O(n log n) on average and in place, but O(n²) with consistently bad pivots. Heap sort builds a max-heap and repeatedly swaps the max to the end: O(n log n), in place, not stable.

Radix sort: no comparisons at all

  
For integers with at most d digits, radix sort distributes the numbers into 10 buckets by the last digit, collects them in order, then repeats with the next digit. Because each pass is stable, earlier digit order survives. O(d × (n + 10)). Bucket sort is the same idea for values spread evenly over a range: scatter into buckets, sort each small bucket, concatenate.

Binary search and its variations

  
Binary search halves a sorted range each step: O(log n). Interviews twist it: the array was rotated, the size is unknown, or the data is a matrix. Pick a variation and a target.

Grouping anagrams together

  
Two words are anagrams when their sorted letters match. Use the sorted letters as a map key and collect words per key, then output the groups. With k-letter words: O(n · k log k). Edit the list.

  

  
Collection<List<String>> group(String[] words) {
    Map<String, List<String>> byKey = new LinkedHashMap<>();
    for (String w : words) {
        char[] k = w.toCharArray();
        Arrays.sort(k);
        byKey.computeIfAbsent(new String(k), x -> new ArrayList<>()).add(w);
    }
    return byKey.values();
}

Peaks and valleys in one pass

  
Rearrange an array so it alternates peak, valley, peak (each peak ≥ its neighbors, each valley ≤ them). Sorting first works in O(n log n), but there is an O(n) trick: walk every second index and swap it with its larger neighbor so it becomes a peak.

  

  
void peaksValleys(int[] a) {
    for (int i = 1; i < a.length; i += 2) {
        int big = i;
        if (a[i - 1] > a[big]) big = i - 1;
        if (i + 1 < a.length && a[i + 1] > a[big]) big = i + 1;
        if (big != i) { int t = a[i]; a[i] = a[big]; a[big] = t; }
    }
}

Sorting a stack with the help of another stack

  
Pop each element into a temp variable; while the helper stack's top is larger, move those back to the input stack; then push the temp onto the helper. The helper stays sorted (largest at the top). O(n²) time, O(n) extra.
