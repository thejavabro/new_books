Linked Lists and Maps

Linked lists test whether you can keep track of pointers without losing a node. Maps test whether you know what hashing buys you. Put them together and you get an LRU cache, an interview favorite.

Linked lists in a nutshell

A linked list is a chain of nodes, each holding a value and a reference to the next node (and, in a doubly linked list, to the previous one). There is no index arithmetic: reaching the k-th node takes k steps, O(n). In exchange, inserting or removing a node you already hold is O(1): just rewire references. Interviews prefer singly linked lists because the missing back pointer makes problems harder.

class Node {
    int data;
    Node next;            // Node prev; in a doubly linked list
    Node(int data) { this.data = data; }
}
Node deleteValue(Node head, int v) {   // returns the new head
    if (head == null) return null;
    if (head.data == v) return head.next;
    for (Node n = head; n.next != null; n = n.next)
        if (n.next.data == v) { n.next = n.next.next; break; }   // unlink
    return head;
}
2

A map from scratch: hashing into buckets

A hash map turns a key into a bucket index with hash(key) % capacity. Keys that land in the same bucket (a collision) are chained in a small list, so get is O(1) on average and O(n) if everything collides. When the size exceeds capacity × load factor (0.75), the table doubles and every entry is rehashed. Put a few keys and watch.

class MyMap<K, V> {
    private static class Entry<K, V> { final K key; V value; Entry<K, V> next; … }
    private Entry<K, V>[] buckets = new Entry[4];
    private int size;

    public void put(K key, V value) {
        int i = index(key, buckets.length);
        for (Entry<K, V> e = buckets[i]; e != null; e = e.next)
            if (e.key.equals(key)) { e.value = value; return; }   // update
        buckets[i] = new Entry<>(key, value, buckets[i]);        // prepend
        if (++size > buckets.length * 0.75) resize();
    }
    public V get(K key) {
        for (Entry<K, V> e = buckets[index(key, buckets.length)]; e != null; e = e.next)
            if (e.key.equals(key)) return e.value;
        return null;
    }
    private int index(Object key, int cap) { return (key.hashCode() & 0x7fffffff) % cap; }
}
3

The runner technique: n-th to last node

Many list problems use two references moving at different speeds or with a fixed gap. To find the n-th node from the end in one pass, move a runner n nodes ahead, then move both one step at a time. When the runner falls off the end, the follower is exactly n from the end.

Node nthToLast(Node head, int n) {
    Node runner = head, follower = head;
    for (int i = 0; i < n; i++) {
        if (runner == null) return null;   // list shorter than n
        runner = runner.next;
    }
    while (runner != null) { runner = runner.next; follower = follower.next; }
    return follower;
}
4

Loop start detection (Floyd's tortoise and hare)

Move a slow pointer one step and a fast pointer two steps. If there is a loop, they must meet inside it. Then put one pointer back at the head and move both one step at a time: they meet again exactly at the start of the loop. (Why: the distance from the head to the loop start equals the distance from the meeting point forward to the loop start, modulo the loop length.)

Node loopStart(Node head) {
    Node slow = head, fast = head;
    while (fast != null && fast.next != null) {
        slow = slow.next; fast = fast.next.next;
        if (slow == fast) break;              // met inside the loop
    }
    if (fast == null || fast.next == null) return null;   // no loop
    slow = head;
    while (slow != fast) { slow = slow.next; fast = fast.next; }
    return slow;                              // loop start
}
5

Reverse a list, then in groups of k

Reversal needs three references: prev, cur and next. Save next, point cur back at prev, advance. Reversing in groups of k applies the same loop k nodes at a time and links each reversed group to the next one.

Node reverse(Node head) {
    Node prev = null, cur = head;
    while (cur != null) {
        Node next = cur.next;   // save
        cur.next = prev;        // flip
        prev = cur;             // advance
        cur = next;
    }
    return prev;
}
Node reverseInGroups(Node head, int k) {
    Node prev = null, cur = head, next = null;
    int count = 0;
    while (cur != null && count++ < k) { next = cur.next; cur.next = prev; prev = cur; cur = next; }
    if (next != null) head.next = reverseInGroups(next, k);   // old head is now the group's tail
    return prev;
}
6

Merge two sorted linked lists

Keep a dummy head and a tail pointer. Repeatedly attach the smaller front node of the two lists and advance in that list. When one runs out, attach the rest of the other. No new nodes are created: O(n + m) time, O(1) extra space.

Node merge(Node a, Node b) {
    Node dummy = new Node(0), tail = dummy;
    while (a != null && b != null) {
        if (a.data <= b.data) { tail.next = a; a = a.next; }
        else                  { tail.next = b; b = b.next; }
        tail = tail.next;
    }
    tail.next = (a != null) ? a : b;
    return dummy.next;
}

LRU cache: a map plus a doubly linked list

A Least Recently Used cache with capacity c evicts the entry used longest ago. A HashMap gives O(1) lookup of a node; a doubly linked list keeps usage order, with the most recent at the front, and lets you unlink any node in O(1). Every get or put moves the node to the front; when full, drop the node at the back. (In real Java code, LinkedHashMap with access order and removeEldestEntry does this for you.)

class LRU<K, V> extends LinkedHashMap<K, V> {
    private final int capacity;
    LRU(int capacity) { super(16, 0.75f, true); this.capacity = capacity; }  // true = access order
    @Override protected boolean removeEldestEntry(Map.Entry<K, V> eldest) {
        return size() > capacity;
    }
}
