Architecture Repository

All architecture work has to live somewhere. The repository is that place, the continua are how it is sorted from generic to specific, and views are how it is shown to the people who need it.

1

One place for every architecture asset

The Architecture Repository is where finished work, work in progress, reference material, standards and decisions all live, organized so the practice can grow. It is a concept, not a product. Tap its parts.

2

Strategic, segment, capability

The landscape gets big, and different people need different depth. TOGAF splits it into three levels of granularity, and the Requirements Repository mirrors them. Slide to zoom in on a healthcare organization.

3

Three continua: from generic to specific

A continuum is a lens for sorting assets from generic, abstract and logical to specific, concrete and physical. The Enterprise Continuum is the outer lens over the whole repository. Inside it, the Architecture Continuum sorts architectures and the Solutions Continuum sorts the products and components that implement them. Pick a stage.

4

Catalog, map, diagram, matrix

Building blocks are documented in four forms. A catalog lists one kind of thing, unconnected. A matrix cross-maps two catalogs. A map shows relationships as text; a diagram shows the same thing graphically. Same content, four presentations.

Less is moreLimit what goes into any one artifact. More, simpler views beat one overloaded one that nobody can read.
5

Deliverables hold artifacts, artifacts hold building blocks

A deliverable such as the Architecture Definition Document holds one or more artifacts (an Organization Map, a Process Flow Diagram, an Application Landscape). Each artifact describes one or more building blocks, and each building block packages one or more metamodel entities. You don't need every artifact TOGAF lists; pick what helps.

Building blocks behave like plastic toy bricks: generic, with clear boundaries, and stackable. Solution Building Blocks (real products and components) stack up to realize an Architecture Building Block (what is needed). Press build.

6

Views and viewpoints

A viewpoint is the template: the perspective and rules for building a view for certain concerns. A view is what you actually show. The book's image: a village in a valley, two people with binoculars on two peaks. One looks at the church tower, the other at the park. Same village, different vantage points. Then the real case: a physician and a patient looking at the same electronic health record (EHR) system.

7

Make the repository real: pick a tool

Word processors and spreadsheets don't relate entities, so every artifact must be tracked by hand, which collapses as the architecture grows. What you need is a tool with a real repository that keeps relationships, so one change ripples everywhere. Tick what a candidate tool supports.
