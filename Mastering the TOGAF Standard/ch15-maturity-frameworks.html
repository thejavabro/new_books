Why measure architecture maturity?

A maturity model describes an ideal Enterprise Architecture practice. It then shows how far the organization is from it and in what order to close the gap. It is used mostly in the Preliminary phase to assess the Architecture Capability itself. TOGAF has no model of its own. Its Series Guide points to two: the Architecture Capability Maturity Model (ACMM) and Capability Maturity Model Integration (CMMI). Organizations can also build their own.

    Levels

    The author's verdict: ACMM leans heavily toward IT architecture. It even has an "IT security" element, although TOGAF treats security as cross-cutting. The CMMI-based model looks at architecture strategically, as the link from strategy to execution, so it fits Enterprise Architecture better.

      Each CMMI element needs particular competencies, and those point to particular roles. Pick an element.

      6

      The EA Implementation Wheel

      The author's own method, from Getting Started with Enterprise Architecture, is a pragmatic, tailored TOGAF for organizations new to architecture. It aims at a fundamental Enterprise Architecture, not a complete one. It reorders the ADM into four stages, read clockwise from the inside out: Document, Define, Execute, Control. Each stage has steps, and each step has key focus areas. Tap any ring segment, including the unlabeled outer slivers, to see where it lands in the ADM.
