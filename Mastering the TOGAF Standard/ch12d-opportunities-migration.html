Phases E and F: From Gaps to a Plan

Gaps found in B, C and D become work. Phase E groups them into solutions and transition architectures; Phase F puts a price, a value and a sequence on them.

1

Phase E: from gaps to work packages

Phase E has three objectives: identify the work packages that realize the target, decide whether an incremental approach (Transition Architectures) is needed, and refine Architecture Building Blocks into clearly specified Solution Building Blocks. It produces the first complete Architecture Roadmap. Step through its ten steps.

2

Plateaus, gaps and work packages

Each architecture state (baseline, transitions, target) is a plateau. Between two plateaus is a gap, and a work package bridges it. Add or remove transitions to see how the path changes; each transition should deliver business value on its own.

Is a work package a process?

3

From Work Package Portfolio Map to Architecture Roadmap

TOGAF has the work package entity but no artifact that really uses it. The author adds two: the Work Package Portfolio Map (work packages linked to objectives and goals) and the Architecture Roadmap built from it. Goals and objectives go down the left, work packages across the timeline. Then add properties and colour views. The rule: never a roadmap without links to goals and objectives.

Add a column for related projects to the Work Package Portfolio Map in Phase F; mapping work packages to running projects prevents doing work twice.

4

Phase F: put value, cost and order on the plan

Phase F turns the roadmap into a detailed Implementation and Migration Plan: align with the organization's management frameworks (portfolio, project, operations), assign business value to work packages, estimate resources and costs (capital and operational), prioritize by cost/benefit and risk, confirm the roadmap and complete the plan. If maturity allows, sketch an implementation governance model and record lessons learned.

The key tool is the Business Value and Risk Matrix. Senior management should set the criteria and weights before any project is plotted. Adjust the weights and watch the projects move.

5

Transition Architecture State Evolution Table

Rows are domains and services; columns are transitions; cells say what happens to each solution building block. The book's example replaces HR Recruitment Application A with B while the database stays. Step through the columns.

Demanding to build, but it spells out exactly what changes per domain and service in each transition.
