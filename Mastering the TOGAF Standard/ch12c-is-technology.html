Phases C and D: Systems and Technology

Phases C and D turn business needs into the data, applications and technology that support them. Same recipe each time: baseline, target, gaps, roadmap components.

PurposeTraceabilityData artifactsApplication portfolioInterfacesPhase DC and D artifactsQuick checkRecap
1

Blueprints for the systems behind the business

Phase C designs the information systems that support the Business Architecture, in two connected parts: Data Architecture (data assets, management and governance) and Application Architecture (the applications, how they interact with each other and with users). Phase D then defines the technology: hardware, software, networks, platforms and standards. All three reuse the eight-step recipe from Phase B and have the same two objectives: a target, plus candidate roadmap components from the gaps.

The missing middleBIZBOK's information concept sits between business and data. TOGAF's core content doesn't really have it yet; only the Information Mapping Series Guide covers it.
IT is not a separate planetIn nine of ten organizations IT runs its own planning and strategy. TOGAF's whole point is to link work in every domain, technology included, back to business goals.
2

Trace a capability down to a server

The phases are connected by the metamodel's relationships. Tap any box to light up everything it connects to, from capability down to physical technology.

3

Data: who creates, reads, updates, deletes?

The Data Entity/Business Function and Process Matrix shows which processes touch which data. A CRUD view makes gaps obvious: data that nobody creates, or that everyone updates. Tap cells to cycle through C, R, U, D and blank.

4

The Application Portfolio Catalog pays for itself

Without a catalog, departments request new applications for functions the organization already owns, approvals come too fast, and the landscape gets overpopulated. License costs climb and nobody can see why. Build the catalog and duplicates become visible. Tap applications to retire them, or switch to the CIA colour view (confidentiality, integrity, availability).

Enrich the catalog further: hosting location (on premises or cloud), capabilities automated (shows remaining manual work). Colour views turn a list into a decision tool.

5

Interfaces: scope dependencies early

Applications create, read, update and delete data in each other through batch files, direct database links, APIs or web services. The Interface Catalog and Application Interaction Matrix show how tangled the landscape is. Compare point-to-point links with a hub.

6

Phase D: technology standards and portfolio

Phase D picks the technology components, platforms and services that let applications run well, and sets standards for consistency, scalability and security. The Technology Standards Catalog records which products are approved and in what state. Filter by status.
