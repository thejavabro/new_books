Dijkstra's Algorithm

Breadth-first search finds the path with the fewest hops. When edges have weights, such as minutes or dollars, Dijkstra's algorithm finds the path with the smallest total.

1

Fewest segments vs. fastest route

Breadth-first search finds the path with the fewest edges. But if each edge has a weight, such as minutes of travel, the path with fewest edges may not be the fastest. A graph with weights is a weighted graph; to find the path with the smallest total weight, use Dijkstra's algorithm.

2

Dijkstra's algorithm, step by step

Dijkstra's algorithm keeps a table of the cheapest known cost to reach each node (unknown ones start at infinity) and each node's parent on that cheapest path. Then it repeats four steps:

  1. Find the cheapest unprocessed node: the one you can get to in the least time so far.
  2. For each of its out-neighbors, check whether going through this node is cheaper. If so, update its cost and parent.
  3. Mark the node processed and repeat until every node is done.
  4. Follow the parents back from the finish to read off the path.
Why the cheapest node is safe to lock inEvery other route to that node would have to go through some node that already costs more, and with no negative weights, adding edges never makes a path cheaper. So once a node is the cheapest unprocessed one, nothing can beat its cost.
3

Terminology: weights and cycles

Following a cycle only adds weight, so it never gives a shorter path. An undirected edge is effectively a two-way pair, which is a tiny cycle. The book keeps things simple by applying Dijkstra to directed graphs without cycles; in practice it also handles cycles and undirected edges, as long as no weight is negative.

4

Negative weights break it

Suppose someone offers to take your LP in exchange for a poster and pay you $7. That trade has a weight of −7. Now the cheapest way to the poster isn't the $0 trade from the book; it's book → LP (5) → poster (−7) = −$2. But Dijkstra processes the poster first, when it looked like it cost $0, and declares it final. It never revisits it.

Dijkstra says: drums cost $35Book → poster → drums.
Truth: drums cost $33Book → LP → poster → drums = 5 − 7 + 35.

If your graph has negative weights, use the Bellman–Ford algorithm instead.

5

Implementation: three hash tables

You need three tables: the graph (node → {neighbor: weight}, a hash table inside a hash table), the costs, and the parents, plus a set of processed nodes.

graph = {"start": {"a": 6, "b": 2}, "a": {"fin": 1},
         "b": {"a": 3, "fin": 5}, "fin": {}}
costs   = {n: float("inf") for n in graph}; costs["start"] = 0
parents = {}
done = set()

while len(done) < len(graph):
    node = min((n for n in graph if n not in done), key=costs.get)
    for nb, w in graph[node].items():
        if costs[node] + w < costs[nb]:      # cheaper through node?
            costs[nb] = costs[node] + w
            parents[nb] = node
    done.add(node)

Scanning for the minimum each time is simple but O(n) per step. A priority queue built on a min-heap (see chapter 13) makes it much faster on big graphs.
