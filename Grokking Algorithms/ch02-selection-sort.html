Selection Sort

Before sorting anything you need somewhere to put it. Arrays and linked lists make opposite trade-offs, and selection sort shows what an O(n²) algorithm feels like.

1

How memory works

Think of computer memory as a huge wall of numbered drawers. Each drawer holds one thing and has an address. When you want to store a list of things you have two basic choices: put them in drawers that sit side by side (an array), or scatter them anywhere and have each one note the address of the next (a linked list).

Striped drawers are already used by other programs.

An array is like a group of friends wanting adjacent seats in a cinema: if someone sits in the next seat, everyone has to move. You can reserve extra seats in advance, but that wastes space if nobody comes, and you still have to move once you outgrow the reservation. A linked list never has to move: every item just points to the next, like a treasure hunt.

2

Reading: random vs. sequential access

The trade-off flips when you read. Because array items are side by side, the address of item 7 is just "start + 7": you can jump straight there. That's random access, O(1). A linked list only knows where its first item is, so to reach item 7 you must follow 7 pointers. That's sequential access, O(n).

Inserting in the middle

Now insert a value into the middle of a list kept in order. An array has to shift every later item one drawer to the right to make room. A linked list changes one pointer: the item before now points to the new item, and the new item points to what came next. Deleting works the same way.

Selection sort

Say you have a playlist and want it ordered by play count, most played first. Selection sort does the obvious thing: scan the whole list for the biggest, move it to a new list, then scan what's left for the next biggest, and so on.

Unsorted
Sorted
def find_largest(items):
    best = 0
    for i in range(1, len(items)):
        if items[i] > items[best]:
            best = i
    return best

def selection_sort(items):
    items, result = list(items), []
    while items:
        result.append(items.pop(find_largest(items)))
    return result
6

Why selection sort is O(n²)

Each pass looks at every remaining item: n, then n − 1, then n − 2 … down to 1. That adds up to about n × n / 2. Big O drops constants like ½, so selection sort is O(n²). It is a neat, correct algorithm, and quicksort (chapter 4) will do the same job in O(n log n).
