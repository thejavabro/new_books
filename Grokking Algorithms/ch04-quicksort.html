Quicksort

Divide and conquer is a way of thinking: find the simplest case, then shrink every problem toward it. Quicksort is the famous result, and its speed hangs on one choice, the pivot.

1

Divide and conquer: the farm

Divide and conquer (D&C) is a recursive way of attacking problems, not an algorithm in itself. Two steps: find the simplest possible case to use as your base case, then figure out how to shrink the problem until it becomes that base case.

The classic warm-up: a farmer has a 1,680 m × 640 m plot and wants to split it into equal square plots that are as big as possible. The easiest case is when one side is a multiple of the other: then the square is just the short side. Otherwise, cut off the biggest squares you can, and the answer for the whole farm is the answer for the leftover strip. That's Euclid's algorithm.

2

Thinking recursively: summing a list

Adding up a list is easy with a loop. Doing it with D&C is practice for thinking recursively. The base case: an empty list sums to 0. The shrink step: sum(list) = first item + sum(rest of list). Each call works on a list one shorter, so it must reach the base case.

def total(items):
    if not items:          # base case
        return 0
    return items[0] + total(items[1:])
A habit worth formingWhen a function works on an array, the base case is often an empty array or an array with one element. Try that first. The same idea gives a recursive way to count items, find the maximum, or even run binary search.
3

Quicksort, one partition at a time

Quicksort uses D&C to sort. Base case: arrays with 0 or 1 items are already sorted. Otherwise:

  • Pick an element as the pivot.
  • Partition: split the rest into items smaller than the pivot and items bigger.
  • Quicksort the two sub-arrays recursively, then join: smaller + [pivot] + bigger.
def quicksort(items):
    if len(items) < 2:
        return items                      # base case
    pivot = items[0]
    smaller = [x for x in items[1:] if x <= pivot]
    bigger  = [x for x in items[1:] if x > pivot]
    return quicksort(smaller) + [pivot] + quicksort(bigger)
Why can you trust it? Inductive proof in a sentenceIf quicksort works on arrays of size 0 and 1 (base case), and working on all smaller arrays means it works on the next size up (inductive step), then it works on arrays of every size. Like climbing a ladder: if you can stand on a rung and step to the next, you can climb all of it.
4

Average case vs. worst case

Quicksort's speed depends entirely on the pivot. Each level of the call stack touches all n items once, so the total work is n × (number of levels). A good pivot splits the array in half, giving about log n levels: O(n log n). A bad pivot, like always the first item of an already-sorted array, peels off one item per level: n levels, O(n²).

The best case is also the average case: with a random pivot, quicksort is O(n log n) on average.

5

When the constant matters

Big O hides a constant c: an O(n) algorithm really takes c × n time. Usually it doesn't matter, because a better shape wins once n is large. But when two algorithms share the same big O, the constant decides. Merge sort is always O(n log n), and quicksort is O(n log n) only on average, yet quicksort is usually faster in practice: its constant is smaller, and it hits the worst case rarely.

Illustrative constants: simple search 10 ms per item, binary search 1 s per step.
