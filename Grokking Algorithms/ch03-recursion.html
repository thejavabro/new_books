Recursion

Recursion is a function that calls itself. It is never faster than a loop, but it can make a solution much clearer, as long as you know when to stop and what the call stack is doing.

1

A key in a box of boxes

You're hunting for a key in your grandmother's attic. It's in a box, which holds more boxes, which hold more boxes. Two ways to search:

With a loopMake a pile of boxes to look through. Take a box off the pile. If you find a box inside, put it on the pile; if you find the key, you're done. Repeat while the pile isn't empty.
With recursionLook through the box. If you find a box, do the same thing with that box. If you find the key, done. The function calls itself.
Pile

Both find the key. Recursion is not faster; loops are sometimes quicker. As one Stack Overflow answer quoted in the book puts it, loops may achieve a performance gain, but recursion may achieve a gain for the programmer. Use whichever makes the code clearer.

2

Base case and recursive case

Because a recursive function calls itself, it's easy to write one that never stops. So every recursive function has two parts: the recursive case, where it calls itself on a smaller problem, and the base case, where it stops. Try a countdown with and without its base case.


    

      

      
      

      

    

  






  
3
The stack, and the call stack

  
A stack is a pile of sticky notes: you can only push a new note on top or pop the top one off. Your computer keeps one called the call stack. Every time you call a function, a box of memory holding that call's variables is pushed. When the function returns, its box is popped and the caller carries on from where it paused.

  

    

    

      

      

      

    

  

  
The key idea: when one function calls another, the caller is paused, half finished, with all its variables still saved on the stack.






  
4
Recursion on the call stack: factorial

  
Recursive functions use the call stack too. fact(4) means 4 × 3 × 2 × 1. Each call waits for the one above it, so the stack grows until the base case, then unwinds as each paused call finishes its multiplication. Notice each call has its own copy of x.

  

    
def fact(x):
    if x == 1:          # base case
        return 1
    return x * fact(x - 1)  # recursive case

      

    

      

      

    

  

  
In the recursive key search, nobody keeps a pile of boxes: the pile is the call stack, a column of half-finished calls each holding its own half-searched box.






  
5
The cost of a tall stack

  
All those saved frames take memory. A very deep recursion can run out of stack space, giving a stack overflow. Your options: rewrite it as a loop, or use a technique called tail recursion, which some languages (not Python) can run without growing the stack.
