Breadth-First Search

Graphs model connections: friends, roads, dependencies. Breadth-first search walks a graph in rings outward from the start, which is exactly why it finds the shortest path.

What is a graph?

Suppose you want the bus route from one stop to another with the fewest transfers. Check everywhere you can reach in one step; if your destination isn't there, check everything two steps away; and so on. That's a shortest-path problem, and the algorithm is breadth-first search (BFS). First, though, the problem has to be modeled as a graph.

A graph is a set of nodes connected by edges. (Not a chart with axes.) If an edge has an arrow, the relationship goes one way: Ana points to Ben, so Ben is Ana's out-neighbor and Ana is Ben's in-neighbor. That's a directed graph. In an undirected graph edges have no arrows, the relationship goes both ways, and you simply say neighbors.

Breadth-first search: find a mango seller

You want to buy mangoes from someone in your network. BFS answers two questions: is there a path from you to a mango seller, and what is the shortest one? Search your friends first (first-degree connections), and only then their friends (second-degree), and so on. Because closer people are searched first, the first seller you find is the closest one. Queues vs. stacks

Searching in order needs a queue: like a line at the bus stop, the first in is the first out (FIFO). You can only enqueue at the back and dequeue from the front. A stack (chapter 3) is the opposite: last in, first out (LIFO). Push the same items into both and see the order they come out.

Implementing the graph and the search

A graph maps each node to its out-neighbors, which is exactly what a hash table does: key = person, value = list of people they point to. The order you insert keys doesn't matter.

graph = {
  "you": ["ana", "ben", "cy"],
  "ana": ["dee"],
  "ben": ["dee", "eli"],
  "cy":  ["fay", "gus"],
  "dee": [], "eli": ["hal"],
  "fay": [], "gus": [], "hal": [],
}
from collections import deque

def search(start, is_seller):
    queue = deque(graph[start])
    searched = set()
    while queue:
        person = queue.popleft()
        if person in searched:
            continue          # don't check twice
        if is_seller(person):
            return person
        queue += graph[person]
        searched.add(person)
    return None
Why track who you've searched?Dee is a friend of both Ana and Ben, so she'd be queued twice. Worse, if two people list each other as friends, the search would bounce between them forever. A searched set (a hash table, so checking is O(1)) prevents both.

Running time: BFS follows every edge (O(E)) and enqueues every person once (O(V)), so it's O(V + E), vertices plus edges.

Ordering tasks: topological sort

Graphs also capture dependencies. If task A points to task B, A must happen before B. Any order that respects every arrow is a topological sort. A graph where edges never loop back (like a family tree) is a tree, a special kind of graph you'll meet properly in chapter 7.
