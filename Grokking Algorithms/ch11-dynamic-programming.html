The knapsack problem, revisited

Back to the thief, now with a 4 lb knapsack and three items: a guitar (1 lb, $1,500), a stereo (4 lb, $3,000) and a laptop (3 lb, $2,000). The simple solution tries every set of items. With 3 items that's 8 sets, fine. But every extra item doubles the count: O(2n).

2

Dynamic programming: fill in the grid

Dynamic programming solves the small versions of the problem first and builds up. For the knapsack, the small versions are smaller knapsacks: 1 lb, 2 lb, 3 lb. Draw a grid with one row per item and one column per knapsack size. A cell holds the best value using only the items in that row and the rows above, in a knapsack of that size. Each cell uses one formula:

cell[i][j] = max( cell[i−1][j] , value of item i + cell[i−1][j − weight of item i] )
first term: the previous best · second term: this item + the best use of the leftover space

The bottom-right cell is the answer. Notice the values in a column never go down as you add rows: each row can only improve on the best estimate so far. And the order of the rows doesn't change the final answer.

Same grid, different problem: a trip itinerary

5

Longest common substring

A user typed hish. Did they mean fish or vista? Measure how much each candidate has in common with the typo, using a grid with one word along each axis. There's no single formula for designing DP grids: work out what the subproblem is (here, comparing prefixes) and what each cell should hold.

vs.

For the substring, the answer is the largest number anywhere in the grid. For the subsequence (letters in the same order, not necessarily adjacent), the answer is in the last cell. Try fosh against fort and fish: both share a substring of length 2, but fish shares a subsequence of 3. Real uses: diff and git diff, DNA alignment, edit distance for spell checkers, plagiarism detection.
