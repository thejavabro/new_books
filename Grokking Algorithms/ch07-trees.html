Trees

A tree is a graph with no cycles. That one rule makes traversal code simpler, separates depth-first from breadth-first search, and lets Huffman coding squeeze text into fewer bits.

1

Your first tree

A tree is a kind of graph, so it's made of nodes and edges. The trees in this book are rooted: one node, the root, leads to every other node. A node can have children, every node except the root has exactly one parent, and nodes with no children are leaves. Tap a node.

2

Walking a file directory two ways

A folder on your disk is a tree you use every day. To print every file under photos/, including subfolders, you need a traversal: an algorithm that visits every node. Breadth-first search from chapter 6 works, using a queue of folders still to open. Depth-first search (DFS) works too: when it meets a folder, it dives into it immediately, which is easiest to write with recursion.

# breadth-first
def print_bfs(start):
    queue = deque([start])
    while queue:
        folder = queue.popleft()
        for entry in sorted(listdir(folder)):
            path = join(folder, entry)
            if isfile(path): print(entry)
            else: queue.append(path)
# depth-first
def print_dfs(folder):
    for entry in sorted(listdir(folder)):
        path = join(folder, entry)
        if isfile(path): print(entry)
        else: print_dfs(path)
No "searched" set neededThe BFS code in chapter 6 had to remember who it had already checked. Here it doesn't, because a tree has no cycles and each node has one parent: there is no way to reach a folder twice. (A symbolic link pointing back up would create a cycle, and then it would no longer be a tree.)
3

Why DFS can't find shortest paths

Both traversals print every file, just in a different order. But only BFS finds the shortest path, because it finishes every node at distance 1 before any at distance 2. DFS charges down the first branch it sees and may find a seller three hops away while a closer one waits on the other side. DFS has other uses, such as producing a topological sort.

4

A better definition: connected and acyclic

Formally, a tree is a connected, acyclic graph: every node can be reached, and no path leads back to where it started. Is each of these a tree?

A binary tree is a tree where each node has at most two children, called the left child and the right child. A family ancestry chart is one (two biological parents each), but the data can be anything. Binary trees fill the rest of this chapter and most of the next.

5

How much space does text take?

Compression is a great use of binary trees, but first: how is text stored? In the 8-bit encoding ISO-8859-1, every character is one byte = 8 bits (0s and 1s), so 256 characters are possible. ASCII before it used 7 bits (128 characters). Today, Unicode is the standard that aims to cover every language, and UTF-8, which uses 1 to 4 bytes per character, is the usual default choice.

A word like "tilt" only uses three different letters. Three letters don't need 256 possible codes; 2 bits each (00, 01, 10) would do. That's the core idea of compression: spend fewer bits per character.

6

Huffman coding

Huffman coding builds a binary tree from the characters in your text. Characters sit only at the leaves. To find a character's code, walk from the root: going left adds a 0, going right adds a 1. The twist is that codes have different lengths, and common characters get the shortest ones. Type any text to build its tree.

How the tree is built (in brief): repeatedly take the two least frequent items, join them under a new node whose count is their sum, and put that node back, until one tree remains. Ties can be broken differently, so different tools may draw different, equally good trees.

7

Decoding: read the tape one bit at a time

With 8-bit codes you can chop the bits into chunks of eight. With variable-length codes you can't, so you read like a tape: start at the root, step left on 0 and right on 1, and when you land on a leaf, write that letter and jump back to the root.

Why the tree guarantees this worksLetters live only at leaves and each leaf has one unique path from the root, so no code is the start of another (with a = 0 and c = 00, the bits "00" would be ambiguous). There are no cycles, so reading always reaches a leaf. The tree is rooted, so you know where to start. And it's binary because a bit has two values: a third child would have no digit to name it.
