Practical AI: The Daily Workflow

AI is a strong amplifier when it is pointed at the right tasks and wrapped in good engineering practice. This first part of chapter 13 follows one engineer through a full day and shows how small AI assists add up.

1

Faster, yes. Your judgment still decides

The book's final chapter, written as a practical playbook, turns everything earlier into a daily workflow with AI assistants. The starting stance: AI speeds you up (one controlled study had developers finish a task about 55% faster with an AI pair programmer), but faster isn't automatically better. Suggestions can be wrong or insecure, so treat AI output the way you'd treat a new third-party dependency: useful, unvetted, your responsibility once merged.

At 1:30 Sam writes the tests before asking for code, so the assistant has a precise target and its output has an automatic referee. The rules: images up to 5 MB, JPEG or PNG only, reject empty files. Pick an implementation the AI "suggested" and run the tests.

Feed it context: the context sandwich

  
An assistant only knows what it can see. Teams help it by indexing the repo, using semantic code search, and keeping a versioned prompts/ folder of patterns that worked. For a single request, the chapter recommends a "context sandwich": the goal on top, the relevant context and constraints in the middle, the specific request at the bottom. Fill in the layers and watch the prompt quality meter.

Recap on one page

  

    
StanceAI output is an unvetted dependency. Speed is real; responsibility stays with you.

    
DelegateBoilerplate, test drafts, summaries, migrations, docs, search.

    
LeadArchitecture, critical logic, security, anything you can't verify.

    
WorkflowBrief → NFRs → ADR → backlog → tests first → small commits → review → docs.

    
ReviewAI can pre-screen and draft comments; a human approves. Never auto-approve.

    
ContextIndex the repo, version your prompts, use goal-context-constraints-request.
