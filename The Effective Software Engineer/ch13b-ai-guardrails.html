Practical AI: Guardrails and Agents

AI-written code looks clean and can still be unsafe. The second part of chapter 13 covers the guardrails that let you go fast safely: security by default, data hygiene, licensing, compliance frameworks and tight limits on autonomous agents.

1

Make secure the default, not an afterthought

AI learned from public code, including insecure public code, and it repeats common patterns. One 2025 industry analysis found that roughly 45% of AI-generated samples contained a well-known vulnerability class. The answer isn't to stop using it; it's to wrap it in habits. Switch on the habits your team has and see how much risk is left (a rough illustration of layered defence).

Anti-pattern: vibe coding. Letting AI generate code with no clear spec and no tests, trusting that if it runs it's fine. It feels very productive. Then the missing requirements, the uncaught assumptions and the insecure defaults show up in production. If you notice yourself pressing Tab on code you don't fully understand because it looks about right, stop and read it.
3

Don't feed it sensitive data

Assume anything sent to an external AI service could someday be seen by a person or leak. Never paste keys, passwords, personal data or confidential code into a tool not approved for it. If you need help reading a production log, redact it first. Try it.


    

  






  
4
Licensing, provenance and regulation

  
Assistants sometimes reproduce training data almost verbatim. If a chunk came from a GPL project and lands in proprietary code, that can become a legal problem, and the law around AI-generated derivative works is still unsettled. What to do with a suspicious suggestion?

  

    

    

  

  
Regulation is arriving too. The EU AI Act sorts AI uses by risk, with obligations growing with it; NIST's AI Risk Management Framework gives a voluntary structure organized around four functions. Tap each.

  






  
5
Agents: useful, as long as they stay on a leash

  
Agents go beyond suggestions: they plan, edit many files, run commands and open PRs. Good jobs for them include mechanical refactors across files, dependency upgrades, adding tests to legacy code and reproducing bugs. Run the same upgrade task with different guardrails switched on and read the log.

  

    

    

    

  

  
The chapter's analogy: today's agents are like self-driving cars on a highway in good weather. They handle a lot, but you keep a driver ready to take the wheel. Start them on non-critical tasks, keep track of how often they help versus cause trouble, and expand only on evidence.
