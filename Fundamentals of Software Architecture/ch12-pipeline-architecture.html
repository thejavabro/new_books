Pipeline Architecture Style

Pipes and filters: data moves one way through small, single-purpose steps. Simple, cheap and great for processing streams of data.

1

Pipes and filters

A pipeline is a chain of filters connected by pipes. Filters are self-contained and stateless; pipes are one-way. Think Unix: cat log | grep ERROR | sort | uniq -c. There are four filter types. Click each.

Producer

The starting point. Outbound only. Sometimes called the source.

Transformer

Accepts input, transforms some or all of it, and forwards it. Like map.

Tester

Accepts input, tests one or more criteria, and optionally forwards it. Like filter or reduce.

Consumer

The end point. Persists to a database or shows the result in a UI.

2

Build a pipeline

Telemetry records flow through filters. Toggle filters on and off and press Run to see what reaches the consumer. Each filter does one thing, which makes them easy to reuse and recombine.

Characteristics ratings

Pipeline: characteristics scorecard

Stars follow our reading of the book's scorecard: 1 means poorly supported, 5 means a core strength. Check the book's figure for the authors' exact ratings.

Simple and cheap, with better modularity than layered because filters are independent. Still a monolith: one deployment, no elasticity, and a single fault can take the whole pipeline down.

5

When to use it

Use whenOne-directional processing: ETL, EDI, data ingestion, compilers, document processing, simple workflows.
Avoid whenYou need back-and-forth interaction, high scalability or fault tolerance, or many complex conditional paths.
