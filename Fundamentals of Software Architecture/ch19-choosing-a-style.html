4

Monolith case study: Silicon Sandwiches

One deployment with domain modules. Customisation per franchise lives inside the relevant module. Simple, cheap, and scalable enough with cloud help.

The core handles ordering; plug-ins carry per-franchise customisations and external integrations. This fits the domain's customisation shape (isomorphism).

Both are monoliths because one set of characteristics serves the whole system. The kata from Chapter 5 resolves to a single quantum.

5

Distributed case study: Going, Going, Gone

The auction system from Chapter 8 needs different characteristics in different places: bid capture needs scale and reliability, video streaming needs performance, payment needs security and reliability. Several quanta means a distributed style. The book combines microservices with event-driven communication.

AsynchronousBids flow as events: Bid Capture → Bid Streamer and Bid Tracker, so a slow tracker never blocks bidding.
Separate quantaBidder-facing pieces scale elastically; auctioneer pieces need reliability, not scale.
DataBid Tracker owns the bid history; Payment owns its data and security.
