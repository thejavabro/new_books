1

Requirements you can measure

Mozart's genius is heard, not read. An architecture likewise stays paper until executed. Design means defining components, relationships and processes that fit the architecture, starting from requirements. The book gives each production-pipeline requirement a threshold (must meet) and an objective (aim for). Pick one and enter a measured value from your latest test run. Values are the book's examples.

Security (examples)

  • Public key infrastructure on external interfaces
  • Record every user's date, time and executions
  • Patch hardware without disturbing operations
  • Protect models against adversarial attacks
  • Data access controls
  • Monitor for model extraction attacks

Compliance (examples)

  • Only authorised users see personal data
  • Archive all financial transactions
  • Encrypt financial IDs at rest and in use
  • Complete audit trail for every model decision
  • Every model version in the registry with lineage
  • Support model governance review workflows

Actors and use cases

A use case diagram anchors scope: ovals are functions, lines show who uses them. The book names nine actor types for an AI pipeline. Click an actor to light up their use cases.

System modes: a state machine around Executing

Executing is the steady state. Monitoring, Learning and Shadow are variants that keep serving while doing more; Updating is maintenance; Degraded is reduced capability after a fault; Configuration usually follows manual intervention. The diagram tells engineers which transitions to implement, gives recovery paths back to normal, and gives operators a mental model. Drive the pipeline.

The bulkhead pattern

Ships are split into watertight compartments so one breach does not sink the vessel. In software, isolation boundaries (containers, separate pools, service boundaries with circuit breakers) limit the blast radius. Especially important in model serving: one bad model must not starve the others. Fail component B.

7

Circuit breaker, retry and friends

The circuit pattern watches for failures and, past a threshold, stops calling a failing dependency for a while, then tests it carefully. Fail and repeat retries transient errors with back-off. Throttle caps expensive work; balancer spreads load; N-party voting requires agreement. Simulate 30 seconds of calls to a feature service that goes down at t=8 s and recovers at t=20 s.

8

Integration strategies

Implementation engineers do most integration, but problems inevitably arise and the architect protects conceptual integrity while designs change. Four classic strategies, each with a trade-off. Watch the order in which modules come together.

The integration harness: a digital twinMimic data inputs and instrument interactions; isolate module performance; measure storage reads and writes; test data integrity without the full pipeline; stub interfaces for parallel teams; add logging points. Modern harnesses add containers, mock model servers, synthetic data generators, versioned registries and shadow deployment.

Continuous integration gates for models
