1

The agent may propose, but the platform must control

Digital applications follow code paths engineers can inspect. Agents decide their path at runtime and read content that may be hostile, so external content is treated as adversarial by default. The design principle: the agent may propose, but the platform must control. Make it concrete with risk tiers. Pick an action for a claims agent.

2

The infrastructure foundation

Placement should follow the relationship between compute, data and control: keep inference near sensitive data, keep checkpoints, vector indexes and operational data on fast secure paths, and treat east-west network traffic as a first-class concern because agents talk to many more services than apps do. Choose a deployment model for your constraints.

Runtime isolation on Kubernetes

Isolation is not only about noisy neighbours; it limits what a compromised or confused agent can reach. Route GPU capacity only to the critical path; CPUs serve orchestration, retrieval and tools, and small models handle simple requests. Many agent calls share long common prefixes (system prompts, tool schemas), so prefix caching cuts latency and cost.

3

Data, memory and retrieval infrastructure

The data layer decides whether an agent operates with discipline or guesswork. Structured data carries transactional truth; unstructured data carries policy and context; streams carry what is happening now. Memory is a runtime concern, and long-term memory is validated before it is written. Try writing to long-term memory.

Where did it come from?

Provenance: source system, document, version, ingestion job.

How fresh is it?

Freshness: last updated, effective date, staleness thresholds per source.

What path did it take?

Lineage: transformations, chunking, embedding model, retrieval filters, up to the prompt.

Six security principles for agentic systems

5

Identity, delegation and access control

Identity is layered: the human, the agent, sub-agents, tool runners and services each have one. With OAuth-style delegation the agent acts on behalf of the user with progressively narrower tokens at each hop, never with a broad service credential. Step through a delegation chain, then test an access rule.

RBAC sets the role; ABAC checks the situation

Long-running tasksScope tokens to the task and its lifetime. A refresh loop should check that the task is still live and still authorized, not only that the token is about to expire; an abandoned agent with a valid token is an open door. Revocation must take effect instantly.
6

Prompt injection, tool abuse and poisoned memory

The OWASP Top 10 for LLM applications lists prompt injection first. In agentic systems the blast radius is bigger because the model can act. Poison also travels: one agent's output becomes another's input. Watch a poisoned document move through a three-agent chain.

7

PII, encryption and residency

PII travels fast in agent pipelines: into prompts, logs, memory and other agents. Detect, mask and redact it at the agent layer, before it reaches the model or storage. Toggle the controls on a claim note.

8

Network zones, isolation and resilience

Retry, fallback and circuit breaker

High availability keeps the lights on during routine failures; disaster recovery is for when HA is no longer enough. Bulkheads isolate resources so one failing agent does not starve others, deadlines stop runs that hang, and compensation logic cleans up half-finished work. Failover must never silently bypass residency, policy or security restrictions.

9

Anti-patterns and a go-live checklist

Most enterprise failures start not with clever attacks but with shortcuts: treating agents like simple APIs, over-exposing tools and privileges, weak isolation between context, memory and tenants, logging without audit design, and autonomy without control boundaries. Go-live is the moment a system becomes accountable. Tick what is ready.
