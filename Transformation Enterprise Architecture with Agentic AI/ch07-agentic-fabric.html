1

From silos to an agentic fabric

Integration once built highways between systems so data could flow. Agents are not new buildings on those highways but operators: dispatchers, investigators, negotiators. The agentic fabric is the disciplined operating layer that lets many such agents work across the enterprise safely. Generative AI started as a single assistant; agency is now distributed across specialists. Before any agent acts, the fabric must answer five questions. Click each.

2

Interoperability, orchestration, grounding

Without the three pillars you get "smart islands": agents that work well alone but cannot cooperate across domains.

3

The protocol layer: Model Context Protocol

Instead of every agent speaking a private dialect to every REST endpoint, MCP standardizes how capabilities are presented without forcing every system to look the same inside. MCP servers are organized by domain and productize enterprise capabilities for agents: tools (actions), resources (data) and prompts (templates). Send a request through.

4

Agent-to-agent: orchestration, choreography, hybrid

The choice is less about central versus distributed technology and more about where authority and accountability live. Answer the chapter's regulated-enterprise questions (who decides, on what evidence, under which policy, with what approval?) and see which model fits.

5

The last mile: from judgment to a committed fact

Integration with core systems is where an agent stops being a clever narrator and becomes a trusted operator. The most dangerous hallucination is not a wrong explanation but a wrong state: an agent claiming "the payment is posted" when it is not. The chapter's answer is a two-phase pattern with a deterministic confirmation. Run both versions.

Structured and unstructured dataDo not dump tables into prompts: translate structured records into a domain narrative the agent can reason over. For documents, keep pointers back to the exact source passage so the agent can cite, not "remember", what a document says.
6

Message contracts, idempotency and failure handling

Agent collaboration needs protocol discipline: messages carry an explicit intent (specific, bounded, testable), the context needed, and an expected outcome. State is layered, actions are idempotent, and failures go somewhere. Try sending the same "issue refund" message twice, then a poison message.

Governance, guardrails and security in the fabric

Guardrails turn a clever assistant into a trustworthy operator. Here is a small policy-as-code rule from the chapter's refund example, and a request to test it against.

rule refund:
  allow prepare  if role in [agent, csr]
  allow commit   if amount <= 100
                 and reason_code valid
  require human  if amount > 100
  deny           if account_frozen
