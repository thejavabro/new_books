Prompt Engineering

A model's behavior is controlled entirely by what you feed it. Prompting has grown into context engineering: deciding what goes into a finite window, in what order, and how to defend it.

From prompt engineering to context engineering

The model never sees "your prompt". It sees a context window: the system prompt, the user message, examples, retrieved documents, tool definitions, conversation history and output constraints, all concatenated into one input. Context engineering means designing that whole package, and the hard constraint is that input and output share one budget. A 128K window with 100K of input leaves at most 28K for the answer.

Four building blocks of a good prompt

Most effective prompts combine instructions (exactly what to do), context (the situation), format (the shape of the output) and examples (what good looks like). When a prompt fails, one of the four is usually missing or vague. Be specific without being verbose. Toggle the pieces.

Controlling output variability

  
The model outputs a probability for every possible next token; decoding settings decide how you pick one. Temperature sharpens (low) or flattens (high) the distribution. Top-p keeps only the smallest set of tokens whose probabilities add up to p. For extraction, classification or code, keep temperature near 0. For brainstorming, raise it.

Chain-of-thought does not always help
MMLU accuracy, Schulhoff et al. 2024

    

    
Zero-shot "think step by step" lowered accuracy on knowledge questions: reasoning steps can introduce errors where the model already knew the answer. Few-shot CoT did best. Modern reasoning models think by default, so heavy CoT scaffolding matters most for smaller non-reasoning models.

  






  
5
Self-consistency: vote over many reasoning paths

  
One chain of thought can go wrong at any step. Self-consistency samples several paths at non-zero temperature and takes the majority answer. If wrong answers are scattered and the right one is the most common, voting boosts accuracy, at the cost of N times the tokens.

  

    
    

    

  






  
6
Prompt injection and layered defenses

  
Jailbreaking is a user trying to talk the model out of its rules. Prompt injection hides instructions inside content the model processes, such as a web page, an email or a retrieved document. There is no single fix; defenses are layered. A toy assistant summarizes an email that contains a hidden instruction. Switch defenses on and see which attack still lands.

Which technique should I reach for?

  
The book's most common real-world mistake is over-engineering: reaching for tree-of-thought or a multi-step chain before trying a clean few-shot prompt. Complexity should be earned by a measured failure. The second is tuning against three favorite examples instead of a representative test set. Walk the decision.
