RAG and Agents

Retrieval grounds a model in facts it never saw; tools let it act. This chapter climbs from a fixed retrieve-then-generate pipeline to agents that decide what to fetch, which tool to call and when to stop.

1

Retrieval-augmented generation, end to end

RAG gives a model facts it never trained on (private, recent or citable) by fetching evidence and putting it in the context. It has an offline indexing path and an online query path. Step through both.

Can long context replace RAG?Not in general. Huge prompts are slow and expensive on every query, models attend unevenly across long inputs ("lost in the middle"), and big or changing corpora do not fit anyway. Long context complements retrieval.
2

Chunking: the first place RAG goes wrong

Chunks that are too small lose context ("it" no longer knows what "it" is). Chunks that are too large dilute the embedding and waste the budget. Overlap keeps sentences that straddle a boundary retrievable. Slide and watch the boundaries move; then try the structure-aware option.

3

Dense, sparse, hybrid, then re-rank

Dense retrieval compares embeddings: good at meaning and paraphrase, weak on exact identifiers. Sparse retrieval (BM25) matches terms: great for error codes, names and SKUs, blind to synonyms. Hybrid fuses both lists, for example with reciprocal rank fusion, and a cross-encoder re-ranker then reorders the short list. Pick a query; the relevant document is shown in green.

4

Is it retrieval or generation? The RAG triad

When a RAG system "hallucinates", do not start by swapping the LLM. Look at the retrieved chunks first. The RAG evaluation triad splits the question into three checks: is the context relevant to the query, is the answer grounded in the context, and does the answer address the query? Pick a failure report and see which leg breaks.

5

From fixed pipeline to agentic RAG

Most teams improve RAG incrementally by adding decision points. Each pattern adds one kind of control; agentic RAG hands the model control of whether, where, how and when to stop retrieving.

6

Workflows first, then the agent loop

Many production systems need structured workflows (prompt chaining, routing, parallelization, orchestrator-workers, evaluator-optimizer), not open-ended agents. Workflows keep the structure fixed while letting the model make some decisions. A full agent loops perceive → reason → act until a stop condition. In an interview, start simple and justify each step up in autonomy.

7

Tools and the Model Context Protocol

A tool has four parts: a name, a description of what it does and when to use it, an input schema, and a return contract including errors. Tools give freshness and access, precision on structured problems (SQL, calculators) and the ability to act. MCP standardizes how apps discover and call tools, so N apps and M tool providers need N+M integrations instead of N×M.

{
  "name": "get_order_status",
  "description": "Look up an order by ID. Use when the
    user asks where an order is. Not for refunds.",
  "input_schema": {
    "type": "object",
    "properties": {"order_id": {"type": "string",
                   "pattern": "^ORD-[0-9]{6}$"}},
    "required": ["order_id"]
  }
}
// returns {"status": ..., "eta": ...}
