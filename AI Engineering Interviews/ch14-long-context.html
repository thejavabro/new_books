Long Context Modeling

Context windows grew from 2K to millions of tokens, but supporting a length is not the same as using it well. This chapter covers the compute, memory and quality walls, and how each is climbed.

1

Why long sequences are hard

Context windows went from 2K tokens to a million and more, but five problems grow with length: compute (attention is O(n²) in prefill), memory (the KV cache grows linearly and dominates serving), lost in the middle (facts buried mid-prompt get missed), noise (more distractors) and distribution shift (most training sequences were short). Watch attention take over the compute as n grows.

2

Lost in the middle and the needle test

Put the one relevant document at different positions among many: accuracy is highest at the start and end and dips in the middle, a U-shape. A needle-in-a-haystack test sweeps both the needle's position and the total length; the result is a heatmap. Slide the needle.

3

Positional encodings for long context

RoPE rotates each pair of dimensions at its own frequency: high-frequency pairs resolve nearby positions, low-frequency pairs encode long distances. Past the training length, low-frequency pairs see angles they never saw. Position Interpolation (PI) divides every position by the extension factor s: all angles stay in range, but nearby tokens get squeezed together. NTK-aware scaling raises RoPE's base so high frequencies barely change while low ones stretch. YaRN interpolates per frequency band (none for high, full for low, a ramp between) and adds an attention temperature; it needs little fine-tuning.

ALiBiInstead of rotating vectors, ALiBi subtracts a penalty proportional to distance from each attention score, with a different slope per head. It extrapolates gracefully by construction but biases attention toward recent tokens, which can hurt precise long-range retrieval. RoPE plus scaling has become the norm.
4

Three families of efficient attention

Exact but efficient: compute standard attention without ever writing the n×n matrix to slow memory (FlashAttention). Approximate: compute less: sparse patterns, low-rank projections of keys and values (Linformer), or kernelized/linear attention that reorders (QKᵀ)V into Q(KᵀV). Non-attention backbones: state space models. Pick a sparse pattern.

5

State space models and ring attention

State space models carry a fixed-size state through the sequence, like an RNN, but are designed to train in parallel. Mamba makes the state update selective: its parameters depend on the input, so it can choose what to remember. Linear time, constant memory per generated token, no KV cache; the trade-off is weaker exact recall of arbitrary earlier tokens, which is why hybrids (Jamba and others) keep a few attention layers.

When one sequence is too long for one GPU's memory, ring attention splits it into blocks across devices arranged in a ring. Each device keeps its query block and passes key/value blocks around the ring, accumulating attention with the same online-softmax trick as FlashAttention, while overlapping communication with compute.

6

Long context in practice

Teams layer their tools: FlashAttention first (exact, free quality), then structured sparsity or sliding windows if still too costly, retrieval instead of stuffing whole corpora into the prompt, and always a distinction between the maximum context length and the effective one, the length where accuracy on your task stays above a threshold.
