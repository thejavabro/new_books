Pretrained Models

Almost every AI product starts from somebody else's pretrained model. Knowing how those models were made, how big they need to be and how to pick one is the first practical skill an interviewer probes.

1

Why everyone starts from a pretrained model

Pretraining is the expensive, one-time step: a model reads trillions of tokens and learns grammar, facts and patterns with no human labels. Everything afterwards (fine-tuning, prompting, retrieval, alignment) is a way of reusing that investment. Three reasons it matters: broad general knowledge, reuse across many tasks, and the economics of paying once and adapting cheaply many times.

When you describe a model in an interview, keep three properties apart. They are independent, and mixing them up is a common slip (for example, there is no downloadable "base GPT-4": closed providers only expose post-trained models).

2

Two ways to learn from raw text

Self-supervision hides part of the text and asks the model to predict it. Masked LM (BERT) blanks out random tokens and uses context on both sides. Causal LM (GPT, Llama, Qwen) sees only the left context and predicts the next token, which is exactly how it will be used to generate. A third, rarer option, prefix LM (T5, UL2), reads a prefix both ways and then generates.

Why causal wonA decoder can be coaxed into understanding ("Is this review positive?"), but an encoder cannot easily be coaxed into generating. The causal objective also scales cleanly and matches inference. Encoders did not vanish: they moved to the perceptual front end of multimodal systems.
3

How text becomes tokens: byte-pair encoding

Whole words need a huge vocabulary and still break on new words; single characters make sequences long and attention expensive. Subword tokenization sits between them, with typical vocabularies of 32K to 128K. BPE starts from characters (or raw bytes, in byte-level BPE, so nothing is ever unknown) and repeatedly merges the most frequent adjacent pair. Step through it on a tiny corpus.

4

Scaling laws: a budgeting tool

Loss falls as a smooth power law in parameters, data and compute. Kaplan (2020) said spend most compute on parameters (GPT-3: 175B params, 300B tokens). Chinchilla (2022) corrected this to roughly 20 tokens per parameter; its 70B model on 1.4T tokens beat the 280B Gopher. Training compute is about C ≈ 6·N·D FLOPs (forward plus a backward pass that costs about twice as much). Then the senior point: compute-optimal is not deployment-optimal. Inference is paid on every request, so labs overtrain small models on purpose.

5

Mixture of experts: big model, small bill

Does every parameter need to run for every token? An MoE layer swaps one feed-forward block for many experts plus a router that sends each token to the top few (often 2). Total parameters set capacity; active parameters set compute per token. Memory still has to hold all of them. Route some tokens.

6

Choosing the right pretrained model

Task requirements (quality, languages, context length, reasoning, modality) meet deployment constraints (latency, cost, hardware, licensing, privacy). The framework is a funnel: requirements first, hard constraints cut the list, then test on your own data.
