LLM Inference

Most of an LLM's lifetime cost is inference. Generating text is memory-bound, so the winning tricks shrink, share or skip the bytes moved per token.

1

Two phases, two bottlenecks

Prefill processes the whole prompt in parallel, fills the KV cache and produces the first token: big matrix multiplies, compute-bound. Decode then generates one token at a time; each step reads all the weights and the growing KV cache to do a tiny amount of math: memory-bandwidth-bound. Users feel prefill as TTFT (time to first token) and decode as TPOT (time per output token). Throughput, and goodput (useful tokens only), measure system capacity.

Rough single-request numbers for an 8B model in BF16 on one H100-class GPU.

Triage ruleHigh TTFT, fine TPOT → prefill or queueing: shorten prompts, prefix caching, chunked prefill, better scheduling. High TPOT → decode: quantize weights, shrink the KV cache, speculative decoding, tensor parallelism, smaller batch per GPU.
2

Arithmetic intensity and the roofline

Arithmetic intensity = FLOPs ÷ bytes moved. A GPU with peak P FLOP/s and bandwidth B bytes/s is memory-bound below the ridge point P/B (about 300 FLOPs/byte on an H100). Decode with batch size 1 does about 2 FLOPs per 2-byte weight, an intensity near 1. Batching reuses each loaded weight across many requests, sliding you up the roof.

3

The KV cache, and how to shrink it

Without a cache, every decode step would recompute keys and values for the whole prefix. The KV cache stores them: size = 2 × layers × KV heads × head dim × tokens × bytes, per sequence. At long context and high batch it can exceed the weights. Architecture fixes: GQA (groups of query heads share one KV head), MQA (all share one), MLA (compress K and V into a latent). Runtime fixes: PagedAttention (allocate in blocks, like OS pages, no fragmentation), prefix caching, quantized KV, eviction.

4

Decoding strategies

Decoding serves four goals: correctness, diversity, controllability and speed. Greedy takes the top token (deterministic, can loop). Beam search keeps the best B partial sequences (good for translation, bland for chat). Sampling methods reshape and truncate: temperature, top-k (keep k tokens), top-p (keep the smallest set reaching mass p), min-p (keep tokens with at least a fraction of the top token's probability). Plus repetition penalties and constrained decoding for schemas.

5

Compression: quantization, pruning, distillation

Weights in 16-bit take 2 bytes per parameter: a 70B model needs 140 GB, more than one 80 GB GPU. Quantization maps values onto a small grid (INT8, INT4, FP8) with a scale per tensor, channel or group. Outliers stretch the grid and waste resolution, so good methods protect them: GPTQ (layer-wise error-compensating rounding using second-order information), AWQ (scale up channels with large activations before quantizing), SmoothQuant (move activation outliers into weights so both can be INT8). 6

Speculative decoding

Decode is memory-bound, so checking several tokens costs about the same as generating one. A small draft model proposes k tokens; the big target model scores all of them in one forward pass; tokens are accepted left to right with a rule that keeps the output distribution exactly the target's; at the first rejection a corrected token is sampled. Expected tokens per target pass = (1 − αᵏ⁺¹)/(1 − α), where α is the acceptance rate.

7

Serving: batching, disaggregation, routing

Static batching waits for the slowest request in the batch; short requests sit idle and new ones queue. Continuous batching schedules at the iteration level: finished sequences leave and new ones join every step. Chunked prefill splits long prompts so they do not stall everyone's decode. Prefill/decode disaggregation runs the two phases on separate GPU pools sized for each bottleneck, moving the KV cache between them; it pays off at scale with strict latency targets.
