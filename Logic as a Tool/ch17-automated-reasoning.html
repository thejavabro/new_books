Automated Reasoning and Prolog

Resolution with unification is the engine of automated provers and of Prolog, where a program is a set of facts and rules and running it means proving a query.

1

Automated and interactive theorem proving

Automated reasoning turns deductive systems into programs. Its roots go back to Ramon Llull's 13th-century Ars Magna; the modern field took off with computers and Robinson's resolution (1965). Most first-order provers (Prover9, the successor of Otter; SPASS; Vampire; E) run refined resolution. Since first-order validity is undecidable, no prover can be complete and always terminate, so hard problems are often tackled interactively: a human proposes lemmas and the system checks every step (Coq, Isabelle, HOL, Mizar, PVS, Agda, ACL2…).

2

Logic programming: a program is a set of clauses

In logic programming you state what is true, not how to compute. A Prolog program is a list of Horn clauses: facts like parent(ann, bob). and rules like ancestor(X, Y) :- parent(X, Z), ancestor(Z, Y)., read as "for all X, Y, Z: if parent(X, Z) and ancestor(Z, Y) then ancestor(X, Y)". A query ?- ancestor(ann, Y). is a negated goal; running the program means deriving the empty clause by resolution, and the unifiers used give the answers. Prolog conventions: variables start with a capital letter.

How Prolog runs: SLD resolution with backtracking

The strategy is SLD resolution: always resolve the leftmost goal of the current query with the first matching clause (renamed apart), depth first; on failure, backtrack to the most recent choice. SLD is complete for Horn clauses in principle, but depth-first search can fall into an infinite branch even when an answer exists. Try the "Left recursion" preset: the same logical content, a different clause order, and the search never ends.

4

Negation as failure and closed worlds

Pure Prolog cannot prove negative facts. Answering "no" really means "I could not derive it". Prolog turns this into an operator: \+ G succeeds exactly when the search for G fails finitely. That is the closed-world assumption, and it makes reasoning non-monotonic: adding a fact can make a previous conclusion disappear. Load the "Negation" preset, ask childless(X), then add the fact parent(eve, fay). and ask again.

Not classical logicClassically, failing to prove parent(ann, cid) says nothing about its truth. Prolog answers "no" anyway.
Cut and orderThe extra-logical ! (cut) prunes the search tree. Used well it gives efficient programs; used carelessly it changes the answers, so the program no longer means its logical reading.
