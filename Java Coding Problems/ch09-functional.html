mapMulti: push elements instead of returning streams

flatMap asks each element for a Stream, even when it yields zero or one item. mapMulti (JDK 16) hands you a Consumer instead: call it as many times as you like (P185). It shines when most elements produce nothing or very little, and when you want to filter and map in one go. Compare.


    

    

  

  
P186 shows the same idea from the other side: Stream.map can carry any custom code, so a "mapper" can be a small class that holds state or configuration, as long as you keep it side-effect free when going parallel.

A method reference is not always the same as its lambda

  
obj::method evaluates obj when the reference is created; () -> obj.method() evaluates it each time the lambda runs (P187). That changes when a NullPointerException appears and which object gets called after a reassignment. Play it out.

  

    
Printer p = null;                          // or a real Printer
Runnable ref    = p::print;                // evaluates p now
Runnable lambda = () -> p2.print();        // p2 read later (a field, so it may change)

Lazy arguments with Supplier

  
Java evaluates method arguments eagerly. log.debug("state: " + expensiveDump()) computes the dump even when debug logging is off. Pass a Supplier<String> and the work happens only if needed (P188–P189). Toggle the level and send a few log calls.

  

    
Logger level

    

    
void debug(Supplier<String> msg) { if (level <= DEBUG) out(msg.get()); }
log.debug(() -> "state: " + expensiveDump());     // dump only built when DEBUG is on

Collector.of: four functions make a collector

  
A collector is four functions (P202): a supplier creates an empty container, an accumulator folds one element in, a combiner merges two containers (used when the stream is parallel), and a finisher turns the container into the result. Step through a parallel run of a collector that partitions numbers into even and odd sums.

  

  
Collector<Integer, long[], String> evenOdd = Collector.of(
    () -> new long[2],                                // supplier
    (acc, n) -> acc[n % 2] += n,                      // accumulator
    (a, b) -> { a[0] += b[0]; a[1] += b[1]; return a; }, // combiner
    acc -> "even=" + acc[0] + ", odd=" + acc[1]);      // finisher

distinctBy, take/skip collectors and n-ary functions

  
P204: distinct() uses equals; to dedupe by a key, keep a concurrent "seen" set inside a stateful predicate. Pick the key.

  

    

    

  

  
static <T> Predicate<T> distinctBy(Function<? super T, ?> key) {
    Set<Object> seen = ConcurrentHashMap.newKeySet();
    return t -> seen.add(key.apply(t));       // add() is false for repeats
}
melons.stream().filter(distinctBy(Melon::type)).toList();
