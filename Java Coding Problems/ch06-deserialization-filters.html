Java I/O: Deserialization Filters

Deserializing untrusted bytes runs code you did not write. Filters let you inspect every class, array and depth before an object is built, and JDK 17 lets you choose a filter per context.

Serialization round trips: bytes, text, XML

The chapter warms up with three ways to persist an object (P131–P133): ObjectOutputStream into a byte[]; those bytes encoded as a Base64 String for text channels; and XMLEncoder, which writes JavaBean properties as XML and does not even need Serializable. The same Melon("Gac", 2500) in each:

byte[] (hex)
Base64 String
XMLEncoder

Every Java serialization stream starts with the magic AC ED and version 00 05; that is the "rO0AB" you can spot at the start of Base64 payloads in logs and HTTP traffic. The bytes above are abbreviated for illustration.

2

Why deserializing untrusted data is dangerous

The bytes decide which classes get instantiated. Any Serializable class on your classpath can be named, and its readObject, hashCode or equals will run during deserialization, before your code ever sees the object. Attackers chain such "gadgets" together. Step through.

The fix: inspect before you build (P134)JDK 9 (JEP 290) added ObjectInputFilter. The stream calls your filter for every class, array length, reference count and nesting depth it is about to process; you answer ALLOWED, REJECTED or UNDECIDED. Rejection throws InvalidClassException before any object of that class exists.
3

Pattern-based filters: a tiny language

The easiest filter is a pattern string (P135), set per stream with ObjectInputFilter.Config.createFilter(...), or JVM-wide with -Djdk.serialFilter=.... Rules are separated by ;: limits like maxdepth=5, class patterns tried left to right where the first match wins, and ! to reject. A trailing !* turns an allow-list into "reject everything else". Edit the filter and watch every incoming item.

Syntax: pkg.* one package, pkg.** package and subpackages, Name* prefix, module/pattern restricts to a module, * anything. With no match the result is UNDECIDED, which the stream treats as allowed unless another filter decides.

4

Filters as classes, methods and lambdas

ObjectInputFilter is a functional interface with one method, checkInput(FilterInfo info), so a filter can be a class, a method reference or a lambda (P136–P138). FilterInfo tells you serialClass(), arrayLength(), depth(), references() and streamBytes().

ObjectInputFilter onlyMelons = info -> {
    Class<?> c = info.serialClass();
    if (c == null) return Status.UNDECIDED;               // a limits-only callback
    return Melon.class.isAssignableFrom(c) || c.getName().startsWith("java.lang.")
         ? Status.ALLOWED : Status.REJECTED;
};
try (var in = new ObjectInputStream(new ByteArrayInputStream(bytes))) {
    in.setObjectInputFilter(onlyMelons);                  // per stream
    Melon m = (Melon) in.readObject();
}
5

Two small payloads, two big problems

Filters are not only about classes. P139: deeply nested objects overflow the stack while readObject recurses. P140: a classic denial-of-service is a HashSet that contains two sets, each containing two sets, and so on, cleverly linked so the payload stays tiny. Rebuilding each set calls hashCode() on its elements, which recompute their elements' hash codes, so the work doubles with each level. Drag the depth.

6

JDK 17: allow/reject filters, merging and a filter factory

JDK 17 (JEP 415) made filters composable (P141). ObjectInputFilter.allowFilter(predicate, otherStatus) and rejectFilter(predicate, otherStatus) build filters from a Predicate<Class<?>>; merge(a, b) combines two (REJECTED wins, then ALLOWED, else UNDECIDED); rejectUndecidedClass(f) closes the gaps. The big change is context-specific filters (P142): a JVM-wide filter factory, a BinaryOperator<ObjectInputFilter>, is asked for the effective filter of every stream, so each part of an app, and each library, can have its own rules. Combine statuses.

// -Djdk.serialFilterFactory=com.shop.ContextFilterFactory
public class ContextFilterFactory implements BinaryOperator<ObjectInputFilter> {
    public ObjectInputFilter apply(ObjectInputFilter current, ObjectInputFilter next) {
        // called with (jvmFilter, null) when a stream is created,
        // and with (current, requested) when code calls setObjectInputFilter
        return current == null ? next : ObjectInputFilter.merge(next, current);
    }
}
ObjectInputFilter.Config.setSerialFilterFactory(new ContextFilterFactory()); // or in code
7

Watching deserialization with Flight Recorder

JDK 17 also added a JFR event, jdk.Deserialization (P143). Turn it on and every filter callback is recorded with the class, array length, depth, references, bytes read, the filter used and its decision. It is the easiest way to discover what an application really deserializes before you write an allow-list.

java -XX:StartFlightRecording=filename=deser.jfr,settings=deser.jfc App
jfr print --events jdk.Deserialization deser.jfr
