Sealed and Hidden Classes

A sealed class says exactly who may extend it. That turns an open hierarchy into a closed set the compiler can check, which pays off in switch. Hidden classes, the other half, are for frameworks that generate code.

1

An electrical panel nobody else can wire into

The chapter models an electrical panel (P172): circuits, capacitors, resistors and transistors behind an ElectricComponent interface. The model is meant to be complete; a stranger adding HackerCircuit extends ElectricCircuit would break code that assumes it knows every kind. Before JDK 17 you could only make leaves final and hide constructors, and even that left gaps (P173). Since JDK 17, sealed ... permits lists the allowed subtypes, and the compiler and JVM enforce it (P174–P176).

2

The rules of permits

Every permitted subclass must pick exactly one modifier: final (stop here), sealed (continue, with its own permits) or non-sealed (reopen this branch to anyone). It must live in the same module as the sealed class, or the same package if you have no modules. If all subclasses are in the same file, permits can be left out and inferred (P175). Will these compile?

Compiles?

public sealed interface Fuel permits SolidFuel, LiquidFuel {}
sealed interface SolidFuel extends Fuel permits Coke, Charcoal {}
non-sealed interface LiquidFuel extends Fuel {}     // anyone may implement this branch
final class Coke implements SolidFuel {}
final class Charcoal implements SolidFuel {}
3

Sealed + records + switch = the compiler checks every case

Combine sealed interfaces with records (P177) and pattern matching (P178–P179), and a switch over the sealed type needs no default: the compiler knows the full list. Leave a case out and it refuses to compile. Better still, add a new permitted type later and every switch that forgot it lights up as an error. Tick the cases you handle.

sealed interface Shape permits Circle, Square, Rect {}
record Circle(double r) implements Shape {}
record Square(double side) implements Shape {}
record Rect(double w, double h) implements Shape {}

The Visitor pattern, reinterpreted

  
The classic Visitor pattern exists to add operations to a fixed set of types without touching them, at the price of an accept method in every class and a visitor interface with one method per type. With a sealed hierarchy and a pattern switch, an operation is just a method with a switch (P180). Compare what changes when the model grows.

  

    

    

    

    

  

  
double price(ElectricComponent c) {             // a new operation = a new method
    return switch (c) {
        case Capacitor cap  -> 0.5;
        case Resistor r     -> 0.1;
        case Transistor t   -> 1.2;
        case ElectricCircuit circuit -> 3.0;
        case ElectricBreaker b -> 12.0;
    };                                          // no default: exhaustive over the sealed type
}

Reflection and the top three benefits

  
P181: Class.isSealed() and Class.getPermittedSubclasses() let tools discover the hierarchy at run time, for example to register every subtype with a JSON library automatically. P182 sums up why sealing is worth it.

  
for (Class<?> c : Shape.class.getPermittedSubclasses())
    System.out.println(c.getSimpleName() + (c.isSealed() ? " (sealed)" : ""));

  






  
6
Hidden classes: for code that writes code

  
Frameworks generate classes at run time: proxies, lambdas, serializers. Defining them in a normal class loader makes them visible to everyone and hard to unload. A hidden class (JDK 15, JEP 371) cannot be found by name, cannot be referenced from other classes' bytecode, and can be unloaded as soon as nobody holds it (P183–P184). Step through.

  

    
byte[] bytes = generateBytecode();          // e.g. with ASM or the ClassFile API
MethodHandles.Lookup lookup = MethodHandles.lookup();
Class<?> hidden = lookup
    .defineHiddenClass(bytes, true, ClassOption.NESTMATE)
    .lookupClass();
Object o = hidden.getConstructor().newInstance();
System.out.println(hidden.getName());     // com.shop.Calc/0x0000001001234567
Class.forName(hidden.getName());          // ClassNotFoundException
