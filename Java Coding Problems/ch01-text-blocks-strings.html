Syntax in one breathA text block opens with """ followed by a line break (nothing else may sit on that line) and closes with """, either at the end of the last line or on a line of its own. """hi""" on one line does not compile. Rule of thumb from the book: if it fits on one line, use an ordinary literal.

Incidental vs essential white space: play the compiler

  
Your IDE indents the text block to match the surrounding code. That leading space is incidental; it should not end up in the string. Space you add on purpose is essential. The compiler separates the two with one rule (P2–P4): count leading white space on every non-blank line including the closing-delimiter line, take the minimum, and strip that many characters from every line. Trailing spaces are always stripped. Move the sliders.

6
Are two text blocks isomorphic?

  
Two strings are isomorphic when every character of the first can be swapped for one character of the second, consistently, in both directions: "egg" and "add" are, "aab" and "que" are not. Two text blocks are isomorphic when their lines are, pair by pair (P12). The solution keeps two maps and fails on the first conflict. Try it.

  

    

    

    

  






  
7
String concatenation vs StringBuilder

  
P13 benchmarks the two with JMH. The reason for the result is easy to draw. A String is immutable, so s += x inside a loop builds a new string each time and copies everything so far. A StringBuilder appends into a growing buffer and only copies when it doubles. (For a single expression like a + b + c, javac already emits an efficient invokedynamic concat, so there is no need to "optimize" that by hand.)

  

    
    

    

  

  
P14 lists the usual ways to turn an int into a String: Integer.toString(i), String.valueOf(i), "" + i, String.format("%d", i) and Integer.valueOf(i).toString(). The first two are direct and cheap; String.format parses a format string every time and is by far the slowest.

String templates and template processors

  
JDK 21 previewed string templates (P15–P16): write \{expression} inside a literal or text block and hand the whole thing to a template processor. The processor receives two lists, the literal fragments and the evaluated values, and decides what to build. Status checkString templates were a preview in JDK 21 and 22 and were withdrawn in JDK 23 for a redesign, so treat this section as a look at the idea rather than an API to ship on. Text blocks, formatted() and StringBuilder remain the stable tools.
