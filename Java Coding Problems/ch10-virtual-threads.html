Virtual Threads and Structured Concurrency

A virtual thread costs about as much as an object, so you can have a million of them. Structured concurrency gives those threads a parent, a lifetime and a single place to handle failure.

1

Concurrency is not parallelism

Parallelism splits one job into subtasks and runs them at the same time on several cores, to finish that job sooner: it is measured in latency. Concurrency juggles many independent jobs that compete for resources, to finish more of them per second: it is measured in throughput (P209). Asynchrony is a third idea: not waiting while something else happens. Virtual threads are a concurrency tool.

2

Why a thread per request ran out of road

A platform thread is a thin wrapper over an OS thread: about a megabyte of reserved stack, an expensive start, and an OS scheduler that struggles with tens of thousands of them. So servers used pools, and a pool of 200 threads blocked on I/O handles 200 requests at a time. A virtual thread (final in JDK 21) is a Java object, a few hundred bytes to start with, scheduled by the JVM (P211). Simulate requests that each wait 1 second on a database.

try (ExecutorService exec = Executors.newVirtualThreadPerTaskExecutor()) {   // P212
    for (int i = 0; i < 10_000; i++) exec.submit(() -> handle(request));   // one cheap thread per task
}                                                                          // close() waits for all

Thread.ofVirtual().name("vt-", 0).start(task);   // builders and factories also exist
Thread.startVirtualThread(task);
3

Mount, run, park, unmount

Virtual threads run on a small pool of carrier platform threads (a ForkJoinPool, one carrier per core by default). When a virtual thread blocks on I/O, sleep or a java.util.concurrent lock, the JVM copies its stack frames to the heap and unmounts it; the carrier picks up another one. When the I/O completes, the virtual thread is rescheduled, possibly on a different carrier (P213). Press play.

4

invokeAll, invokeAny and Future.state()

The classic ExecutorService methods work unchanged with virtual threads (P216–P217): invokeAll waits for every task; invokeAny returns the first successful result and cancels the rest. JDK 19 added Future.state() with RUNNING, SUCCESS, FAILED and CANCELLED, plus resultNow() and exceptionNow() (P218). Make some tasks fail and run.

5

Structured concurrency: subtasks with a parent

With plain executors, nothing ties the three fetchTester(id) calls to the method that started them: if one fails, the others keep running; if the caller is interrupted, they leak (P210). StructuredTaskScope (preview in JDK 21) gives subtasks a lexical scope: they start inside a try block and are guaranteed finished when it ends (P220). A policy decides when to stop early: ShutdownOnFailure cancels the rest on the first failure (P222); ShutdownOnSuccess on the first success (P221). Set it up and run.


  

  
P223 combines scopes with streams: fork one subtask per element with map(id -> scope.fork(() -> fetchTester(id))), collect the Subtasks, join(), then stream their results. P219 does the same with a virtual-thread executor.






  
6
Seeing virtual threads

  
A million threads make old tools struggle. Thread dumps now have a JSON format that groups virtual threads by their scope, and JFR has dedicated events (P224).

  
jcmd <pid> Thread.dump_to_file -format=json threads.json
java -XX:StartFlightRecording=filename=vt.jfr App
jfr print --events jdk.VirtualThreadStart,jdk.VirtualThreadPinned vt.jfr
