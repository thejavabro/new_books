A Locale is a tag, not just a language

A Locale names a language, optionally a script and a region, plus extensions such as a calendar or numbering system (P17). You can build one with a constructor (deprecated since JDK 19), Locale.of() (JDK 19), Locale.Builder or Locale.forLanguageTag() from an IETF BCP 47 tag. Pick the parts and watch the same moment format differently (P18).

Locale ro  = Locale.of("ro", "RO");                    // JDK 19+
Locale zh  = Locale.forLanguageTag("zh-Hans-CN");       // BCP 47 tag
Locale ca  = new Locale.Builder().setLanguage("fr").setRegion("CA").build();

String s = LocalDateTime.now().format(
    DateTimeFormatter.ofLocalizedDateTime(FormatStyle.MEDIUM).withLocale(ro));
String p = LocalDate.now().format(
    DateTimeFormatter.ofLocalizedPattern("yMMM").withLocale(ro)); // JDK 19: a skeleton, ordered per locale

strictfp: a keyword that became unnecessary

On old x87 hardware, intermediate floating-point results could be held in 80-bit registers, so the same expression could give slightly different answers on different machines. strictfp forced strict IEEE 754 64-bit rounding at every step, at a cost. Modern CPUs (SSE2 and later) do strict math at full speed, so JDK 17 (JEP 306) made all floating point strict and the keyword now does nothing but trigger a compiler warning (P19).

3

Integer overflow wraps silently; the *Exact methods don't

An int lives on a ring of 232 values. Step past MAX_VALUE and you land on MIN_VALUE, with no exception. The famous trap (P20): Math.abs(Integer.MIN_VALUE) is still negative, because +2,147,483,648 does not exist. Math.absExact() (JDK 15), addExact, multiplyExact, floorDivExact and friends throw ArithmeticException instead (P21). Try some values.

Which way does division round?

The / operator truncates toward zero, and % takes the sign of the dividend. That is rarely what you want for negative numbers: bucket indexes, clock arithmetic and pagination need rounding toward minus infinity. Java has had floorDiv/floorMod since JDK 8; JDK 18 added ceilDiv/ceilMod (P22, P26). The modulus always satisfies x == div(x, y) * y + mod(x, y).

5

Unsigned integers: same bits, other reading

Java has no unsigned types, but since JDK 8 it can read an int or long as unsigned (P25). The 32 bits do not change; only the meaning of the top bit does: in two's complement it is worth −231, unsigned it is worth +231. Tap bits to flip them.

Square roots the Babylonian way

P28: guess x, then replace it with the average of x and v/x. If x is too big, v/x is too small, so their average lands closer. Each step roughly doubles the number of correct digits. Pick a number and a bad first guess.

static double sqrtBabylonian(double v) {
    double x = v / 2, prev;
    do { prev = x; x = (x + v / x) / 2; }
    while (Math.abs(x - prev) > 1e-9);
    return x;
}
7

Multiply without *, slice with TAU, and other small tools

P31 asks for p·q with no multiplication, division, bitwise ops or loops. The trick is the square of a sum: (p+q)² = p² + 2pq + q², so pq = ((p+q)² − p² − q²) / 2. Squares come from Math.pow, and "divide by two" becomes a recursion that subtracts 2 until nothing is left. The picture shows why it works.

τ = 2π = one full turn (P32)

With Math.TAU (JDK 19) an angle reads as the fraction of a turn it is. A quarter turn is TAU/4 rather than PI/2. Radius from circumference: r = c / Math.TAU.

JDK 17's RandomGenerator family

Before JDK 17, Random, SecureRandom, ThreadLocalRandom and SplittableRandom shared no common type. JEP 356 put one interface, RandomGenerator, on top, with sub-interfaces that describe what a generator can do (P33). Click a box.

Algorithms come from RandomGeneratorFactory, by name or by property. Tick what you need and see which algorithms qualify. The default, L32X64MixRandom, is what RandomGenerator.getDefault() returns.
