Records and Record Patterns

A record is a transparent carrier for immutable data. Declare the components once and Java writes the constructor, accessors, equals, hashCode and toString. Record patterns then take them apart again.

One line instead of fifty

A record (final in JDK 16) is a class whose whole state is listed in its header (P88). From record Melon(String type, float weight) {} the compiler generates everything a careful developer would write by hand. Click the generated members to see what each one does.

public record Melon(String type, float weight) {}

  

  
Not a "Lombok replacement"A record is a semantic promise: the object is exactly its components, nothing hidden. That is what lets the platform deconstruct it in patterns and serialize it safely.

Canonical and compact constructors

  
The canonical constructor takes every component in order. You can write it out in full, or write the compact form with no parameter list: its body runs before the fields are assigned, so it is the place to validate and normalize (P89). Other constructors must delegate to it with this(...) (P92). Try some inputs.

  

    
public record Melon(String type, float weight) {
    public Melon {                          // compact
        Objects.requireNonNull(type, "type");
        if (weight < 1000 || weight > 16000)
            throw new IllegalArgumentException(
                "weight out of range: " + weight);
        type = type.strip().toUpperCase();  // reassign parameter
    }                                       // fields assigned here

    public Melon(String type) {             // extra ctor
        this(type, 1000);                   // must delegate
    }
}

What a record may and may not contain

  
Records can have methods, static members, nested types and annotations, and can implement interfaces (P90, P93). They cannot add hidden state or be extended (P91). Guess each one.

Records deserialize through the front door

  
Classic serialization rebuilds an object without calling its constructor: fields are poked in by reflection. Any validation in the constructor is skipped, so a tampered stream can create an object that "can't exist". A Serializable record is different: the stream only supplies component values, and the JVM calls the canonical constructor with them (P94). Feed both a tampered stream whose batch code breaks the rule "must start with ML".

Record patterns: take it apart in the test

  
A record pattern (final in JDK 21) matches a type and binds its components, nesting as deep as you like (P97–P100). A nested pattern never matches a null component, so such a value simply falls through to the next case (P101). Set up an order and see which case wins.

  
record Address(String city) {}
record Customer(String name, Address address) {}
record Order(Customer customer, double total) {}

String route(Object o) { return switch (o) {
    case Order(Customer(var n, Address(var city)), var t) when t > 100 -> "express to " + city;
    case Order(Customer(var n, Address(var city)), var t)              -> "standard to " + city;
    case Order(Customer(var n, var addr), var t)                       -> "ask " + n + " for an address";
    case Order o2                                                      -> "no customer!";
    default                                                            -> "not an order";
}; }

Simplifying expressions with nested patterns

  
P102 models string expressions as records: Literal, Variable and Concat. Simplification rules become one case each: Concat(Variable(var n), Literal(var t)) when t.isBlank() → just the variable. Build an expression and simplify it.

  

    
Left:Right:

    

    

  

  
static Str shorten(Str s) { return switch (s) {
    case Concat(Variable v, Literal(var t)) when t.isBlank() -> v;
    case Concat(Literal(var t), Variable v) when t.isBlank() -> v;
    case Concat(var a, var b) -> new Concat(shorten(a), shorten(b));
    default -> s;
}; }

  
Unnamed patterns and variables (P103)When you need the shape but not every component, JDK 21 previewed _: case Order(Customer(var n, _), _) -> .... It also works for ignored lambda parameters and catch variables: catch (NumberFormatException _). Finalized in JDK 22.

Records in Spring Boot, JPA and jOOQ

  
The chapter ends with three frameworks (P104–P106). The short version: records are ideal wherever data is carried, and a poor fit wherever a framework needs to mutate or proxy an object.
