Data structures the JDK doesn't ship

The JDK gives you lists, hash maps, trees and heaps. The second half of chapter 5 implements a dozen structures that each make one operation dramatically cheaper (P119–P130). This page draws six of them in detail and summarizes the rest. Tap a card for the one-line pitch.

2

Rope: a string as a tree

Concatenating or inserting into a huge String copies the whole thing. A rope (P119) keeps short strings in leaves and joins them with nodes that store a weight: the length of their left subtree. Concatenation is just a new root, O(1). To find character i, go left if i < weight, otherwise subtract the weight and go right. Pick an index.

3

Skip list: express lanes over a linked list

A sorted linked list needs O(n) to find anything. A skip list (P120) adds higher "express" levels: each node is promoted to the next level with probability ½ (a coin flip). Search starts top-left, moves right while the next key is smaller, then drops down. Expected cost: O(log n), with no rebalancing at all. Java's ConcurrentSkipListMap uses exactly this.

K-D tree: split space, then search a little of it

A k-d tree (P121) stores points in k dimensions. Each level splits on one axis in turn: x, then y, then x. Nearest-neighbour search walks down to the cell containing the query, then backtracks only into cells that could hold something closer. Click anywhere to query.

Huffman coding: short codes for common symbols

Huffman's algorithm (P126) repeatedly takes the two least frequent symbols (or subtrees) from a priority queue and joins them. Frequent symbols end up near the root, so they get short codes, and no code is a prefix of another, so the bit stream decodes without separators. Type something.

6

Splay tree: what you touch moves to the top

A splay tree (P127) is a binary search tree that, after every access, rotates the accessed node up to the root with zig, zig-zig and zig-zag steps. Recently used keys stay near the top, which makes it a natural cache, and the amortized cost is O(log n). Click a key to access it.

7

Three ways to join two tables

P130 implements the join algorithms databases use. Nested loop compares every pair. Hash join builds a hash table on the smaller side, then probes it once per row of the other. Sort-merge sorts both sides on the key and walks them together like a zipper. Change the sizes and compare the work.

Recap on one page

RopeO(1)-ish concat, O(log n) index via left weights.
Skip listCoin-flip levels give O(log n) search without rotations.
K-D treeAlternate axes; prune whole regions in nearest-neighbour search.
