SRP: The Single Responsibility Principle

The most misunderstood SOLID principle is not about doing one thing. It says a module should answer to one group of people, so one group's change can't break another's numbers.

1

Not "do one thing"

SOLID is five principles for the mid-level: how to group functions and data into classes (any coupled grouping, OO or not) and how those groups should connect. The goal is structures that tolerate change, are easy to understand, and can be reused across systems. The first, the Single Responsibility Principle, has a misleading name. "Every function should do one thing" is a real rule, used when refactoring big functions, but it's not the SRP. Step through how the wording sharpens.

A module should have one, and only one, reason to change.Classic phrasing. But what is a "reason"?
A module should be responsible to one, and only one, user or stakeholder.Reasons to change are people. But several people may want the same change.
A module should be responsible to one, and only one, actor.An actor is a group of people who want the system to change in the same way.

A "module" is usually a source file, or more generally a cohesive set of functions and data. Cohesion is the force that binds together the code responsible to a single actor.
