LSP and ISP

Two principles about promises. Anything plugged in behind an interface must keep the interface's promises, and nobody should be forced to depend on promises they don't use.

LSP: substitutes must keep the promise

Barbara Liskov's 1988 definition of a subtype, in plain words: S is a subtype of T if any program written for T behaves the same when you hand it an S instead. A Billing app calls license.calcFee(); personal and business licenses compute fees differently, but Billing doesn't care which one it got. Both are substitutable. The famous counter-example is the square.

// User code, written against Rectangle
function check(r) {
  r.setWidth(5);
  r.setHeight(2);
  assert(r.area() === 10);
}

A square's sides must change together; a rectangle's change independently. The only defense is for the user to add if (r instanceof Square), and as soon as the user's behavior depends on the type, the types aren't substitutable.

LSP at architecture scale: the taxi aggregator

Early on the LSP was seen as a guide to inheritance. It has grown into a rule about interfaces and implementations of every kind: Java interfaces, Ruby duck types, or a set of services that all answer the same REST interface. Imagine a site that dispatches taxis from many companies. Each driver record stores a dispatch URI, and the system appends pickupAddress, pickupTime and destination. One big company's programmers abbreviated destination to dest. Dispatch some rides.

One broken substitute, lots of extra machineryHard-coding a company name invites mysterious bugs and even security holes. The sane fix, a dispatch-format table driven by configuration, is real complexity added to the architecture only because one implementation didn't honor the interface.

ISP: don't depend on what you don't use

  
Three users each call one operation of a class OPS. In a statically typed language, User1's source still depends on the whole class, including op2 and op3 it never calls. Change op2 and User1 recompiles and redeploys for nothing. Segregate the operations into interfaces and see the difference.

In dynamically typed languages (Ruby, Python) there are no such source declarations to import, so this recompile problem doesn't arise. That makes those systems more flexible and less coupled. But the ISP isn't merely a language quirk.
