Introduction

This volume teaches non-programmers to direct Claude Code: design something, get a checked first version, build it up feature by feature, then publish it. Here is how the volume is organised and the vocabulary it relies on.

1

From chatting with Claude to building with it

Most people meet Claude through conversation: ask, read, ask again. This volume is about the next step, using Claude Code to make things other people can open or install: a website at a public address, or an app on a phone. You do not need to learn JavaScript, Swift or Kotlin syntax. Claude Code writes the code; you decide what to build and judge whether it is right.

The author's complaint about other guides: they drown beginners in internals, or spread thin over everything, or follow one big project you never wanted. His alternative is a path that matches how people actually succeed with AI. Step through it.

2

Three books, one destination

The volume holds three books. Each ends with a project of your own, so you finish every book holding something real rather than a pile of theory. Read them in order: Book 3's mobile app assumes the web skills of Book 2, which assume the safe working habits and Git skills of Book 1.

Book 1Build ToolsVS Code workspace, build briefs, clear prompts, plans, Git checkpoints, one-cause-at-a-time debugging. Ends with a command-line tool.
Book 2Build and Publish WebsitesHTML, CSS, responsive layout, navigation, JavaScript, a contact form, an audit, and a live public site.
Book 3Build and Ship Mobile AppsReact Native and Expo: screens, navigation, stored data, reminders, real-device testing, beta testing and store submission.

3

The recurring boxes in every chapter

Each chapter mixes explanation with labelled boxes. Tap one to see what it is for. You don't need to act on every box; read the ones that help with what you're doing right now.

Most chapters end with Try it now (a 5–15 minute task; the three projects take an hour or more) and Check the result questions, so reviewing Claude's work becomes a reflex.

4

How the book copes with a fast-changing product

Claude Code's menus, buttons and modes change often, so the book teaches decisions that last (is this code doing what it should? is this screen easy to understand?) and pairs every instruction with a stable landmark (what a menu is for) plus the label currently on screen. If the label moves, the landmark still points you there. Details likely to move live on an online changes page, organised by chapter, under five headings.
