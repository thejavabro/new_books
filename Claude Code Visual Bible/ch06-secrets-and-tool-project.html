What a permission request protects you from

In Auto mode every action passes a safety check first. Reading files inside your project almost always sails through, because reading changes nothing. Actions that are hard to undo (deleting) or that reach outside your project (sending data to a service) are far more likely to stop and ask, or be swapped for a safer route. If several actions in a row get stopped, Claude Code switches to asking about everything for the rest of the session, like Manual mode, so you can see what's being proposed. A familiar, specific command can usually be approved permanently for a project; anything unfamiliar still asks. Tap an action to see where it lands.

Keep keys out of your code and out of Git

An API key is a password that lets your project use an outside service. Commit one and push it to GitHub and anyone may see it, even after you delete it, because Git keeps old versions. The standard pattern: keep keys in a file named .env, and list it in .gitignore so Git never includes it. Claude Code may decline to write real secrets into a .env for you, but it will happily prepare a .gitignore that excludes .env and its variants while still allowing a harmless .env.example that documents which variables are needed.

# Environment / secrets
.env
.env.*
!.env.example

Question packages, claims and your own prompts

Before a new package joins the project, ask three things: what does it do, is it actively maintained, and does the project actually need it? One reader asked out of habit and learned the date library he was about to use hadn't been updated in years; a maintained alternative did the same job. The same scepticism applies to statements: a claim about pricing, the law or security is something to verify, especially where money, privacy or safety is involved.

Paste into a prompt, or keep out?

The test the book suggests: would you be comfortable seeing this text in a public place, or in an email to a stranger?

Book 1 project: a command-line tool you would use

A command-line tool reads some input, does one job and prints a result. Small enough to finish, real enough to keep using. No new skill here, just every habit so far on one project.
