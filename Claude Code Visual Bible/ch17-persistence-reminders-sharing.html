Persistence, Reminders and Sharing

Make habits survive a restart, handle the awkward states every real app has, ask for notification permission at the right moment, and keep reminders in step with deletions.

1

Make habits survive closing the app

So far the habits live only in the app's working memory: close or reload it and everything resets. Persistence means saving data somewhere that outlives the app. For an offline-first app that place is the phone itself. AsyncStorage is the standard way an Expo app saves simple data on the device: save the list whenever it changes, load it on start. Test with a genuine force-close, not just navigating away and back; some saving problems only show after a real restart.

AsyncStorage is not encryptedFine for habit names and completion dates. Never for a password, a private key or anything genuinely sensitive, in this app or any other.
Worth re-checkingThe book points to Expo's documentation for choosing between on-device storage options, which differ in size limits and security. Recommended libraries for this shift over time.
2

Empty, loading and corrupted

A real app plans for more than the happy path. A brand-new user with no habits needs a clear empty message, not a blank. The brief loading moment while storage is read must not look like "empty"; one reader was confused by "No habits yet" flashing before his habits appeared. And stored data that can't be read (corrupted) must lead to a graceful recovery, not a crash. Ask Claude to simulate the corrupted case for you.

3

Ask for notification permission when it makes sense

Every reminder needs the user's permission. Asking the instant the app opens, before anyone has a reason to want reminders, tends to get refused. Asking when the user sets their first reminder time gives the request context, the same principle as Book 1's permission habit. Because a reminder can be set from Add Habit or from editing on Habit Detail, the check belongs in one shared place, not duplicated per screen. Step through both experiences.

4

Schedule local reminders, and keep them in step

A local notification is generated and delivered by the phone itself, no server, which suits the offline-first design. Set a reminder a few minutes ahead to prove it arrives, then prove it stops when cleared. Two gaps the book calls out: habits created in earlier chapters may already hold a reminder time with nothing scheduled, so reconcile them on the next launch; and deleting a habit must cancel its notification. One reader kept getting reminders for a habit deleted two days earlier.
