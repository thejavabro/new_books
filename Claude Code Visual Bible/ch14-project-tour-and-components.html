Tour the Expo project before changing it

An Expo Router project is organised around five kinds of thing: routes (files in app/, where each file's location becomes a screen and its address, much as each HTML file became a page in Book 2), components (reusable interface pieces screens are built from), assets (images, icons, fonts), configuration (such as app.json: name, icon, settings) and packages (listed in package.json). And one giant folder you will never open: node_modules. Tap through a typical starter project.

What kind of file?

Give me a plain-language map of this whole project: what each main folder is for and how a screen gets built from the pieces. Then tell me where my three planned screens would likely go.

Follow one import from a screen to its source

An import brings something defined in one file into another. Following just one by hand makes the project feel far less intimidating than trying to understand every file at once; that was exactly what helped one overwhelmed reader in the book. Step along this one.

app/(tabs)/index.tsx (a route)
import { HelloWave } from '@/components/hello-wave';
…
<HelloWave />
tsconfig.json (configuration)
"paths": { "@/*": ["./*"] }
components/hello-wave.tsx (a component)
export function HelloWave() {
  return <Animated.Text>👋</Animated.Text>;
}
3

Native components: View, Text and Pressable

Where Book 2 used HTML elements, React Native uses native components that render with each phone's own real interface pieces. Three cover most of HabitTrail: View to arrange or group things and add spacing or a background, Text for any text or number, and Pressable for anything the user taps. In a habit card, the card and screen background are Views, the name and streak are Texts, and tapping to toggle today is a Pressable.

Big enough for a finger

  
A phone is touched with a fingertip, not clicked with a precise cursor. A reader's first HabitCard checkbox looked fine on his computer and was fiddly on his phone; checking against standard touch-target guidelines (commonly around 44 to 48 points or density-independent pixels; check Apple's and Google's current guidance) and testing on a real device fixed it. Shrink the target and see how much of the fingertip misses.

Keep clear of the notch and the gesture bar

  
Parts of the screen can be covered by a notch, a camera cut-out or the home-gesture bar. A layout can look perfect in a screenshot or in code and still tuck the title under the notch. Toggle safe-area handling and check on a real device.
