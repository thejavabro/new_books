HabitTrail becomes an offline-first iOS and Android app. Scope it to one person and one habit, map three screens, then create an Expo project and see it live on your phone.

1

Design around one person and one repeated habit

Book 3 turns HabitTrail into a real iOS and Android app with React Native, Expo, Expo Router and TypeScript. It stays offline-first throughout: everything happens on the user's own phone, with no account, no server and no internet needed. That keeps it finishable while still teaching real mobile skills. Start with one specific, believable person and the thing they repeat, like reading ten minutes a day or drinking more water. "Habits in general" designs nothing; a concrete habit tells you what each screen must show. One reader tracking a stretching routine realised her Add screen needed a reminder time and nothing more elaborate.

First version, or deliberately later?

The smallest useful version: add a habit, mark it done today, see how you're doing. Reminders and sharing do arrive later in the book (Chapter 3.10), but anything beyond one daily reminder time stays out.

Your computer runs it, your phone shows it

  
Expo handles most of the setup a mobile app normally needs. Expo Go is a free phone app that runs your in-progress project directly, no store build required. You need Node.js on the computer and Expo Go on the phone. Because requirements change between versions, ask Claude to check the current ones rather than trusting an old guide:

  
Check the current requirements for creating a new Expo app: which Node.js version I need and anything else to install. Tell me what is missing on this computer before installing anything.

4
Why the book pins Expo SDK 54

  
May have changed since publication: version-specificAt the time of writing (September 2026), the book reports that the store versions of Expo Go on both iOS and Android only supported projects built with Expo SDK 54, even though newer SDKs (up to 57) existed, because an Expo Go update for later SDKs was awaiting App Store approval. The workaround, eas go, builds a personal Expo Go delivered through TestFlight but needs a paid Apple Developer account. The book therefore sticks to SDK 54. This is exactly the kind of detail likely to be out of date: check Expo's documentation and the version shown in Expo Go before creating your project.

  
The rule that will outlast the specific numbers: Expo Go on the phone must support the SDK your project was created with. Try combinations based on the situation the book describes.

Stopping the app cleanly

  
On the computer, press Ctrl+C in the terminal running npx expo start; you'll see "Stopped server". On the phone just swipe Expo Go away: it was only connected to your computer over Wi-Fi. If restarting complains that the port (usually 8081) is in use, a lingering process is holding it, especially on Windows. Find its process ID with netstat and end it with taskkill, or ask Claude to do it with you.
