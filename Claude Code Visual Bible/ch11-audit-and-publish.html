Audit the Site and Publish It

Before strangers see the site, audit it for keyboard access, speed and how it looks when shared. Then push to GitHub, host it, and verify it from a different device.

1

One page, three kinds of reader

Before publishing, stop adding and audit the whole site in one sitting, because problems interact: an oversized image slows the page and also delays a screen reader reaching real content. The same page must make sense to a visitor (by keyboard as well as mouse), to a search engine, and to a link preview in a chat app, all from the same title, description and structure.

2

Find what slows the page down

Slow pages lose visitors before they see anything. The usual fixable culprit is images: a photo straight off a phone can be several megabytes when a few hundred kilobytes would look the same. The other fix is letting images below the visible screen load later so the top of the page appears first. Try it.

3

Title, description and social card

Three things in each page's <head> decide how it appears beyond your browser: the title (browser tab and search results), the description (the summary under a search result), and social card tags (Open Graph) controlling the preview when a link is pasted into a chat or post. Each page needs its own accurate pair, not one generic text everywhere. One owner in the book found out from a group chat that her site previewed as "Untitled" with a broken image.

GitHub Pages or Netlify?

  
Both are free and both turn a GitHub repository into a live site. The deciding question for HabitTrail is the contact form. GitHub Pages only serves files; a form needs a separate service such as Formspree. Netlify can collect form submissions itself with one added attribute, viewable in its dashboard. That's why the book uses Netlify; for a site with no form, Pages is the simpler choice. Answer for your site:

From your folder to a public address

  
Run a last visitor's-eye pass (every page, the nav, the form, the theme) and fix what you find. Then follow the path. You'll need free GitHub and Netlify accounts.

6
Check it like a stranger would

  
Once it's public, search engines may index it within days, so first make sure there's no stray test message, placeholder image or unfinished section. Then test from a device and network you didn't build on, ideally your phone on mobile data: a freelancer in the book learned from a friend the next morning that her form was broken on mobile. Updating later is the same commit habit: push a commit and Netlify republishes automatically.
