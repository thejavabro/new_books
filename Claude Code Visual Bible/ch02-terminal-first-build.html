The Terminal and Your First Build

Just enough terminal to stand in the right folder, then one full trip around the loop: ask for a tiny page, watch how Claude Code asks permission, and prove the result yourself.

1

Prompt, path and current folder

A terminal (or command line) is a window where you type commands instead of clicking. Open one in VS Code with View | Terminal. The short line ending in $ or > is the prompt, waiting for you, and it shows your current folder: where your commands act. Every file has a path, an exact address like C:\claude\my-first-project. Think of the current folder as where you are standing and a path as directions to somewhere else.

Glance before you actA command typed in the wrong folder creates files in the wrong place, or points Claude Code at the wrong project. Read the folder name in the prompt before running anything that changes something.
2

Five commands, practised in a pretend terminal

You need only a handful: cd name to step into a folder, cd .. to step out, ls (or dir on Windows Command Prompt) to list, mkdir name to create a folder, and Ctrl+C to stop whatever is running. The up arrow recalls your last command. This simulator also understands claude, /usage and /exit. Nothing here touches your real computer.

3

Installing the claude command

The VS Code extension gives you a friendlier interface, but the claude command itself is installed separately with a one-line installer: a PowerShell command on Windows, a curl … | bash line on macOS and Linux. On Windows the installer may warn that its folder isn't on your PATH; the fix is to add that folder to your user Path environment variable and restart VS Code. Then, from your project folder, type claude. The first run walks you through a colour theme, a login method (normally your Claude subscription), some security notes, and a "do you trust this folder?" check.

May have changed since publicationThe book shows a specific installer output (a version in the 2.1 series), three login choices (subscription, Anthropic Console billing, or a third-party cloud platform), and the /usage command for checking how much of your plan's usage window remains. Installer URLs, version numbers, login options and slash commands are exactly the kind of detail that moves. Check the current CLI reference at code.claude.com/docs before copying commands.
Check your usage before a long taskOn a subscription, /usage shows how much of the current window is left and when it resets (pay-per-use accounts see a running cost). Look before you start something demanding, not when a limit interrupts you halfway.
4

Ask for something tiny and specific

Your first real request: one page, one heading, one short paragraph. Naming the exact file, the exact heading text and what to leave out gives you a target you can verify at a glance. Something like:

Create one HTML file named index.html. Give it the heading "Hello, Builder" and a single short paragraph introducing me as someone learning to build with Claude Code. No styling, no extra sections.

Compare that with "build me a website", which leaves Claude to guess almost everything and leaves you nothing specific to check.

5

How much Claude Code checks with you

Before acting, Claude Code decides how much to ask you. The book describes a mode indicator in the chat panel with these choices. Pick a mode and see how four actions would be handled.

While you are learning, the book suggests Manual, so you see every request; switch back to Auto once you trust its judgment on routine work. Leave Bypass Permissions alone: it removes the safety net the whole book relies on. Whatever the mode: read before you approve.

May have changed since publicationMode names, which mode is the default, and exactly what Auto mode lets through are product decisions that have shifted before and may shift again. The principle (see risky actions before they happen) is the part to hold on to. Anthropic's permissions page has the current list.
6

Open the result and prove it works

A file existing isn't the same as a working result. Open index.html in your browser and check three things. This version of the page has a surprise in it: Claude sometimes adds small "helpful" extras you didn't ask for. Tick only what is actually true.

Hello, Builder

I'm learning to build things with Claude Code, one small step at a time.

Thanks for visiting! Follow me for more.

That is one full trip round the loop: request, plan, approval, edit, your own check. A good follow-up is a single focused change ("change the heading to 'Hello again', leave everything else the same"), the move you'll make constantly from now on.
