Failure Detection and Leader Election

Two small chapters about two questions every cluster must answer: is that node dead, or just slow? And if the leader is gone, who takes over?

1

Dead, or just slow?

Without timing assumptions you can't tell a crashed process from a slow one (that's FLP again). A failure detector is a local component that decides which peers to suspect, so algorithms can exclude them and keep making progress. Two properties matter. Liveness: something good eventually happens (a real failure is eventually detected). Safety: nothing bad happens (a live process isn't declared dead). Detectors trade efficiency (how fast) for accuracy (how often right); you can't have both perfectly, so false positives are allowed. Tune a timeout and see.

Heartbeats every 100 ms; the peer really crashes at t = 2000 ms.

2

Heartbeats, pings and outsourced heartbeats

A ping asks "are you alive?" and waits for a reply; a heartbeat is the peer announcing "I'm alive" on its own. Either way, a missed deadline marks the peer as suspected, as in Akka's deadline detector. One node's view is fragile: a bad link between P1 and P2 looks like P2 is dead. SWIM uses outsourced heartbeats: if P2 doesn't answer, P1 asks a few random members to ping P2 on its behalf and relay the result.

Without timeouts at allThe Heartbeat algorithm (a timeout-free detector) forwards heartbeats along paths: each process increments counters for everyone in the path and forwards to those not yet in it. Counters give a global, relative view, so a peer reachable only indirectly still looks alive. The hard part is choosing the threshold to interpret those counters.
3

The phi-accrual failure detector

Instead of a yes/no timeout, φ-accrual (used by Cassandra and Akka) outputs a continuous suspicion level. It keeps a sliding window of recent heartbeat inter-arrival times, assumes they're roughly normal, and asks: how unlikely is it that the next heartbeat still hasn't arrived after this long? φ = −log₁₀(P(arrival later than now)). φ = 1 means about a 10% chance of being wrong, φ = 3 about 0.1%. Because the window tracks real conditions, a jittery network automatically gets more patience. It splits into monitoring, interpretation and action.

4

Gossip-style failure detection

Each member keeps a table of every member's heartbeat counter and the local time it last increased. Periodically a member bumps its own counter and sends its table to a random peer, which merges it (keeping higher counters). A member whose counter stops rising for long enough is considered failed. The verdict is an aggregate of many views, so a single broken link doesn't cause a false alarm: news travels around it.

FUSE: turn one failure into a group failureFUSE arranges processes into groups that ping each other. When a member sees a failure, it stops answering pings itself, so silence spreads until every member knows the group has failed. Every member is guaranteed to learn of it, even across partitions; the flip side is that a single bad link also takes down the whole group.
5

Leader election: why and what it guarantees

Coordinating every step with every peer is expensive. A leader (coordinator) can order messages, hold global state and drive the algorithm, cutting round trips. Leaders are long-lived but not permanent: when one fails, an election picks a successor. Liveness: there is a leader most of the time and elections finish. Safety would be "at most one leader", but most election algorithms can violate it in a partition, producing split brain. A single leader can become a bottleneck, so systems like Spanner partition data and give each replica set its own leader. Unlike a distributed lock, everyone must know who the leader is, and a long reign is a feature.

6

The bully algorithm

Every process has a rank; the highest-ranked live process wins. A process that notices the leader is gone (1) sends Election to all higher-ranked processes, (2) if any answer Alive, hands over to the highest of them, (3) otherwise declares itself and broadcasts Elected to the lower ranks. Pick who notices, optionally cut the network, and run it.

7

The ring algorithm

Nodes form a logical ring and know their successors. The detector sends an election message around the ring; each live node adds itself to the collected set, and unreachable nodes are skipped. When the message returns to the initiator, the highest rank in the set wins, and a second lap announces it. (A variant carries only the running maximum.) A partitioned ring can still elect two leaders.

Electing a leader is consensusAll these algorithms can produce two leaders. To rule out split brain you need a cluster-wide majority, and agreeing on a leader is itself a consensus problem. Multi-Paxos and Raft therefore tolerate brief overlaps and resolve them: a proposer with an older ballot or term gets rejected and steps down. Leadership is a performance optimization; safety comes from the consensus protocol (chapter 14).
