Anti-Entropy and Dissemination

Replicas drift. Anti-entropy is the collection of background and foreground tricks that notice the drift and pull replicas back together, and gossip is how news spreads through a large cluster without anyone in charge.

1

Three ways to spread information

Cluster metadata (who joined, who failed, schema changes) and lost writes both need to reach every node. Three broad patterns: broadcast from one node to everyone (simple, but one sender carries all the load and must be up), anti-entropy where peers periodically compare and fix differences pairwise, and gossip, where every recipient helps spread the update. Entropy here means how far replicas have drifted apart; anti-entropy mechanisms push it back down, either in the background (Merkle trees, logs) or piggybacked on reads and writes (read repair, hinted handoff).

2

Read repair

Reads are a natural moment to spot divergence: the coordinator asks several replicas for the same key and compares answers. If one is behind, it sends it the newer value. Blocking read repair waits for the repair to be acknowledged before replying, which guarantees monotonic reads for quorum reads but costs latency and availability. Asynchronous repair replies first and fixes later.

3

Digest reads

Shipping full results from every replica wastes bandwidth. Instead, the coordinator asks one replica for the data and the others for a digest: a hash of what they would have returned. If all digests match the hash of the full read, done. If one differs, the coordinator can't tell who is ahead, so it falls back to full reads from the mismatching replicas and reconciles. The hash needs to be fast rather than cryptographic; a rare collision is caught by other anti-entropy layers.

Hinted handoff and sloppy quorums

Write-side repair. If a target replica doesn't acknowledge, another node keeps a hint: the write plus a note of who it was really for, replayed when the target returns. With a sloppy quorum (Riak), the write may be counted on a healthy node outside the replica set, so writes stay available. The price: a read that only reaches the "real" replicas may miss it.

5

Merkle trees

Read repair only fixes keys someone reads. To find differences in cold data without comparing every record, each replica hashes ranges of its data, then hashes pairs of hashes up to a single root. Equal roots mean equal data. If roots differ, descend only into children whose hashes differ. Edit records on replica 2 and watch how few comparisons pinpoint the damage. The catch: a change means recomputing hashes up to the root, and bigger leaves make the tree smaller but repairs coarser.

6

Bitmap version vectors

Another approach keeps track of exactly which writes each node has seen. Every write coordinated by node n gets a dot (i, n): its local sequence number. A node's view of each peer is a set of dots, stored compactly as (highest contiguous number, bitmap of extras beyond it). Gaps are exactly the writes to fetch during sync. Once everyone has a contiguous prefix, it can be truncated; a long-dead node blocks truncation.

7

Gossip: spreading like an epidemic

Gossip borrows from epidemiology. A node holding new information is infective; one that hasn't heard is susceptible; one that has lost interest is removed. Each round, every infective node contacts fanout random peers. Nodes stop after hearing the rumor again too often (or with some probability per round). Duplicate deliveries (redundancy) are the price of robustness. Messages reach everyone in about log N rounds.

8

Overlay networks and hybrid gossip

Pure gossip is robust but wasteful. A spanning tree delivers each message exactly once per node in a fixed number of hops, but one broken link cuts off a whole subtree. Plumtree combines both: messages travel eagerly along a tree, while every other link carries only message IDs lazily. A node that sees an ID for a message it never got asks for it and grafts that link into the tree, so the tree heals itself, and tends toward the fastest links.

Solid: eager tree links. Dotted: lazy links that only carry IDs.

Partial views (HyParView)Nobody needs the full membership list. Each node keeps a small active view (peers it gossips to) and a larger passive view (spares). Nodes periodically shuffle views with peers. When an active peer fails, a passive one is promoted; a node with an empty active view gets priority so newcomers join quickly. Plumtree runs over these views; Riak and Partisan use them.
