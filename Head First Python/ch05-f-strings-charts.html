Squash big numbers into a pixel range

  
Times in hundredths run into the thousands, which would make bars thousands of pixels wide. The book's helper module provides convert2range: a linear mapping from one range to another. Here is the idea as a short function, with a slider to see what it does.

  
def convert2range(v, f_min, f_max, t_min, t_max):
    """Map v from the range f_min..f_max onto t_min..t_max."""
    return round(t_min + (t_max - t_min) * ((v - f_min) / (f_max - f_min)))

Write the file, then open the browser

  
The open BIF writes as easily as it reads: pass mode "w" to create (or overwrite) a file, and call write. Then the standard library's webbrowser module opens it. Three lines take a string to a chart on screen.

  
CHARTS = "charts/"
save_to = f"{CHARTS}{filename.removesuffix('.txt')}.html"
with open(save_to, "w") as sf:
    print(header, body, footer, file=sf)     # print can write to a file too
webbrowser.open("file://" + os.path.realpath(save_to))

6
round() rounds; it doesn't format

  
One chart showed an average ending ".2". Was that .20 or .02? The culprit was using round() and then str() for display. Rounding is arithmetic: 0.20 and 0.2 are the same number, so the zero vanishes. For display you want a format specifier after a colon inside an f-string: :.2f means two decimal places, :02 means at least two digits, padded with zeros.
