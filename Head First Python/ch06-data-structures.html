Getting Organized: Data Structure Choices

Lists are great for order and terrible for lookup. The dictionary turns "find this swimmer's files" from a scan into a single step.

The list-set-list trick

The Coach wants to pick a swimmer, not a filename. Pulling the name off the front of each of the sixty filenames gives sixty names with plenty of repeats, because most swimmers have several files. A set keeps only unique values, so convert the list to a set, then back to a list (sets have no order, and you want to sort for display). Step through it.

names = []
for fn in os.listdir(FOLDER):
    names.append(fn.split("-")[0])
names = sorted(list(set(names)))      # the list-set-list trick
2

Add the filename and the trick stops working

Picking a name is only half the job: the app also needs each swimmer's files. If you store (name, filename) tuples instead of names, every tuple is different, because every filename is. The set has nothing to remove, and finding one swimmer's files means scanning the whole list with a loop, every single time.

3

Searching a list versus looking up a key

Lists are perfect when order matters. They are poor at "find the thing called X": for and even in have to check items one at a time, so the work grows with the list. A dictionary (Python's associative array, map or hash) jumps straight from a key to its value, and its speed barely changes as it grows. Pick a list size and a swimmer to find.

list: check each item until a match
dict: hash the key, go straight there
4

Key/value rows with square brackets

A dictionary is a set of rows, each a key and a value joined by a colon, inside curly braces. Keys must be unique; values can be any object at all. Square brackets do the work: d[key] reads a value, and d[key] = value either creates a new row or replaces the value if the key already exists. Dictionaries are mutable and grow as you add.


    

    

  






  
5
Lists and dictionaries are best friends

  
The answer for the Coach combines both: a dictionary whose keys are swimmer names and whose values are lists of that swimmer's filenames. Build it once in a single pass over the folder. If a name is new, create the row with a one-item list; otherwise append to the existing list. After that, one lookup gives everything for one swimmer.

  

    
swimmers = {}
for fn in os.listdir(FOLDER):
    name = fn.split("-")[0]
    if name not in swimmers:
        swimmers[name] = []
    swimmers[name].append(fn)

swimmers["Katie"]   # all of Katie's files

    

  

  

    
print versus pprint

    

    
A big nested dictionary printed with print is one long line. The standard library's pprint module ("pretty print") lays it out over several lines.
