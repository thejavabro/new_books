Working with Data: Data Manipulation

1

From a list of rows to a dictionary of dictionaries

The scraper left a flat list of (event, time) rows, table after table. To answer "what is the record for women's 100m butterfly in a 50m pool?" you'd scan it. Reshape it once into a dictionary of dictionaries: the outer key names the table (course and gender), the inner key names the event, and the value is the record time. Then the question is two square-bracket lookups.

before: a list of tuples
after: dict of dicts

Record times are sample values for illustration.

2

A small dictionary as a translation table

The Coach's filenames say Fly; the scraped tables say butterfly. Filenames carry an age but no gender, and the pool length is a separate fact. Instead of a pile of ifs, a tiny dictionary maps one vocabulary to the other, and an event_lookup function turns any filename into the keys of the records dictionary. Pick a file.

CONVERSIONS = {
    "Free": "freestyle",
    "Back": "backstroke",
    "Breast": "breaststroke",
    "Fly": "butterfly",
    "IM": "individual medley",
}
3

Too much data? Filter it

The tables also hold relay records, which the Coach doesn't need. When building the inner dictionaries, skip any event whose name contains "relay". It is a one-word condition: if "relay" not in event:.

4

Save the dictionary as JSON

The scraped records should be fetched once and reused, not re-scraped on every chart. The standard library's json module writes nested dictionaries and lists to a text file with json.dump and reads them back with json.load. JSON is textual, language-neutral and readable (if not pretty). It does have limits: it has no notion of sets, tuples come back as lists, and dates need converting to strings first. Try saving different values.


  

  
import json
with open("records.json", "w") as jf:
    json.dump(records, jf)

with open("records.json") as jf:
    records = json.load(jf)






  
5
A world record under every chart

  
Integration is an edit and a copy-and-paste: the chart code loads records.json, calls event_lookup on the filename, and adds the record as a reference bar (and a line of text) at the bottom of the chart. Now the Coach can see how far each swimmer is from the best in the world.

  

    

    
  






  
6
A utility that refreshes the records every night

  
Records change. Rather than re-scrape by hand, the notebook code becomes a small standalone program, update_records.py, which you run from a terminal with python3 update_records.py. Test it locally first, upload it with the webapp, and ask PythonAnywhere's Tasks tab to run it every day (the book picks 1:00am). The webapp itself never scrapes; it just reads the latest JSON.
