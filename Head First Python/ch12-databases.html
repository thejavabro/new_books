When files stop being enough

Disaster, of a small kind: someone copied the latest session's files into the data folder, and every filename that matched overwrote last week's data. Files named by swimmer and event have no room for when. Swapping folders per session would break when two people use the app at once. The grown-up answer is a database, and Python ships with one: SQLite, a file-based engine that needs no server and no admin. You talk to it in SQL, from Python.

2

Three tables on a napkin

Plan before you code. One table lists swimmers (a swimmer is a name plus an age group), one lists events (a distance plus a stroke), and one records times. Each times row points at a swimmer and an event by their id, and carries a timestamp, so sessions never overwrite each other. Tap a column to see what it links to.

3

Connect, execute, commit, close: with does it

The book uses DBcm from PyPI, a small context manager. Give UseDatabase a filename and it uses SQLite (give it a dictionary of credentials and it uses MySQL/MariaDB, as in chapter 14). Inside the with block you get a cursor and call execute; when the block ends DBcm commits your changes and closes the connection. The same with idea as files in chapter 3.

import DBcm

DB = "CoachDB.sqlite3"
SQL_CREATE = """
    create table if not exists swimmers (
        id integer not null primary key autoincrement,
        name varchar(32) not null,
        age integer not null
    )
"""
with DBcm.UseDatabase(DB) as db:
    db.execute(SQL_CREATE)
Triple quotes for SQLSQL reads best on several lines. A triple-quoted string can span lines without any escaping, so put each query in one, assigned to an UPPERCASE name.
4

Never build SQL with f-strings

It is tempting to drop values into SQL with an f-string. Don't. If a value contains SQL, the database runs it: that is an SQL injection attack. Use placeholders instead: ? in SQLite (%s in MariaDB), with the values passed separately as a tuple. The driver treats them strictly as data. Type a nasty "name" and compare.

5
Getting results back: fetchall, fetchmany, fetchone

  
Statements like insert and create return nothing; a select does. After db.execute(SQL_SELECT), the Python DB-API gives you three ways to collect rows: fetchall() returns a list of tuples (an empty list if nothing matched), fetchmany(n) returns up to n at a time (handy for paging), and fetchone() returns a single tuple.

  

    

    

    
  






  
6
Put the loop inside the with, not around it

  
Filling the tables means inserting hundreds of rows. Connecting, inserting one row and disconnecting inside a loop makes the database set up and tear down a connection every time. Open one connection with with, then loop inside it. Your database (and whoever runs it) will thank you.
