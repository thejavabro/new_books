List Comprehensions: Database Integrations

Python programmers love list comprehensions: a five-line loop in one readable line. You'll need them as the webapp starts reading from the database.

1

Five lines of loop become one

Over and over you've written: make an empty list, loop, transform each item, append. A list comprehension says the same thing in one line, inside square brackets: the expression first, then the for, then an optional if. It is shorter, typically faster, and, unlike a loop statement, it is an expression, so it can go anywhere a value can (a return, an argument, a template variable). Step through the transformation.

2

Build a comprehension and run it

Comprehensions come in two flavours. Transforming ones (mappings) produce a new value for every item. Filtering ones have an if and keep only some items. Many do both. Pick the parts and the result updates live on a list of times from a database query.


    

    

  

  
Set and dict comprehensions tooSwap the square brackets for braces and you get a set comprehension; add key: value and it's a dictionary comprehension: {name: len(files) for name, files in swimmers.items()}. There is no tuple comprehension (parentheses give you a generator instead).

Four queries, four small functions

  
The webapp now gets its data from the database, not the folder. Each question the Coach asks becomes one SQL query, and each query is wrapped in a short function in a data_utils.py module, with placeholders for its inputs. Results arrive as lists of tuples, so a comprehension often tidies them into a plain list. Follow the Coach's clicks through the chain.

  
def get_swim_sessions():
    with DBcm.UseDatabase(DB) as db:
        db.execute(SQL_SESSIONS)
        return [row[0] for row in db.fetchall()]   # list of tuples → list of dates

The chart moves into a Jinja template

  
Chapter 8 left the bar-chart HTML inside a Python f-string. Now it moves into a Jinja2 template: Python computes the numbers (scaled widths, times, the record) and passes them to render_template; the template's {% for %} loop writes one <rect> per time. Logic in Python, presentation in templates, and the chart finally inherits the site's stylesheet.

  
{% for width, time in data %}
  <svg height="30" width="400"><rect height="30" width="{{ width }}"></rect></svg>{{ time }}<br>
{% endfor %}






  
5
list(zip(...)): pairing two lists

  
That template wants pairs of (width, time), but the code has two separate lists. The zip BIF walks several sequences in step and yields tuples of matching items, like the teeth of a zip coming together. It stops at the shortest input. zip is lazy (it hands out pairs on demand), so wrap it in list() to see them all at once.
