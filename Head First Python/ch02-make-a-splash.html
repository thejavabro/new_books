The Coach's problem

A swim coach times every length on a clipboard, then types each swimmer's times into a spreadsheet at home, averages them and makes a bar chart. With a couple of dozen swimmers, each swimming several distance and stroke combinations, that is well over sixty spreadsheets per training session. He can't take on more swimmers because the admin is drowning him.

The first step is to replace the clipboard with a smart stopwatch that uploads each swimmer's times as a small text file. The file's name carries who swam what; its content carries the times. Both halves matter.

  • Task 1: the filename
  • Get the filename
  • Break it apart on the hyphens
  • Store name, age group, distance and stroke in variables
  • Task 2: the file's data (next chapter)
  • Read the lines; ignore the empty second one
  • Split the first line on commas
  • Convert each "m:ss.hh" string to a number
  • Average, and convert back for display

What a filename tells you

The stopwatch names every file the same way: name, age group, distance and stroke joined by hyphens, then .txt. Tap a piece to see what it means. Pick another file to check that the pattern holds.

A string is an object full of methods

Python strings are objects, and print(dir(fn)) lists roughly fifty methods you didn't have to write. Call one with the dot operator and parentheses: fn.upper(). That differs from the BIFs, which are called like functions, len(fn): methods belong to a type, BIFs are generic. Mix them up (fn.len() or upper(fn)) and Python complains.

Strings are also immutable. Methods never change the original; they return a new string (or, for split, a new list). Numbers, strings, booleans and tuples are immutable; lists, sets and dictionaries are mutable.

Splitting a string into a list

  
split() with no argument breaks on whitespace (spaces, tabs, newlines and friends). Give it a separator and it breaks on that instead. Either way the result is a list of the pieces. Splitting the filename on hyphens nearly works, but the last piece is 'Fly.txt', with the extension still attached.

Read error messages from the bottom up

  
A tempting fix is to chain a second split: fn.split("-").split("."). It fails. The first split returns a list, and lists have no split method, so Python raises an AttributeError. The error report is called a traceback, and the useful part is at the bottom. Step through how to read one.

  

    

    

  






  
6
Chain the right methods in the right order

  
The fix is another string method. removesuffix(".txt") drops the extension while the value is still a string; then split("-") turns it into a list. Order matters: each call works on whatever the previous one returned. Flip the order to see the chain break.

  

    

    

    

  






  
7
Multiple assignment, aka unpacking

  
Four values, four variables, one line. Put several names on the left of = and Python unpacks the list on the right into them, one by one. The counts must match. Here is the finished Task 1: one line that does all the work.

  

    
swimmer, age, distance, stroke = fn.removesuffix(".txt").split("-")
