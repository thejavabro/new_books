Working with HTML: Web Scraping

The Coach wants world-record times on his charts. They live in HTML tables on the web, built for humans. Python can read them too.

Data built for eyes, not code

The Coach wants each chart to show the current world record for that event. The records are published as tables on a web page. HTML is text, so it is not hopeless: but it is written for a browser to render and a person to read. Before scraping anything, look at both views of the same table.

Sample values for illustration. The real page has four big tables: long course and short course pool, men and women, plus relays.

2

A step-by-step plan for scraping

Scraping is a pipeline. Get the raw HTML; parse it into a searchable structure; find the tables you care about; walk their rows and cells and keep the data. The book uses gazpacho from PyPI, which can both fetch a page and parse it. Its parsed document is called soup (yes, gazpacho is a cold soup, and the tradition comes from the older "Beautiful Soup" library).

import gazpacho

URL = "https://en.wikipedia.org/wiki/List_of_world_records_in_swimming"
html = gazpacho.get(URL)          # a (very long) string
len(html)                         # get to know your data before parsing
print(html[:300])                 # peek at the start with a slice
3

Slices: start, stop, step

To peek at a huge string you need part of it. Square brackets accept a slice: seq[start:stop:step]. It works on any sequence: strings, lists, tuples. Each part has a sensible default (start at the beginning, stop at the end, step 1), negative indexes count from the end, and a negative step walks backwards. The gotcha everyone hits: stop is not included.

Find tags, then search inside them

  
Wrap the HTML in a Soup and call find with a tag name, optionally with attributes to match. With mode="all" you always get a list back, which is exactly what a for loop wants. Each result is itself soup, so you can find inside it: tables, then tr rows, then td cells. Try the searches below on a tiny page.

  

    

    

    

  






  
5
Four tables, one nested loop

  
Which tables matter? The page has more tables than the four record tables (navigation boxes, notes), so the code filters on a class attribute and checks the count. Then one loop walks the tables and an inner loop walks each table's rows, pulling the event name and record time from the right cells. Step through it.

  

    
records = []
for table in tables[:4]:                      # LC men, LC women, SC men, SC women
    for row in table.find("tr", mode="all")[1:]:   # [1:] skips the header row
        cells = row.find("td", mode="all")
        event, time = row.find("th").text, cells[0].text
        records.append((event, time))
