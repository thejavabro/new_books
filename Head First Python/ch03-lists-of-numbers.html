Open, process, close: let with handle it

The built-in open reads (or writes) files. The pattern is always the same: open, do something, close. Forgetting to close wastes resources, and an OS only allows so many open files. The with statement sets up a context: it opens the file, runs your indented block, and closes the file when the block ends, even if the block crashes. The as keyword names the opened file object.

FOLDER = "swimdata/"                    # UPPERCASE = treat as a constant
FN = "Darius-13-100m-Fly.txt"

with open(FOLDER + FN) as file:
    lines = file.readlines()            # a list, one string per line

times = lines[0].strip().split(",")
file closed
No constants, just a conventionPython has no true constants. An ALL-CAPS name is a promise to other programmers that you won't change it. Variables like file and lines simply come into being when something is assigned to them; no declarations needed.

Your new best friend: the colon

A colon at the end of a line says "an indented block starts here". The block (the docs call it a suite) ends when the indentation does. Forget the colon and Python won't run the code at all. Tap any line to see which block it belongs to.

From "m:ss.hh" to a number

"1:28.47" looks like a time but it is text, so you can't average it. The strategy: split off the minutes at the colon, split seconds from hundredths at the dot, convert each piece with int(), then add everything up as hundredths of a second. Parentheses make the order of operations obvious even though Python's precedence rules would get it right anyway.

for loops beat while loops (most of the time)

  
Converting one time means you can convert them all with a loop. Python's for walks through any sequence, item by item, and stops when it runs out; no counter, no length check. A while loop can do the same job but needs an index, a condition and an increment, and each is a chance to get it wrong. Step both side by side.

Growing a list as you go

  
Keep the converted numbers for later. Start with an empty list, converts = [], and append each value inside the loop. Lists grow on demand: no size to declare, no type to declare. A list holds references to objects, so it can mix types freely. Then let the standard library do the arithmetic: statistics.mean(converts).

  

    
converts = []
for t in times:
    converts.append(to_hundredths(t))

import statistics
average = statistics.mean(converts)

Turning the average back into a swim time

  
The mean comes back as something like 8925.83 hundredths. The Coach wants "1:29.26". Reverse the conversion: round to a whole number of hundredths, peel off the hundredths with % 100, turn the rest into seconds, then split minutes from seconds with // 60 and % 60. Drag the slider to try other averages.

  

    
    

    
hundredths = round(average)               # 8926
secs, hundredths = hundredths // 100, hundredths % 100
mins, secs = secs // 60, secs % 60
swim_time = str(mins) + ":" + str(secs) + "." + str(hundredths)

    
Spot the wrinkle at 1:05.07 or 1:29.04: plain str() drops the leading zeros. Chapter 5 fixes it with f-string format specifiers.
