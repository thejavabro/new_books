Dynamic Programming

When greedy choices go wrong and brute force is too slow, dynamic programming splits the problem into smaller ones, solves each exactly once, and builds the answer from a table.

When greedy fails: Algorithm Land's tokens

Algorithm Land pays change in its own tokens: 1, 7 and 10. A cashier owes you 14 and does what she learned with US coins: biggest token that fits. Ten, then four 1s: five tokens. But 7 + 7 is two. Greed grabbed the 10 and could never take it back. To be sure of the best answer we have to consider every option. Done naively, that is brute force and exponential. Done cleverly, it is dynamic programming.

Meet dynamic programming

Solve each subproblem once, store the answer, reuse it. That's it. A problem is a good fit when it has two properties:

There are two ways to organize the work. Top-down is chapter 4's memoization: recurse from the big problem, cache answers as they come back. Bottom-up (tabulation) skips recursion: fill a table from the smallest subproblems upward, so every cell only looks at cells already filled. No deep call stack to overflow.

dp[i] = dp[i−1] + dp[i−2]

O(n) time and O(n) space. Since each cell needs only the previous two, you can even keep just two variables and drop space to O(1).

4

Coin change, one cell at a time

Make an array with one cell per amount from 0 to 14. Each cell answers "fewest tokens to make this amount". dp[0] = 0. For each later amount, try every token that fits: 1 + dp[amount − token], and keep the smallest. Step through it; the blue cells are the ones the current cell reads.

def min_tokens(amount, tokens):
    dp = [0] + [float("inf")] * amount
    for a in range(1, amount + 1):
        for t in tokens:
            if t <= a:
                dp[a] = min(dp[a], 1 + dp[a - t])
    return dp[amount]

6

Back to the dragon's lair: the knapsack table

Greedy left with $2,600; brute force found $2,700 by checking all 32 subsets. Dynamic programming finds $2,700 without that blow-up. The table has a row per item (plus a "no items" row) and a column per capacity, 0 to 50 in steps of 5. Cell [i][w] holds the best value using the first i items in a bag of capacity w. For each cell there are two choices: skip the item (copy the cell above) or take it (its value plus the best for the remaining capacity in the row above). Keep the bigger.

7

How big is the table?

(n + 1) × (W + 1) cells, each an O(1) comparison: O(n × W) time and space, where W is the number of capacity steps. For 5 items brute force's 32 subsets actually beat 66 cells. Grow n and the table wins enormously. Watch W too: a capacity measured in single grams can make the table huge.

Space trickEach row reads only the row above, so you can keep two rows and use O(W) space. The price: you can no longer backtrack to see which items were taken, only the best value.
