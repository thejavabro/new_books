#1 Tries: autocomplete's secret

Type "hel" and your phone offers "hello". It isn't scanning the dictionary. A trie (prefix tree) stores one character per node, so words that start alike share a path: "cat" and "car" share c → a. Looking up a word costs O(length of the word), not O(number of words); finding everything with a prefix means walking to the prefix's node and collecting what lies below. The trade-off is memory: many child pointers per node, mostly empty, which compressed tries and radix trees tame.

#2 The LRU cache: two structures, one job

A full cache must evict something; least recently used says evict whatever was touched longest ago. You need O(1) lookup and O(1) eviction, and neither structure from chapters 3 and 6 can do both alone. Combine them: a hash table maps keys to nodes of a doubly linked list ordered by recency. A hit moves its node to the front; eviction removes the tail. Everything stays O(1). Operating systems, CPUs, databases, browsers and CDNs all use variants.

#3 Self-balancing trees

A binary search tree keeps smaller keys left and larger keys right, giving O(log n) lookups, but only while it stays balanced. Insert keys in sorted order and it degenerates into a linked list: O(n). Self-balancing trees fix this with rotations, O(1) pointer rewirings that change shape without breaking order. AVL trees rebalance strictly; red-black trees (inside Java's TreeMap and C++'s std::map) allow a little slack for fewer rotations. Insert 1, 2, 3... in order and compare.

#4 Parallel and distributed algorithms

The book assumed one processor doing one thing at a time. Real machines have many cores, and services run on fleets of servers. Parallel algorithms share memory, and must survive race conditions (two cores updating one counter can lose an update). Distributed algorithms run on separate machines that exchange messages, which can be lost or delayed; frameworks like MapReduce split the work and combine the results. And there's a ceiling: Amdahl's law says the sequential part limits your speedup, however many processors you add.

5

#5 String algorithms

Text is a line of characters, and string tasks (searching, comparing, finding repeats, hashing) keep re-checking the same runs. The naive search lines the word up with the text, compares character by character, and on a mismatch shifts by one and starts over. Smarter algorithms such as Knuth-Morris-Pratt and Boyer-Moore remember the partial match and skip ahead, never re-reading text they've matched.

6

#6 Approximation algorithms

For NP-hard problems, ask "can we get a good answer fast, and know how good?" An approximation algorithm runs in polynomial time and carries a guarantee, which separates it from a guess. Algorithm Land wants sensors on attractions so every path has a sensor at one end: a minimum vertex cover, which is NP-hard. The simple fix: pick any uncovered edge, put sensors at both ends, repeat. Any optimal cover needs at least one end of each edge you picked, so you are never worse than 2× optimal.

7

#7 Machine learning is algorithms you know

Under the hood, neural networks are weighted graphs, decision trees are trees and tensors are multidimensional arrays. Most training is optimization: minimize a function that measures error. Gradient descent is greedy: feel which way is downhill, take a step, repeat. Backpropagation walks the network graph backward reusing partial results, which is dynamic programming for derivatives. Decision trees split the data, then recurse: divide and conquer. Try step sizes.

8

#8 External memory algorithms

Every algorithm so far assumed the data fits in RAM. When it lives on disk, the cost that matters is how many blocks you read, since disk is thousands of times slower than memory. B-trees give each node hundreds of children, sized to one disk block, so a lookup in a billion keys touches only a handful of nodes. External sorting sorts chunks that fit in memory, writes them out, then merges them sequentially, merge sort adapted to disks.

9

#9 Randomized algorithms

Adding randomness can make algorithms faster or simpler. Random pivots make quicksort's O(n²) worst case astronomically unlikely, and no adversary can craft a bad input. Monte Carlo methods estimate answers by random sampling; Bloom filters answer "definitely not in the set" or "probably in it" using a sliver of the memory. Estimate π by throwing darts at a square with a circle inside.

10

#10 Bit manipulation

One integer can hold dozens of yes/no facts. Each bit is a flag; masks test, set and clear them in O(1): flags & (1 << k) tests bit k, | sets it, & ~ clears it. It's a tiny data structure: compact sets with constant-time operations.
