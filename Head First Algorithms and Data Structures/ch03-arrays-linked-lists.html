Arrays and Linked Lists

Data structures are the shape of data; algorithms are what you do with it. The same operation can be instant on one shape and slow on another, so picking the structure is half the algorithm.

2

Static arrays: a block of seats in a row

A static array is a fixed-size block of side-by-side memory slots, like a row of theater seats booked together. Because the slots are contiguous and equally sized, the computer finds slot i with one calculation: address = start + i × slot size. So reading or writing by index is O(1). Inserting in the middle is different: to keep things contiguous, every later item must shift.

Dynamic arrays: room to grow, amortized

A dynamic array (Python's list, Java's ArrayList, C++'s vector, JavaScript's Array) keeps spare slots at the end. Appending usually drops the item into a spare slot: O(1). When the spare runs out, it allocates a bigger block (commonly double), copies everything and continues. That one append costs O(n), but doubling makes those copies so rare that the average cost per append stays constant. We call that amortized O(1).

Singly linked lists: a chain of nodes

A linked list gives up contiguity. Each node holds a value and a pointer to the next node; the list keeps only a pointer to the head. Nodes can live anywhere in memory. There is no index arithmetic, so reaching item k means walking k links: O(n). But inserting or deleting at the head, or right after a node you already hold, is just a pointer change: O(1).

Where linked lists shineThe book's road-trip example: once you are at a stop in the route, adding several detours right there is O(1) each, with no shifting and no copying. Finding the spot is what costs O(n).
5

Doubly linked lists: pointers both ways

Give every node a prev pointer as well as next, and keep a tail pointer as well as the head. Now you can walk in both directions, and add or remove at either end in O(1). The price is an extra pointer per node and more links to keep consistent. A playlist with back and forward buttons, or undo and redo, is a natural fit.

Back at Micro-Storage: the O(n) tax

Binary search made lookups O(log n), but only because the box list stays sorted. Now boxes arrive and leave all day, and every insert into a sorted array shifts items: O(n) each time. An unsorted array or linked list makes inserts cheap but lookups O(n) again. Slide the daily churn to see the trade-off for a million boxes.

Static arrayFixed, contiguous. O(1) index; O(n) middle edits and resizes.
Dynamic arraySpare capacity, doubles when full. Amortized O(1) append.
Singly linked listNodes plus next pointers. O(1) at the head; O(n) to reach index k.
Doubly linked listprev and next, head and tail. O(1) at both ends; walk both ways.
