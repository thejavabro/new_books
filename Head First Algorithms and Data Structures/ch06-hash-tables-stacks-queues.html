Hash Tables, Stacks and Queues

Arrays and linked lists can only take you so far. Hash tables find things by name in about one step, while stacks and queues give you discipline about what comes out next.

Can Micro-Storage be saved? Meet the hash table

Keeping boxes sorted made lookups fast and updates painful. A rival, Hash Storage, offers "instant finds at any scale". Their trick: skip searching altogether. Picture a wall of cubbies numbered 0 to N−1 and a librarian who, given any key, always points to exactly one cubby. The cubbies are an array; the librarian is a hash function. To find a slot: index = hash(key) mod N. Array access by index is O(1), so store and lookup are O(1) too.

Collisions are inevitable, so plan for them

A hash function squeezes a huge space of possible keys into N slots, so sooner or later two different keys land on the same index: a collision. It is the birthday problem: with 365 days, a room of just 23 people has better-than-even odds that two share a birthday. The fix used above is chaining: each bucket holds a short list, and a lookup scans only that list. (Other tables use probing: try the next free slot.)

Collision vs. duplicate keyA collision is two different keys in the same bucket; both are kept. Putting the same key twice overwrites the old value. That is by design: a hash table maps each key to exactly one value.
3

What makes a hash function good

A good hash is consistent (same key, same number, every time), fast, and well mixed (similar keys land far apart). A lazy hash that just uses the first letter clumps keys into a few buckets and turns lookups back into linear scans. Compare how 60 product names spread over 16 buckets.

Better keys: combine fields with a tuple

Keys must be unique. Use book titles alone as keys in a library and two different books called "Night" overwrite each other. Combining title and author into an immutable tuple, ("Night", "Wiesel"), gives each book its own identity. Tuples work as keys because they cannot change after they are hashed.

Stacks: last in, first out

  
Hash tables find anything fast. Stacks do the opposite: they deliberately let you touch only the top. push adds on top, pop removes the top, peek reads it. Because nothing is searched or shifted, every operation is O(1). A Python list works as a stack (append and pop at the end); Java offers ArrayDeque. You already met one: the call stack.

Queues: first in, first out at the taxi stand

  
A queue serves in arrival order: enqueue at the back, dequeue from the front. The chapter's taxi stand after a movie lets out is the perfect job for one. Built well, every operation is O(1). Built on a plain Python list, dequeue is pop(0), which shifts every remaining item: O(n). Use collections.deque, which behaves like a doubly linked list.

Stack plus queue: a palindrome checker

  
Push every letter onto a stack and enqueue it on a queue. Then pop and dequeue together: the stack gives letters in reverse, the queue in original order. If every pair matches, the word reads the same both ways.
